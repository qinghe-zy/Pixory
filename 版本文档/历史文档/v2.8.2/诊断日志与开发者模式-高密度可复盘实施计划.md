# 诊断日志与开发者模式：高密度可复盘实施计划

- 计划日期：2026-09-05
- 状态：待实现，已自审
- 本轮范围：日志密度、异常独立产出、白屏复盘、开发者模式、设置入口、聊天列表裁剪
- 本轮不做：不改代码、不发布 OTA、不修改聊天/记忆/备份/导入导出公开格式

## 1. 目标

将当前“数量少但分散、关键链路缺失”的诊断系统改为“少量高密度操作摘要 + 高频窗口聚合 + 独立异常事件”。收到一份日志后，应能判断问题属于数据库、摘要/记忆、Prompt、Provider、附件、流式解析、线程状态、FlatList/React 渲染、页面刷新、内存或系统异常，并明确区分未发生、未采集、被过滤、被保留策略删除和写入失败。

验收要求：

- 关键操作有完整父子 trace 和 monotonic duration；
- 不逐 token 写 SQLite；
- 高频 token、滚动、布局和帧数据按 250/500ms 窗口聚合；
- 关键异常不受普通日志数量上限影响；
- 日志数量明显下降，但每条操作摘要包含完整阶段、资源、结果和错误信息；
- 白屏、消息消失、摘要上滑异常、思考计时不结束和空响应可以独立复盘；
- 导出完整性可用数字守恒验证；
- 日志系统失败不得阻塞聊天主流程。

## 2. 当前样本结论

样本：`docs/日志/pixory-diagnostics-1788621318090/`

- `eventCount` 为 200，说明存在导出/保留/旧 bundle 层的 200 条限制或截断；不能仅凭 `droppedEventCount=0` 认定没有缺失。
- 有 36 次生成开始、30 次完成、1 次空响应；部分请求缺少完整终点。
- 缓存按 prompt token 加权约 68%，不能声称达到 90%；`stablePrefixEstimatedTokens` 多次为 0，客户端缓存指标不可信。
- 主要只有 generation/prompt/provider 事件，数据库、页面、刷新、摘要、列表、附件事件缺失。
- 文件名出现 `.jsonl.json`，说明系统目录复制时扩展名或 MIME 处理不稳定。
- `architecture.json` 中 app、model、provider、prompt、history 字段为 unknown/null，无法还原运行环境。
- 未发现明确的 warmth、reassurance、energy、assertiveness、intimacy、responseLength、primaryIntent 或安全围栏字段；但仍存在每轮自动追加的“下一条回复要求”和约束包装，需要记录其来源并评估。

## 3. 数据模型

### 3.1 操作摘要 `diagnostic_operations`

一条用户操作或系统操作一条记录。覆盖进入页面、历史加载、发送、摘要、记忆、刷新、分页、切线程、切分支、恢复、导出和附件发送。

字段：`operationId`、`traceId`、`parentOperationId`、`operationType`、space、thread/generation hash、UTC 起止、monotonic duration、终态、阶段摘要、资源摘要、incident 引用和覆盖标记。

阶段摘要必须包含开始/结束/耗时、结果数量和状态：数据库打开、消息查询、附件持久化、上下文、memory drain、companion observer、RAG、Prompt、序列化、fetch、上传、Provider 首字节、首 reasoning、首 answer、首次 UI 可见、流式完成、最终落盘、页面稳定。

### 3.2 高频窗口 `diagnostic_windows`

固定窗口聚合流式、滚动、布局和帧数据。字段包括：operation/generation/screen/thread hash、窗口起止、delta 数、字符增量、render/layout 次数、可见/挂载项、内容/视口高度、JS/UI 帧 P50/P95、掉帧、内存、滚动偏移/速度和 anomaly flags。

正常窗口可以按采样率保留；异常前 5 秒和异常后 10 秒窗口强制保留。不保存 token 正文，不逐 token 写数据库。

### 3.3 独立异常 `diagnostic_incidents`

异常不与普通事件共用 200 条上限。每个 fingerprint 聚合一次，保存：incidentId、trace、operation、generation、类型、严重级别、首次/最近时间、状态、检测器版本、阶段、症状、恢复动作、关联事件和结构化上下文。

fingerprint：`incidentType + stage + stableErrorCode + component`。保存 count、affectedOperations、recoveredCount 和 unresolvedCount。

## 4. 日志数量和完整性

默认每空间保留：

- 操作摘要：20,000 条或 14 天；
- 高频窗口：20,000 条或 7 天；
- 独立异常：5,000 条或 30 天；
- 关键生命周期、生成终态、数据库失败和 Provider 错误优先保留；
- 正常 scroll/layout/token 只保存聚合窗口。

每次采集、flush、保留删除和导出都累计：

```text
eventsRecorded
eventsQueued
eventsPersisted
flushFailedCount
retryCount
droppedByMemoryCount
droppedByPrivacyCount
prunedByRetentionCount
excludedByFilterCount
excludedByExportLimitCount
bufferedAtExport
unknownGapCount
clockJumpCount
```

导出必须生成 `integrity.json`。任意阶段无法测量必须使用 `unattributed`，不得用 0 假装没有耗时。诊断写入失败时先内存保留关键摘要和 incident，退避重试一次，再写轻量 fallback；不阻塞聊天。

## 5. 全链路和异常检测

必须覆盖 App 启动/恢复、数据库打开/迁移、主页首屏、资料库素材、聊天历史/分页/刷新、摘要和记忆、Prompt/RAG、Provider、附件、流式、页面稳定、线程切换、分支、重生成、continue、后台恢复和诊断导出。

独立检测：

- generation empty、无首 token、reasoning 无 answer、无 terminal、terminal 后仍 generating、思考计时继续增长、重复 start/terminal、Provider 完成但未落盘、落盘完成但 UI 未更新；
- 有数据但可见/挂载项突然为 0；contentHeight 大于 0 但 UI 空白持续 250ms；onContentSizeChange 后数据/渲染异常下降；线程/generation 不匹配；裁剪开关后空白；摘要/记忆写入附近列表重置；
- SQLite busy、事务嵌套、锁等待、迁移、查询超时、回滚；Provider HTTP/SSE/重试；文件、SAF、图片格式、大小和编码；diagnostic flush、隐私扫描、导出完整性。

白屏 incident 必须包含：数据长度、可见/挂载项、内容/视口高度、线程/generation、分页/刷新/摘要状态、裁剪参数、最近两秒布局和数据变化、是否恢复、恢复耗时。

## 7. 开发者模式与设置入口

### 7.1 状态和门槛

新增本地 `developerModeEnabled`，不进入普通备份、聊天导出或跨空间同步。生产构建中点击入口无效；开发构建仍可由构建能力开关限制。

### 7.2 进入

“关于”页的大号 Pixory 文字和版本号都支持连续点击 7 次，共用一个计数器：10 秒内完成，离开页面或超时重置。成功后提示“已开启开发者模式”。

### 7.3 普通模式与开发者模式的设置按钮规则（硬约束）

这里的“设置按钮”不能删除，两个模式都必须保留：

- 普通模式：保留设置按钮，但按钮暂时不可点击；即使未来普通模式设置按钮恢复可点击，也不能显示“性能与诊断”入口；
- 开发者模式：设置按钮可点击，并在设置内容中显示“性能与诊断”入口；
- “性能与诊断”不是普通模式的可用功能，不能因为不可用而删除整个设置区域；
- 其它普通设置入口、聊天、记忆、备份和导入导出不受影响。

推荐 UI：普通模式按钮保持正常布局但置灰，附“开发者模式专用”说明；开发者模式按钮正常可点，设置页内显示诊断入口。

### 7.4 退出

位置固定为：`设置 → 开发者模式 → 关闭开发者模式`。二次确认说明“只隐藏开发者专用内容，不删除聊天、记忆、备份或诊断日志”。关闭后只将本地状态置 false，保留全部日志和业务数据；下次重新点击 7 次进入。

## 8. Android 列表裁剪策略

永久 `removeClippedSubviews={false}` 可以降低 inverted FlatList 在摘要/记忆布局变化时白屏的风险，但长对话会增加原生视图、内存、GC 和渲染压力，不能作为永久最终方案。

最终采用动态策略：

- 稳定且无任务时使用 true；
- 生成、摘要/记忆写入、历史分页、刷新、切线程/分支、最近发生大幅布局变化或最近出现白屏时使用 false；
- 无生成/分页/刷新/摘要任务，完成 content size/layout 提交且连续约 1 秒无异常后再恢复 true；
- 恢复后检测到可见项为 0 或高度异常，立即回退 false 并产生 incident；
- 低内存时降低 windowSize 和批量渲染，记录内存、JS/UI 帧、mounted item 和裁剪切换；
- 只对活动聊天列表采用保守策略，图片使用缩略图，Markdown/HTML 缓存测量结果。

## 9. 实现批次

A. 数据表、迁移、事件完整性和失败 fallback。

B. operation/window/incident 聚合器、环形缓冲和关键事件优先级。

C. 接入聊天、摘要、记忆、RAG、Prompt、Provider、附件、数据库、主页、资料库、刷新和恢复。

D. 实现生成终态、白屏、空列表、消息消失、计时不结束、线程错配和资源异常检测器。

E. 重构导出清单、完整性报告、隐私扫描、文件名/MIME 校验和离线分析入口。

F. 实现开发者模式双入口、普通/开发者设置按钮差异、开发者设置页和关闭选项。

G. 将 Android 永久 false 改为动态裁剪、自动回退和内存/帧率监控。

每批次先定向测试，再 review；所有批次完成并真机验证前不发布 OTA。

### 自审结论

本计划不删除普通设置按钮，不把普通模式和开发者模式混为一个可见性条件；“性能与诊断”只属于开发者模式设置内容。日志系统的成功标准不是日志越多越好，而是数量减少、每条操作记录密度提高、关键异常独立产出、导出完整性可验证。实现时必须先确认旧 bundle 的 200 条限制来源，再逐批落地和真机验证。
