# Pixory 版本文档工作流 Spec

## 1. 当前区间

- 基线版本：2.8.1
- 目标版本：2.8.2
- 当前更新说明：根目录 `LOCAL_UPDATES_LOG.md`
- 当前过程文档：`版本文档/当前版本文档/`
- 最新功能矩阵：`docs/feature-matrix.md`，只保留最新状态并进入 Git

## 2. 目录职责

- `当前版本文档`：直接保存当前目标版本的 Spec、Plan、Review、规划、算法、调研和版本过程索引，不再建立类型子目录。
- `历史文档/vX.Y.Z`：每个已发布版本只有一个直接子目录，目录内直接保存该版本全部过程文档和索引，不再嵌套。
- `版本更新说明`：直接保存 `Pixory-vX.Y.Z-版本更新说明.md`，不为版本另建子目录。
- `待办`：只在用户明确要求“写进清单”或“写进待办”时增加文件；不会在打包时自动归档或清空。
- `docs/feature-matrix.md`：唯一最新功能矩阵，不复制版本快照。

## 3. 旧文档归属

需要迁出的版本过程资料包括：

- `docs/superpowers/specs/`
- `docs/superpowers/plans/`
- `docs/reviews/`
- `docs/ai-chat-research/`
- `docs/ai-chat-streaming-research/`
- 根目录 `task_plan.md`
- 明确属于阶段审计、实现规划或算法研究的其他 Markdown/Draw.io 文档

归属版本按文档最后一次 Git 修改提交确定：选择该提交之后最早发布的版本标签。晚于 v2.8.1 发布的资料归入当前目标版本 2.8.2。每个版本目录必须生成 `版本文档索引.md`，记录归档文件名、原始路径、类型、最后提交、日期和归属依据。

README、用户手册、官网文件、最新功能矩阵和长期产品说明不属于版本过程资料，继续留在 Git。

## 4. 打包归档

Android 打包前必须输出：

- 当前基线和目标版本
- 根更新说明路径
- 当前版本文档文件清单
- 即将写入的历史版本目录
- 即将生成的版本更新说明文件
- 待办目录保持不动的提示

只有 APK 成功复制到 `output/release` 后才能归档。归档顺序：

1. 在更新说明和过程索引末尾追加最终版本、提交、标签、时间、APK 路径和验证摘要。
2. 将当前版本文档直接移动到 `历史文档/vX.Y.Z/`。
3. 将根更新说明移动为 `版本更新说明/Pixory-vX.Y.Z-版本更新说明.md`。
4. 建立下一补丁版本区间的新 `LOCAL_UPDATES_LOG.md`、区间配置和过程索引。

归档不得覆盖或删除历史文件。目标已经归档且当前区间已经前进时，重复打包同一版本只输出“已归档”并跳过文档移动。

## 5. Git 边界

- `LOCAL_UPDATES_LOG.md` 与整个 `版本文档/` 不进入 Git。
- 归档脚本、打包脚本、AGENTS 规则、`.gitignore` 和最新功能矩阵进入 Git。
- 旧版本过程文档从 Git 工作树迁出后，以删除记录提交；内容保存在本地版本归档中，Git 历史仍可追溯原文件。

## 6. 验收

- 每个历史版本只有一层版本目录，内部没有子目录。
- 版本更新说明文件夹只有说明文件，不含版本子目录。
- 当前版本文档只包含 2.8.2 相关资料。
- 待办目录包含用户明确要求保存的后续性能清单。
- 打包失败不改变文档；成功后归档并初始化下一版本。
- `pnpm typecheck`、相关策略/脚本测试和 `git diff --check` 通过。
