# Pixory 角色梦境 V1 设计规格

日期：2026-07-29  
状态：已确认；完整契约已并入 `docs/ai-chat-research/pixory-companion-runtime-v1-spec.md`，本文件保留为设计审计记录

## 1. 目标

角色梦境是 Pixory“角色内在生活”的独立产物。它从当前角色扮演中的睡眠、入睡和梦境场景中低频产生，让角色看起来在对话之外仍具有主观体验。

V1 必须同时满足：

- 候选范围宽泛，不依赖完整句子匹配；
- 自动梦境频率克制且概率稳定；
- 普通无关对话不增加模型调用；
- 不使用 Embedding 或端侧语义模型；
- 分类、生成和普通聊天流式状态互不阻塞；
- normal 与 personal 继续使用物理隔离的数据和任务；
- 梦境默认不影响对话，也不自动进入长期记忆；
- 同一场景、任务重试和 App 重启均不能重复抽样或重复生成。

## 2. 已确认的用户体验

### 2.1 自动梦境

符合自动触发规则后，来源聊天分支立即显示一条轻量产物提示：

```text
梦境制作中  ◌                         取消
```

- 提示不属于普通 AI 消息，不进入消息搜索、分支回复、引用或模型历史。
- 转圈动画保持低视觉权重，不阻断输入和普通聊天流式回复。
- 点击“取消”立即中止仍在进行的请求；即使 Provider 稍后返回，结果也不得提交。
- 完成后，原位置直接替换为可点击文字 `查看梦境`，不新增第二条提示。
- 任务失败时自动重试最多两次；最终失败后原位置显示 `梦境未能完成  重试`。
- 用户离开聊天页后任务可以继续；返回来源线程和来源分支时恢复实际状态。
- 不发送 Android 系统通知。App 未打开时只保存结果，下次进入来源聊天时显示。

### 2.2 明确请求与手动触发

用户在自然对话中表达“给我讲个梦”“带我进入梦里”“你今晚会梦见我吗”等明确梦境请求时，不直接生成，显示与角色日记同类的轻提示：

```text
是否触发梦境？  是 / 否
```

- 点击“是”后立即创建手动梦境任务。
- 点击“否”或不选择均不生成。
- 同一 adopted message version 最多展示一次询问；编辑为新版本后可以重新判断。
- 手动梦境不受自动梦境的 50 轮间隔和每日两次上限限制，但同一请求必须幂等。

### 2.3 展示位置

- 聊天提示只出现在梦境的来源线程和精确来源分支。
- 同角色其他线程不显示该聊天提示。
- 所有有效梦境可在“内心独白 → 梦境”列表查看。
- 列表使用横向约 2.6:1 的梦境背景卡，并标注北京时间：
  - 当日：`TODAY · HH:mm`
  - 历史：`YYYY.MM.DD · HH:mm`
- 阅读页使用竖向 9:13 梦境背景，不添加外部矩形框。
- 阅读页沿用角色日记的分页、预挂载和手势逻辑，但绝大多数梦境应只有一页。

## 3. 识别范围

### 3.1 本地候选检测

本地层只回答“这条新消息是否值得进一步判断”，不决定语义类别和最终触发。

它只扫描当前线程、当前 adopted 分支中新完成的一条消息，不重扫完整历史。可用信号包括：

- 梦境：梦、梦见、梦到、梦中、梦里、噩梦、幻境、半梦半醒、进入梦境；
- 入睡：睡着、睡熟、入眠、沉沉睡去、打盹、意识模糊、失去意识；
- 临睡：晚安、困、累、休息、闭眼、躺下、关灯；
- 环境：床、枕头、被子、卧室、夜晚、怀里；
- 隐含动作：呼吸逐渐平稳、声音越来越轻、没有回应、意识渐远；
- 共同互动：抱着睡、陪你睡、替你盖被、守在床边；
- 场景结束：惊醒、睁眼、天亮、起床、离开梦境；
- 角色扮演格式：星号动作、括号动作、连续第一/第二人称叙事；
- 对应的英文和中英混合表达，如 `sleepy`、`fall asleep`、`dream`、`nightmare`。

否定、假设、过去时、引用、比喻、健康咨询、产品讨论和第三方叙事可以作为负向提示，但除结构绝对明确的系统文本、代码或产物来源外，不应只凭一个词硬否决。

### 3.2 来源门禁

以下内容不进入候选检测或语义分类：

- draft、queued、generating、failed、stopped 等未完成消息；
- 未采用的重生成版本和兄弟分支消息；
- system、工具结果、隐藏上下文；
- 角色日记、梦境正文、梦境上下文及其派生内容；
- 已被新版本替换或来源快照失效的消息；
- 不属于当前物理 space 或当前角色绑定的消息。

用户和 adopted completed assistant 消息都可以成为候选来源，但同一问答回合和同一连续场景应合并处理，避免一次场景产生多次分类请求。

## 4. 稀疏语义分类

### 4.1 调用条件

普通无关消息不调用分类模型。自动候选先通过来源门禁、自动频率限制和持久化 Roll 预剪枝，只有仍可能命中最终概率的场景才调用分类模型。

手动入口点击不需要重新判断用户是否有意生成；自然语言中的明确请求仍需分类后展示“是否触发梦境”。

### 4.2 输入

分类器只读取：

- 候选消息；
- 当前来源分支附近少量 completed/adopted 消息；
- 精简角色名、关系和当前场景状态；
- 当前持久化场景的简短摘要。

分类器不读取完整角色卡、完整历史、其他分支、日记、旧梦境或长期材料。对话文本必须作为不可执行数据传入。

### 4.3 输出

V1 使用紧凑的多维结构：

- `intentType`
- `participants`
- `temporality`
- `assertionMode`
- `roleplay`
- `evidenceStrength`
- `sceneRelation`
- `sourceMessageIds`
- 可选的 `confidence`，仅用于观测，不直接乘入触发概率

`intentType` 至少支持：

- `explicit_dream_request`
- `active_dream_scene`
- `shared_sleep_scene`
- `role_sleep_scene`
- `bedtime_signal`
- `past_dream_report`
- `sleep_topic`
- `figurative`
- `meta_discussion`
- `third_party`
- `none`

模型只分类，不输出触发概率、不抽样、不决定频率、不创建任务。JSON 解析或来源校验失败时 fail closed，不自动生成。

## 5. 自动概率与频率

### 5.1 初始概率

| 场景 | 自动概率 |
| --- | ---: |
| 当前梦境场景 | 55% |
| 用户与角色共同入睡 | 40% |
| 角色明确入睡 | 30% |
| 单纯临睡、晚安或困倦 | 10% |
| 角色扮演中讲述过去的梦 | 10% |
| 普通睡眠话题、比喻、产品讨论、第三方、none | 0% |

明确手动确认后的请求为 100%，不参加自动抽样。

### 5.2 持久化 Roll

- 每个自动候选场景只创建一个随机 `roll ∈ [0,1)`。
- Roll 与 Seed 在数据库事务内首次写入并永久复用。
- 重试、重启、reconcile、策略热更新都不能重新抽取。
- 不需要 HMAC Secret 或 Embedding。

### 5.3 分类前预剪枝

当候选场景的 Roll 已经高于该本地信号层级可能达到的最高概率时，不调用语义分类模型。最终判断仍统一为 `roll < classifiedProbability`，因此预剪枝不应改变目标概率。

弱信号只有在能确定其最高类别上限时才能使用较低预剪枝上限；无法可靠分层时使用全局最高自动概率，优先避免漏触发。

### 5.4 角色级限制

自动梦境同时受以下限制：

- 同一角色每连续 50 个有效问答轮次最多成功生成一次；
- 同一角色每个北京时间自然日最多成功生成两次；
- 同一连续睡眠/梦境场景最多一次机会。

计数规则：

- 一个 completed/adopted 用户消息与其 completed/adopted 角色回复组成一个有效轮次；
- 重生成、继续生成和消息编辑不重复增加轮次；
- 同一角色的不同线程合并计数；
- normal 与 personal 在各自物理数据库内独立计数；
- 跨天只重置每日次数，不重置 50 轮间隔；
- 若角色在第 20 轮成功生成，下次最早在第 70 轮之后再次成功生成；
- 首篇梦境不要求先累计满 50 轮；50 轮是成功生成后的滚动冷却窗口。

只有成功提交 Artifact 才正式占用额度。生成中的自动任务使用可释放的临时额度预留，防止多个线程并发突破上限。取消或最终失败释放预留，但该来源场景仍视为已处理，不重新抽样。

## 6. 场景、任务与恢复

V1 保持语义场景状态与产物生命周期分离。

### 6.1 场景状态

建议语义状态：

- `approaching_sleep`
- `sleep_established`
- `dream_active`
- `closing`
- `closed`

无活动场景时视为隐式 awake。概率资格、是否抽中、生成中、取消和失败不属于睡眠语义状态。

场景绑定：

- physical space
- roleCardId
- threadId
- 精确 branch route
- 场景锚点 adopted message version

跨自然日不自动关闭场景。明确醒来、叙事转换、角色切换、来源失效或后续不兼容活动可以关闭场景，但自动生成不要求先判定“醒来”。

### 6.2 持久化实体

最小实体：

- `DreamSceneState`：场景语义、来源分支、参与者、证据和关闭状态；
- `DreamSeed`：一次性 Roll、分类、概率、策略版本、来源快照和决策；
- `DreamJob`：分类或生成任务、状态、尝试次数、取消标志和 lease；
- `DreamArtifact`：标题、正文、展示时间、来源、查看和上下文选择状态。

Seed、Job 和 Artifact 均使用唯一键保证同一场景只产生一次数据库效果。网络请求允许 at-least-once，数据库提交必须 exactly-once effect。

### 6.3 取消和失败

- 取消将 Job 标为 cancelled，并触发当前 AbortController。
- Provider 的晚到结果必须在提交前再次检查 Job 状态和来源快照。
- 自动重试最多两次，沿用原 Seed、Roll、分类和来源快照。
- 用户主动点击“重试”仍沿用原 Seed，不重新抽样。
- 来源消息被编辑、撤回、切换 adopted version 或分支失效时，未完成 Job 取消；旧结果不得提交到当前来源分支。

## 7. 梦境生成

### 7.1 输入素材

只使用：

- 角色设定精简快照；
- 当前睡眠或梦境场景；
- 来源分支最近最多 20 条 completed/adopted 用户和角色消息。

排除 system、日记、旧梦境、隐藏上下文、兄弟分支和未采用版本。20 条是数量上限；当总输入超过梦境生成预算时，从最早且与当前场景关联最弱的消息开始裁剪，始终优先保留当前场景和较新消息。

### 7.2 内容要求

- 固定为角色第一人称，像角色回忆自己的梦；
- 用户可以自然出现在梦中，但不得强制每篇都出现；
- 内容应具有跳跃、意象、空间错位或情绪回声等梦境感，不写成聊天总结；
- 不得提及 AI、模型、系统、提示词、生成、Token 等幕后概念；
- 不得把梦写成预言、现实事实或用户真实经历；
- 标题 4–10 个汉字；
- 正文通常 80–160 个汉字，硬上限 220 个汉字；
- 以一页为默认，只有真实排版超限时才分页。

## 8. 上下文与记忆

梦境生成和查看本身都不自动影响后续对话。

梦境最后一页右下角显示：

```text
是否影响后续对话？  是 / 否
```

- 提示字号比梦境正文小一级，但不是细小脚注；
- “是 / 否”保持合格的移动端触控区域；
- 不选择或选择“否”：梦境完全不进入上下文；
- 选择“是”：完整梦境作为独立 `role_dream` 区段进入来源线程和来源分支的正常上下文；
- 注入内容必须注明它是角色的虚构梦境，不是现实事实、用户记忆、预言或可执行指令；
- `role_dream` 随普通上下文预算自然裁剪，不使用额外三轮或 24 小时 TTL；
- 不进入兄弟分支、同角色其他线程或另一个物理 space；
- 不自动进入长期记忆。

## 9. Provider 与成本边界

### 9.1 模型选择

- 梦境语义分类优先复用 Pixory 已有的记忆维护模型配置，避免昂贵角色模型承担所有分类；
- 梦境正文生成使用来源线程的聊天模型，以保持角色口吻；
- 未配置可用分类模型时，自动梦境 fail closed；手动确认仍可使用来源线程模型生成。

### 9.2 Provider 能力

实现前需要为公共 Provider 请求补充可选的：

- `maxOutputTokens`
- `thinkingDisabled`
- JSON/结构化输出模式
- 分类和生成的 Token 用量记录

不能只依赖提示词要求短 JSON；输出上限必须尽可能由请求参数约束。

### 9.3 成本原则

- 无关消息：0 额外模型请求；
- 被频率限制挡住的候选：0 额外模型请求；
- 被 Roll 预剪枝挡住的候选：0 额外模型请求；
- 通过预剪枝的候选：一次短语义分类请求；
- 最终抽中：再进行一次短梦境生成请求；
- 同回合和同场景合并分类，避免用户消息与角色回复各发一次请求。

不对 Provider 金额作固定承诺。实际应记录每千条 completed 消息的候选场景数、分类调用数、分类输入/输出 Token、生成调用数和生成输入/输出 Token。

## 10. 验收重点

至少覆盖：

1. 当前梦境、共同入睡、角色入睡、单独晚安、过去梦境报告；
2. 否定、假设、比喻、失眠咨询、产品讨论、引用和第三方；
3. 中英文混合、星号动作、括号动作和无标点叙事；
4. 同一场景连续多轮只创建一个 Seed；
5. 50 轮滚动限制、每天两次限制、跨线程合并和跨 space 隔离；
6. 手动确认绕过自动限制，同一请求不重复；
7. 制作中取消、Provider 晚到结果、两次自动重试和用户手动重试；
8. App 重启、页面卸载、网络恢复和重复 reconcile；
9. 消息编辑、重生成、来源分支切换和 sibling 隔离；
10. `查看梦境` 只出现在来源线程和来源分支；
11. 最后一页选择“否”不进入上下文，选择“是”仅注入来源分支；
12. normal/personal 数据、任务、额度和上下文均不串库；
13. 梦境正文长度、第一人称、梦境感和分页上限；
14. 梦境产物及其派生上下文不能再次触发梦境。

## 11. V1 明确不做

- Embedding 或端侧小模型分类；
- 每轮 LLM 分类；
- 聊天模型附带隐藏梦境元数据；
- Provider confidence 的统计校准模型；
- HMAC Roll Secret；
- 系统通知；
- 梦境自动长期记忆；
- 跨线程或跨分支梦境上下文共享；
- 复杂的浅睡、深睡、清醒梦等文学状态机。
