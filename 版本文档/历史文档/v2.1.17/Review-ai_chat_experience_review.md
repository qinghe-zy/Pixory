# Pixory AI 聊天体验产品审阅

> 以产品经理视角，对标 DeepSeek / ChatGPT 移动端体验，审阅全部 18 个核心文件后的发现。
> 不涉及代码修改，仅做需求发现和产品设计建议。

---

## 一、整体印象

Pixory 的 AI 聊天已经具备了完整的聊天骨架：流式输出、多版本回看、消息重写/重新生成、深度记忆、RAG 资料检索、角色卡、会话设置。功能覆盖面已超过大多数内嵌 AI 聊天的独立 App。

**但在"使用感受"层面，和 DeepSeek / ChatGPT 相比，存在明显的体验密度差距。** 下面按用户旅程拆解。

---

## 二、逐环节对标分析

### 2.1 首次打开 AI → 发出第一条消息

| 维度 | ChatGPT / DeepSeek | Pixory 现状 | 差距 |
|------|-------------------|-------------|------|
| 进入速度 | 点击即进入输入框 | 先到 AI 工作台首页，再点"开始聊天"，再进入聊天页 | **多了一跳** |
| 首屏引导 | 空聊天页有 Suggestions / 示例提示词 | 空聊天页无任何引导，只有输入框 | **无启发式引导** |
| 上下文暗示 | 标题栏直接显示模型名、可点选 | 标题栏有模型名但不可点切换 | **缺少快速模型切换** |

> [!IMPORTANT]
> **核心问题：从打开 AI 到发出第一条消息的路径太长且缺乏启发。**
> 
> DeepSeek 和 ChatGPT 都在空聊天页提供「Suggested prompts / 快速建议」让用户不用想就能开始对话。Pixory 的空聊天页是完全空白的，对新用户和不确定"问什么"的用户来说，体验断裂感很强。

#### 建议
1. 在空聊天页显示 3-4 个上下文相关的启发式提示词卡片（如 IP 聊天："介绍这个 IP 的特点"、"列出所有标签"）
2. 允许从 AiHomeScreen 一键进入"带输入框的空聊天页"而不需要额外跳转
3. 考虑在标题栏 modelLabel 区域做可点击的模型快速切换

---

### 2.2 消息输入体验（AiChatComposer）

| 维度 | ChatGPT / DeepSeek | Pixory 现状 | 差距 |
|------|-------------------|-------------|------|
| 输入框自适应 | 平滑高度动画 | 有高度计算但无动画过渡 | **高度跳变生硬** |
| 回车发送 | 支持（可配置） | 不支持 | 无快捷发送方式 |
| 语音输入状态 | 有录音中动画/波形 | 调用 `recognizeSpeech()` 后无任何视觉反馈 | **语音输入是"盲等"** |
| 附件预览 | 图片有缩略图预览 | 只显示文件名芯片，图片无预览 | **图片附件无视觉区分** |
| 停止按钮 | 明确的红色/方块 + 脉冲动画 | 有停止图标但无视觉区分 | 停止状态不够醒目 |

> [!WARNING]
> **语音输入体验是当前最明显的盲区。**
>
> 用户按下语音按钮后，`recognizeSpeech()` 是一个原生 Promise，期间 UI 没有任何变化——没有"正在录音"状态、没有波形、没有计时器。用户完全不知道当前状态是在录、在识别、还是失败了。对比 DeepSeek 的录音动画，差距极大。

#### 建议
1. 语音按钮按下后显示录音状态指示器（波形/脉冲点/计时器），明确告知"正在录音"
2. 输入框高度变化增加 `LayoutAnimation` 或 Animated 过渡
3. 图片类附件在附件区域显示缩略图预览而不是仅文件名
4. 发送后输入框的清空可加轻微的过渡，而不是瞬间清空

### 2.3 流式输出 & 消息显示（AiMessageBubble + AiMessageContent）

| 维度 | ChatGPT / DeepSeek | Pixory 现状 | 差距 |
|------|-------------------|-------------|------|
| 流式打字效果 | 光标闪烁 / 逐字出现有节奏感 | 按 80ms 间隔批量更新文本 | **无光标/打字感** |
| 长消息阅读 | 消息内可折叠/展开 | 全部展开，长消息需要大量滚动 | 无折叠机制 |
| 消息操作 | hover/长按出现操作菜单 | 固定显示在气泡下方 | **操作按钮始终可见，信息密度偏低** |
| 复制反馈 | "已复制"toast 提示 | 只是 `Clipboard.setStringAsync`，无任何 UI 反馈 | **用户不知道是否复制成功** |
| 代码块 | 语法高亮 + 复制按钮 + 行号 | 有复制按钮但无语法高亮、无行号 | **代码阅读体验差** |
| Markdown 链接 | 可点击跳转浏览器 | 仅着色显示，不可点击 | **链接不可交互** |
| 图片在回复中 | 可渲染 AI 回复中的图片 | Markdown 解析器不处理图片语法 | 不支持 |
| 错误消息展示 | 明确的错误卡片 + 重试按钮 | 气泡内显示错误文案，无专门样式 | 错误状态不够醒目 |
| 消息时间戳 | 按天分组 + 相对时间 | 仅在 AI 消息显示 HH:mm，用户消息不显示时间 | **用户消息无时间** |

> [!IMPORTANT]
> **三个最影响阅读体验的问题：**
> 1. 复制操作无反馈 — 用户不知道按了有没有用
> 2. Markdown 链接不可点击 — AI 回复中的 URL 是死的
> 3. 代码块无语法高亮 — 对技术用户来说阅读体验大打折扣

#### 建议
1. 复制后显示短暂 toast 或将图标切换为 ✓ 1-2 秒
2. Markdown 链接用 `Linking.openURL` 实现可点击
3. 消息操作按钮改为默认隐藏，长按/点击消息时浮出操作面板（ChatGPT 模式）
4. 引入轻量代码语法高亮（如 prism-react-renderer 的 RN 适配）
5. 消息按日期分组显示日期分隔线（"今天"、"昨天"、"5月20日"）
6. 用户消息也显示时间戳
7. 错误消息使用专门的错误气泡样式（红色边框 + 重试按钮）

### 2.4 思考过程展示（AiThinkingBlock）

| 维度 | DeepSeek | Pixory 现状 | 差距 |
|------|----------|-------------|------|
| 思考动画 | 脑图/脉冲动画 + 流式展示思考过程 | 静态文字 "正在思考中… X.X秒" | **无动画，观感僵硬** |
| 思考内容 | 流式显示思考文本 | 思考完成后才能展开查看 | **思考过程不可实时观看** |
| 折叠/展开 | 平滑动画 | 无动画，直接显隐 | 过渡生硬 |

> [!TIP]
> DeepSeek 的思考过程展示是其核心差异化体验。建议：
> 1. 思考中显示动态加载指示器（如 3 个脉冲点）
> 2. 允许思考中实时流式展示 `reasoningText`（当前数据流已支持 `reasoning_delta`，但 UI 层在思考完成前不展示）
> 3. 展开/折叠加 `LayoutAnimation`

### 2.5 会话管理 & 历史

| 维度 | ChatGPT / DeepSeek | Pixory 现状 | 差距 |
|------|-------------------|-------------|------|
| 侧边栏 | 从聊天页左滑出会话列表 | 需要返回 → AI 工作台 → 历史会话 | **切换会话需 3 步** |
| 搜索聊天 | 支持按内容搜索历史 | 无搜索功能 | **无法找回旧对话** |
| 会话分组 | 按日期自动分组（今天/昨天/过去7天） | 只有按类型过滤 | **时间线不清晰** |
| 新建聊天 | 聊天页内一键新建 | 必须返回 AI 工作台 | 路径长 |
| 会话置顶 | 支持 | 不支持 | — |

> [!WARNING]
> **会话切换是 AI 聊天的高频操作，目前路径太长。**
>
> 用户每次想切到另一个会话，需要：返回 → AI 工作台 → 最近继续/历史 → 点击。而 ChatGPT 只需左滑出侧边栏。这在多会话使用场景中体验非常差。

#### 建议
1. 聊天页标题区可点击，弹出最近会话快速切换面板
2. 历史页增加搜索框（按标题和 lastMessagePreview 搜索）
3. 历史列表按日期自动分组
4. 聊天页增加"新建聊天"快捷入口（如标题栏右侧 + 号）

### 2.6 会话设置体验（AiSessionConfigScreen）

| 维度 | ChatGPT / DeepSeek | Pixory 现状 | 差距 |
|------|-------------------|-------------|------|
| 模型切换 | 聊天页内直接切换 | 必须进会话设置页 | **太重** |
| 设置保存 | 实时保存 | 手动点"保存" | **容易忘记保存** |
| 设置预览 | 选项有详细说明 | 部分选项说明不够（如"资料范围"三种模式无解释） | 可理解性不足 |

> [!TIP]
> 建议：
> 1. 轻量设置（模型、回复倾向）在聊天页内做 BottomSheet 而不是跳转
> 2. 设置项改为"修改即保存"的实时模式，去掉保存按钮
> 3. 每个设置选项增加一行灰色解释文案

### 2.7 AI 行为质量（aiChatService + promptBuilder）

| 维度 | 评价 | 说明 |
|------|------|------|
| 标题生成 | ✅ 良好 | 有完整的去噪、低信号检测、fallback 逻辑 |
| 深度记忆 | ✅ 良好 | 有 scoring、ranking、去重、保守策略 |
| 资料检索 | ✅ 合理 | keyword + vector 双路召回 |
| Prompt 结构 | ⚠️ 可优化 | system prompt 太长时会挤占上下文窗口 |
| 错误信息 | ⚠️ 可优化 | 部分错误面向开发者而非用户 |
| 上下文窗口管理 | ⚠️ 缺失 | 无 token 计数和超长上下文截断策略 |

> [!IMPORTANT]
> **当前最大风险：没有 token 计数机制。**
>
> `CHAT_HISTORY_MESSAGE_LIMIT = 20` 是固定条数截断，但每条消息长度不确定。一个包含大段代码或长文档的对话，20 条可能远超模型的 context window，导致 API 400 错误或截断丢失关键上下文。ChatGPT 和 DeepSeek 都有 token counting + 智能截断。

#### 建议
1. 引入 token 估算（如按字符数 × 系数粗估），在拼 history 时做总量控制
2. 用户可见的错误信息做本地化人话转换（如 "API key 无效" → "请检查您的 API 密钥设置"）
3. 当上下文过长时，在 UI 提示用户"对话过长，较早的消息可能不再被参考"

## 四、体验细节清单

以下是逐文件发现的具体体验问题：

### AiChatScreen.tsx
1. **错误消息显示在列表顶部**（L704）而不是底部，用户需要向上滚动才能看到，违反直觉
2. **"加载更早消息"按钮**（L706）在顶部，但没有 loading 状态
3. **scrollToLatestMessage** 用了 3 次 setTimeout（80ms + 180ms），说明 FlatList 滚动不稳定，是体验隐患
4. **无空状态设计** — 新会话打开后是完全空白的页面
5. **键盘避让**逻辑对 bubble 编辑模式做了特殊处理，但没有测试覆盖，可能有边界问题

### AiChatComposer.tsx
6. **allowFontScaling={false}** — 禁止了字号缩放，对辅助功能用户不友好
7. **发送按钮 disabled 时只有 opacity 变化**，没有颜色变化，区分度不足
8. **输入框 placeholder "输入提示或需求"** — 可以更有引导性，如根据上下文动态变化

### AiMessageBubble.tsx
9. **用户消息最大宽度 88%**（L227）— ChatGPT 用的是约 85% 且有视觉区分，建议微调
10. **内联编辑器的 cursorColor 和 selectionColor 都是 `aiLightColors.onDark`** — 在 coral 背景上白色光标可能不够清晰
11. **版本切换器无动画过渡**，内容直接替换
12. **用户消息气泡只显示纯文本** — 不做 Markdown 渲染，但 AI 回复中如果引用了用户的 Markdown 格式内容，用户自己看不到格式

### AiMessageContent.tsx
13. **Markdown 解析器是手写的**，边界情况可能有遗漏：
    - 不支持嵌套列表（只处理单层）
    - 不支持图片语法 `![]()`
    - 不支持水平分隔线 `---`
    - 不支持 HTML 标签
    - 行内代码和加粗不能嵌套（如 `**`code`**`）
14. **代码块无行号**，长代码可读性差
15. **表格单元格硬编码 minWidth**（L383 `spacing[12] * 2`），窄屏幕可能溢出

### AiThinkingBlock.tsx
16. **100ms 间隔 setInterval**（L39）— 对于展示秒数来说，500ms-1000ms 就够了，100ms 导致不必要的重渲染
17. **思考完成后没有完成动画**，直接从"正在思考中…"跳到"思考完成"

### AiSessionConfigScreen.tsx
18. **"保存并开始聊天"和"仅保存设置"两个按钮** — 对用户来说决策成本过高，ChatGPT 的做法是设置即时生效
19. **删除会话按钮和保存按钮在同一视觉层级** — 危险操作没有足够的视觉隔离
20. **subtitle 显示 threadId 原始字符串**（如 `aithread_20260523...`）— 暴露内部 ID，不是用户语言

### AiHistoryScreen.tsx
21. **滑动归档用 PanResponder 实现**但没有动画过渡，行直接位移
22. **空状态只有一行文字"没有历史会话"** — 不符合 AGENTS.md 的空状态设计要求
23. **filter 切换无加载动画** — 切换过滤器时内容瞬间变化，没有过渡

### aiChatService.ts
24. **stoppedMessageIds 是内存 Set** — 应用重启后停止状态丢失
25. **`STREAMING_PERSIST_INTERVAL_MS = 120`** — 过于频繁的 SQLite 写入，可能在低端安卓设备上造成卡顿
26. **深度记忆更新是 fire-and-forget**（L1238 `void updateDeepMemoryAfterReply`）— 如果失败，用户完全不知道

## 五、优先级排序建议

```
P0 — 直接影响基本可用性
├─ 复制成功 Toast / 反馈
├─ Markdown 链接可点击
├─ 语音输入状态指示
├─ 空聊天页启发式引导
└─ 错误消息位置修正（移到底部）

P1 — 显著提升日常使用体验
├─ 聊天页内新建会话 / 快速切换
├─ 流式思考过程实时展示
├─ 消息操作改为长按浮出
├─ 滚动到底部 FAB
├─ 日期分隔线
└─ Token 上下文窗口管理

P2 — 体感提升但不阻塞
├─ 代码语法高亮
├─ 输入框高度动画
├─ 模型聊天页内切换
├─ 设置即时保存
├─ 历史搜索
└─ 图片附件缩略图预览
```

## 六、总结

Pixory 的 AI 聊天 **功能骨架完整度非常高**（深度记忆、RAG、版本回看、多模型、角色卡——这些很多竞品都没有）。但体验层的"最后一公里"还有明显差距，主要体现在：

1. **反馈感不足** — 复制无提示、语音无状态、思考无动画
2. **操作路径过长** — 新建会话和切换会话需要多次跳转
3. **内容渲染不完整** — 链接不可点、代码无高亮、不支持嵌套 Markdown
4. **空状态缺失** — 新会话空白页缺少引导

> [!NOTE]
> 总体评价：功能 85 分，体验 60 分。
> 
> 把 P0 的 5 项做完，体验分可以到 70+。把 P1 也做完，可以到 80+，接近 DeepSeek / ChatGPT 的基本体验水平。
