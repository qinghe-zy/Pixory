| 项目 | 内容 |
|---|---|
| 版本 | v2.8.3 |
| 计划日期 | 2026-09-07 |

| 过程状态 | 历史版本补全稿，原始英文/过程文档保留 |

## 2. 版本目标

本版本的产品目标是：恢复新设备首次安装和启动链路；保持既有聊天、资产、Personal 和备份数据结构不变。计划优先保护已有线程、角色、记忆、材料、Personal 和备份边界，不以视觉或单点修复破坏长期数据。

## 3. 范围

### 3.1 必须交付

- 对齐 Expo SDK 54 依赖，修复 expo-keep-awake 版本过高导致的 NoClassDefFoundError 和新安装启动闪退。
- 既有空间、文件和数据库作用域保持不变。
- 成功、空数据、失败、取消、重试、后台、返回和重复操作均有可解释结果。
- 版本变更能够在代码、功能矩阵、更新说明和诊断中追溯。

### 3.2 明确不做

- 不将实验能力写成默认稳定能力。
- 不改变原始导入文件，不以缩略图替代原文件。
- 不把 API key、恢复密钥、提示词或聊天正文写入诊断。
- 不在没有迁移方案的情况下改变历史数据结构。

## 4. 依赖与风险

依赖升级/降级需要同时验证 OTA 与 APK；只做启动验证不足以覆盖流式、导入和 Personal 任务

| 风险 | 预防 | 回滚 |
|---|---|---|
| 数据迁移失败 | 版本下限判断、幂等迁移、备份 | 保留现有数据库，阻断升级 |
| UI/动画异常 | 真机截图、长列表和返回链路回归 | 回退到稳定布局或关闭实验开关 |
| Provider 不兼容 | 模型白名单和能力探测 | 退回关键词/默认模型 |
| 隐私边界破坏 | space 校验、token 失效、字段脱敏 | 停止任务、关闭空间、清理缓存 |

## 5. 计划阶段

1. 需求冻结：确认本版本的用户问题、功能矩阵状态和非目标。
2. 技术设计：编写 Spec，标注数据、状态机、迁移和失败行为。
3. 开发：按领域提交，单项完成后更新功能矩阵。
4. 验证：自动化检查、Android 设备回归、诊断导出和数据安全检查。
5. 发布：版本文件一致、APK 生成、签名验证、更新说明发布。
6. 归档：仅在 APK 成功后移动版本文档，并记录 Commit、Tag 和产物。

## 6. 验收门槛

- 主流程来自真实产品入口，不依赖演示数据或人工改库。
- 关键失败场景不会产生半成品、重复消息或越权读写。
- 版本功能与功能矩阵状态一致。
- pnpm typecheck、pnpm test、git diff --check 通过。
- 若为 Android 发布，Gradle 必须先 clean；真机未验证项必须显式列出。

## 7. 交付物

- 中文 Plan、Spec、Review、文档驱动开发记录。
- 对应产品/技术变更和测试证据。
- 更新说明与版本归档信息。
