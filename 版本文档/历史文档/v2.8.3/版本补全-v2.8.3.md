# Pixory v2.8.3 产品交付档案（补全）

> 文档类型：历史版本产品层补全  
> 适用版本：v2.8.3  
> 文档状态：新增补全，不改动原始版本文档  
> 证据原则：以该版本目录、版本更新说明、功能矩阵和可验证实现为准。

## 1. 版本定位

本版本承接前一版本的产品与数据边界，不重写历史文档。

- **产品主题**：Android 原生启动崩溃热修复
- **用户问题**：依赖版本不匹配导致新安装 Android 启动时 NoClassDefFoundError，用户无法进入应用。
- **交付范围**：将 expo-keep-awake 对齐 Expo SDK 54，修复原生模块解析失败。

本档案用于补足产品经理视角的目标、用户价值、验收和遗留边界；原始 Spec、Plan、Review、Research 文件仍是该版本的过程证据。

## 2. 用户故事

 - 作为长期用户，我希望本版本解决“Android 原生启动崩溃热修复”相关问题，并在更新后能够继续使用 Pixory 而不丢失已有数据。
- 作为创作/材料用户，我希望本版本的能力能与线程、角色、材料和空间边界保持一致。
- 作为隐私用户，我希望任何新增或调整的能力都明确说明数据存储、授权和失败恢复方式。
- 作为维护人员，我希望能够从本版本文档定位实现入口、验收证据和未完成边界。

## 3. 验收标准

1. 主流程可从真实产品入口进入，不依赖演示数据、占位页面或人工改库。
2. 关键状态覆盖成功、空数据、失败、取消、重试、后台、返回和重复操作。
3. 与聊天、角色卡、记忆、材料、分支、备份和空间相关的数据保持原有作用域，不发生静默串线。
4. 涉及原件、隐私、密钥或删除时，先完成校验和用户确认；失败时不留下半成品。
5. 版本发布前的自动化、设备验证和未验证边界均记录在版本交付记录中。

## 4. 产品与数据影响

- **用户价值**：新安装、升级和启动不触发该类崩溃；依赖版本与 SDK 一致；构建产物可安装。
- **数据边界**：SQLite 保存结构化产品数据；原始媒体和文档保存在受管目录；派生缩略图与缓存独立保存。
- **隐私边界**：normal 与 personal 的路由、数据库、文件、缓存、后台任务和备份必须保持隔离。
- **兼容边界**：Android 优先；Provider、文件系统、迁移和恢复失败必须给出可操作结果。

## 5. 证据与状态

- 原始证据：Pixory-v2.8.3-版本更新说明.md；历史文档/v2.8.3/版本过程索引.md
- 当前能力判断：本档案只确认该版本的产品意图和交付边界；当前是否仍可用以 docs/feature-matrix.md 为准。
- 状态说明：如果功能矩阵标记为“部分实现、待验证、规划或实验/不上线”，不得在发布说明或用户手册中写成完整已上线能力。

## 6. 遗留限制与后续

该版本是稳定性修复，不引入新的用户工作流；后续构建必须继续执行 clean 和签名验证。

后续版本如修改本版本形成的核心不变量，必须新增决策记录、更新用户故事和验收标准，并在功能矩阵中同步说明影响。
