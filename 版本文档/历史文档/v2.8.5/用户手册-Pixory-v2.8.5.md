# Pixory 用户手册

## 1. 开始使用

首次打开 Pixory 后，先创建或导入一个角色卡，再进入新线程。建议先在设置中确认默认语言、模型提供商和空间。API key 等敏感设置只保存在设备 SecureStore，不要粘贴到普通聊天或诊断文本中。

## 2. 创建角色卡

1. 打开“角色”入口，点击新增。
2. 填写名称、角色描述、性格、场景、首次消息和边界模式。
3. 可添加头像、标签、备用问候语和默认模型。
4. 保存后从角色卡进入新线程。

导入 SillyTavern chara_card_v2/v3 时，Pixory 会读取角色描述、性格、场景、系统提示、示例对话和后置指令。导入后请人工检查宏替换、边界和语言偏好。

## 3. 开始和继续聊天

### 3.1 新建线程

选择角色后点击开始。用户消息会先保存在本地，随后才请求模型。网络不可用时，消息仍会留在草稿/待处理状态。

### 3.2 阅读流式回答

回答会逐步显示。停留在底部时会跟随最新内容；向上滚动查看历史时不会强行拉回底部。切后台、切页面或停止生成后，再次进入线程即可查看已保存内容。

### 3.3 停止、重试和恢复

- **停止**：结束本次生成并保留已生成内容。
- **重试**：在没有可恢复内容时重新请求。
- **继续**：存在部分回答时接着生成，系统会避免重复拼接。
- **失败**：查看提供商、网络或空间状态后再操作。

## 4. 编辑、分支和收藏

长按或打开消息操作菜单，可编辑用户消息、重新生成回答、收藏消息或从当前消息创建分支。原分支不会被覆盖；切换分支时，顶部应显示当前分支状态。

## 5. 管理记忆

在记忆入口查看记忆的范围、来源、状态、置信度和更新时间。

- **确认/锁定**：确认事实并避免普通自动流程改写。
- **编辑**：修正内容或范围。
- **标记过期**：保留历史但不再作为默认事实。
- **撤销/删除**：停止后续注入。
- **冲突处理**：查看冲突来源后选择保留、合并或询问。

记忆是背景信息，不是新的系统指令。对不确定内容，角色可能会使用“我记得……但不确定”的表达。

## 6. 使用 IP、图片、视频和 AI 文档

### 6.1 导入图片/视频

选择文件后，Pixory 会把原文件复制到应用管理目录，生成独立缩略图并写入元数据。原图不会被压缩、裁剪或覆盖。大批量导入前请检查空间和预估大小。

### 6.2 组织材料

为素材分配 IP、分组和标签，可添加备注、封面、收藏和最近查看状态。图片支持筛选和分页；视频只预加载当前及相邻窗口，当前视频独占声音。

### 6.3 AI 文档与引用

导入文档后，系统会解析、分块和索引。在线程中明确开启 IP/知识库上下文后，回答可能引用材料。点击 [[cite:S1]] 可回到来源片段；若材料版本更新，引用会显示对应版本。

## 7. Personal 私密空间

Personal 与普通空间分开存储。进入 Personal 需完成密码、图案、恢复密钥或生物识别验证。

锁定 Personal 后：

- 后台任务令牌失效；
- 等待中的任务停止或进入安全等待；
- 数据库关闭；
- 图片缓存只保留在内存中的内容被清理。

把素材移出 Personal 前会出现两次风险确认。与 Personal 绑定的线程、IP 或知识库不能被静默移动。

## 8. 备份与恢复

备份包含数据库、原图、缩略图、AI 文档、聊天附件、角色头像和 Manifest 校验信息。API key 等 SecureStore 机密不会进入备份。

恢复时请选择可信备份包。系统会先校验路径、大小和 SHA-256，再通过事务导入并重建搜索索引。若校验失败，请保留原数据并查看恢复报告，不要手工覆盖应用目录。

## 9. 回收站

删除素材默认只是移入回收站。进入回收站可恢复；“清空回收站”才会物理删除原图和缩略图。清空前请确认备份已经完成。

## 10. 诊断与问题反馈

在设置中可导出标准或深度诊断。诊断会自动过滤提示词、回答正文、文件路径、URI、密钥、Cookie、密码和 Base64。反馈时建议附带版本号、设备型号、发生时间、线程是否可恢复等信息。

## 11. 常见问题

### 为什么回答没有引用材料？

请确认线程已绑定正确 IP/知识库，材料解析已完成且问题包含可检索关键词。低相关度结果会被主动省略。

### 为什么角色记住的内容不准确？

打开记忆详情查看来源和置信度。可以标记过期、编辑或撤销，不建议把未经确认的内容锁定为长期事实。

### 为什么重进线程后回答继续出现？

这是生成恢复机制在工作。系统会读取本地生成状态和部分内容，最多执行一次续接或一次重试。

### 为什么导入被阻止？

可能超过单次数量、单文件大小、批次容量或剩余空间门槛。按导入预检提示拆分批次或清理空间。

## 12. 安全建议

不要在普通聊天中发送 API key、恢复密钥或密码；不要把 Personal 备份包上传到不可信位置；清空回收站和删除备份前先确认没有恢复需求。

## 13. 完整任务指南

### 13.1 第一次建立可持续陪伴

推荐操作顺序如下：

1. 创建一个角色卡，不要一开始就把所有世界观内容塞入首次消息。
2. 在角色卡中填写长期稳定设定：身份、性格、边界、语言和称呼。
3. 把会经常引用的设定放入一个 IP 或知识库，把一次性资料留在普通线程材料中。
4. 开始线程后先进行 3–5 轮普通对话，确认角色口吻和边界符合预期。
5. 看到不准确的长期事实时，优先在记忆详情中修正，不要反复发送“请记住”。

### 13.2 如何判断一条记忆是否应该保留

建议保留：长期偏好、稳定称呼、明确承诺、重要关系和用户主动确认的事实。
建议只留在当前线程：临时计划、当天情绪、一次性任务和未确认猜测。
建议撤销或标记过期：已经改变的地址、时间、计划、关系状态或用户明确否认的内容。

打开记忆详情时重点看四项：来源消息、作用范围、置信度、更新时间。看不到来源或范围的内容，不建议直接锁定。

### 13.3 如何让材料引用更可靠

1. 文档名称和章节标题尽量具有辨识度。
2. 将互相矛盾的设定拆成不同版本，不要覆盖原文件。
3. 线程只绑定真正需要的 IP/知识库，避免召回噪音。
4. 提问时提供明确对象和关键词，例如角色名、章节名或事件名。
5. 点击引用回看原片段；如果原材料已更新，重新开始一轮生成。

### 13.4 长线程的维护方法

- 每隔一段时间检查摘要是否仍然准确。
- 把关键关系、承诺和偏好交给记忆治理，不要依赖几百轮旧消息。
- 重要路线用分支保存，不在原分支反复编辑。
- 如果线程变得很长且回答变慢，可新建分支或新线程并挂载同一角色与材料。

### 13.5 导入大批量素材的建议流程

1. 先清理临时文件并确认剩余空间。
2. 按 IP 或主题拆分批次，不要一次导入全部相册。
3. 先导入 20–50 个样本确认文件名、分组和标签规则。
4. 再提交大批次，保留导入批次记录。
5. 导入结束后查看失败项、跳过项和重复项，不要只看总成功数量。
6. 完成后立即做一次备份，确认 Manifest 和原图校验存在。

### 13.6 备份前检查清单

- [ ] 当前没有正在写入的大批量导入。
- [ ] 重要线程的生成任务已经完成或明确停止。
- [ ] Personal 已解锁，并选择了正确的普通/隐私备份类型。
- [ ] 设备剩余空间足以生成临时备份包。
- [ ] 导出后能看到文件大小、校验结果和保存位置。

## 14. 故障处理决策树

### 14.1 “回答一直转圈”

先看是否已经出现部分回答。若有，使用“继续”；若无，使用“重试”。两次仍失败时停止任务，保留错误信息并导出标准诊断。不要连续快速点击发送，这会让旧任务和新任务互相取消。

### 14.2 “返回后页面空白或滚动位置异常”

先等待一秒并重新进入当前线程/素材页。如果仍异常，记录版本、设备、页面入口和是否从阅读器返回，再导出诊断。不要立即清除应用数据，清除会破坏本地恢复证据。

### 14.3 “素材导入成功但看不到缩略图”

检查原文件是否存在、是否显示 previewPending、是否处于回收站。原文件记录存在时，不要重复导入同一文件；先让缩略图任务重试或重新打开页面。

### 14.4 “Personal 无法打开”

确认输入方式（密码/图案/恢复密钥）是否正确，避免连续试错触发锁定。锁定后等待策略结束，再使用恢复流程。不要把恢复密钥截图发送给他人或放入普通诊断。

## 15. 用户可见状态的含义

| 状态 | 含义 | 建议动作 |
|---|---|---|
| 生成中 | 请求已发出或正在接收 | 保持页面或稍后回来 |
| 可继续 | 已有部分内容但未完成 | 点击继续 |
| 可重试 | 没有可用部分内容 | 检查网络后重试 |
| 已停止 | 用户或系统结束任务 | 可重新生成 |
| 已过期 | 记忆或材料不再默认使用 | 查看来源后决定 |
| 需确认 | 记忆存在冲突或安全风险 | 先查看并确认 |
| 待解析 | 材料已复制但索引未完成 | 等待或重试解析 |

## 16. 数据安全边界

普通备份不包含 Personal 数据；Personal 备份也不会把 SecureStore 中的 API key 和恢复密钥导出。删除线程、材料或记忆前，应用优先执行软删除或标记删除，真正物理清理由用户显式触发。
