# Pixory v2.8.5 中文版 Spec

## 1. 设计摘要

表单内联流、底部悬浮操作、全局返回按钮、筛选/排序抽屉、吸顶顶栏、长按误触、IP排序、恢复密钥与唯一身份逻辑。本 Spec 将版本目标转化为可实现契约，所有新增逻辑必须服从本地优先、空间隔离、原始文件安全和可恢复生成原则。

## 2. 功能契约

| 能力 | 输入 | 正常结果 | 异常结果 |
|---|---|---|---|
| 版本核心功能 | 用户操作、已有数据 | 状态和数据按版本目标更新 | 显示可行动错误，不静默丢失 |
| 列表/导航 | 当前空间、筛选、路由 | 保留滚动、筛选和返回状态 | 回到稳定入口并记录诊断 |
| AI/Provider | 线程、角色、模型、材料授权 | 按提示词分层和预算生成 | 重试/续接/停止，保留部分内容 |
| Personal | 解锁态、任务 token | 仅在授权空间读写 | token 失效、关闭数据库、拒绝操作 |
| 文件/迁移 | 受管路径、版本号 | 幂等写入、可恢复 | 回滚或保留原文件 |

## 3. 数据与状态

1. 结构化记录写入 SQLite；原图、视频、AI 文档和角色头像写入受管目录。
2. normal 与 personal 使用独立数据库、文件目录、缓存和路由。
3. 生成相关更新必须携带 generationId、threadId 和当前空间。
4. 删除默认软删除；只有明确的清空动作才物理删除。
5. 迁移必须有版本下限判断，重复执行不能重复添加字段或索引。
6. 与记忆、材料、缓存和诊断相关的版本字段必须可用于失效和回放。

## 4. 交互与边界

- 重要确认操作使用明确的风险文案；移出 Personal 至少二次确认。
- 列表有空状态、失败状态和清除筛选入口。
- 实验/诊断模式与默认体验隔离，关闭开关不影响普通链路。
- 视觉效果不得遮挡内容、按钮或系统返回区域。
- 需要用户等待时显示阶段，不使用无意义的永久 loading。

## 5. 测试用例

### 正向

- 新安装、升级安装、已有数据库升级。
- 长线程搜索、返回、滚动、筛选和重复点击。
- AI 发送、首字节、流式、停止、续接、重试和重进线程。
- 图片/视频导入、重复文件、批量门槛、软删除和恢复。
- Personal 解锁、锁定、恢复密钥和跨空间移动。
- 诊断标准/深度导出，ZIP 可保存且不含敏感字段。

### 反向

- 网络超时、提供商返回错误、页面失焦、应用被杀。
- 数据库锁、迁移重复执行、空间不足、文件复制失败。
- 错误的模型白名单、非法路径、错误恢复密钥、连续失败尝试。
- 低端 Android、宽屏、长文本、无材料、无记忆和空列表。

## 6. 兼容性与回滚

- 旧版本已有聊天、角色、记忆、材料、Personal 数据必须可读取。
- 版本升级失败不得删除数据库或原始文件。
- OTA/本地 APK 必须使用同一版本元数据和 runtimeVersion。
- 如无法验证某一设备或真实恢复链路，应在 Review 中标记待验证，而不是默认通过。
