# Pixory 稳定版产品需求文档（PRD）

> 文档类型：产品基线 PRD  
> 适用版本：Pixory v2.8.5 及后续稳定化补丁  
> 文档状态：可交付基线（基于当前功能矩阵、源码入口、测试覆盖和已归档版本证据）  
> 编制日期：2026-09-11  
> 事实源：[`docs/feature-matrix.md`](../../docs/feature-matrix.md)

## 1. 产品定义

Pixory 是 Android-first、local-first 的陪伴式 AI 聊天与个人材料管理应用。产品中心是长期、连续、可恢复且可信的 AI 对话；IP、图片、视频、文档和知识材料是聊天的本地上下文基础，而不是独立的云相册业务。

Pixory 的产品承诺：

1. 对话可以长期保存、搜索、分支、编辑、重新生成并在异常后恢复。
2. 角色卡、记忆、材料和 Provider 设置是可管理的产品数据，而不是临时提示词。
3. 用户能够理解哪些内容进入了上下文，能够撤销、删除或隔离敏感数据。
4. 原始图片和视频安全保留，预览、缩略图与原件始终分离。
5. 普通空间与 Personal 空间在数据库、文件、缓存、后台任务和备份边界上强隔离。

## 2. 用户与核心场景

### 2.1 目标用户

| 用户 | 核心任务 | 成功表现 |
| --- | --- | --- |
| 长期陪伴用户 | 与固定角色持续聊天，保留共同经历 | 能快速回到正确线程和分支，角色不失忆、不串线 |
| 创作与角色用户 | 创建/导入角色卡，使用角色设定和材料创作 | 角色身份、问候语、头像、提示词和材料可复用 |
| 材料整理用户 | 管理 IP、图片、视频、标签、分组和文档 | 导入不损坏原件，能检索、引用、批量整理和恢复 |
| 隐私敏感用户 | 把个人对话和材料放入 Personal 空间 | 锁定、备份、导入、后台任务和缓存均不越界 |
| 维护与支持人员 | 定位性能、Provider、数据和渲染问题 | 诊断包可复盘，发布和回滚边界清晰 |

### 2.2 Jobs to be Done

- 当我想继续一段长期关系时，我希望回到正确的线程、分支和角色状态，而不是重新解释背景。
- 当我有一组角色或 IP 材料时，我希望一次导入并安全管理，让 AI 能在明确范围内引用它们。
- 当我不满意某条回复时，我希望编辑、重新生成或切换分支，同时保留旧路径，避免不可逆丢失。
- 当我处理隐私内容时，我希望知道数据在哪里、谁能访问、如何锁定、导出、恢复和彻底删除。
- 当应用或网络异常时，我希望已经显示的内容和未完成任务都能被安全恢复，不产生幽灵消息。

## 3. 产品目标与非目标

### 3.1 当前阶段目标

1. 把 AI 聊天做成稳定、连续、可恢复的主工作流。
2. 让角色卡、记忆、分支、材料和 Provider 形成可理解的闭环。
3. 以本地 SQLite 和受管文件存储保证数据一致性与原件安全。
4. 将 Personal 空间隔离、备份恢复、删除和诊断做成可审计能力。
5. 在 v2.8.5 基线之后优先收敛稳定性、性能和真机验证，而不是继续扩张表面功能。

### 3.2 明确非目标

- 不做云相册、社交关系、公开内容社区。
- 不默认做通用图片编辑器或 AI 图片生成器。
- 不在没有隐私边界、删除策略和用户授权的情况下引入服务端语义缓存。
- Live2D 桌宠当前关闭/不上线；恢复前必须重新完成 Android 性能验收。
- 多正文气泡、Response Presentation Plan 等仍属规划/暂缓，不写入当前已上线能力。
- AI 不主动发消息、不伪造在线状态、已读回执或后台主动关心。

## 5. 核心用户体验原则

1. **连续性优先**：任何刷新、分页、切换、后台恢复都不能把用户带到错误线程、错误分支或错误空间。
2. **用户拥有上下文**：记忆、日记、梦境、材料引用必须有作用域、来源和可撤销边界。
3. **可恢复优先于炫技**：停止、失败、取消、重试和进程恢复均应保留可操作状态。
4. **本地优先但不盲目离线承诺**：本地数据和密钥可用；需要网络的模型能力应明确显示 Provider 状态。
5. **原件不可破坏**：导入只复制原件，缩略图和预览是独立派生文件。
6. **少打扰的陪伴**：不主动推送、不伪造人类在线状态；由用户主动进入、发送和确认。

## 6. 功能需求

### 6.1 聊天与线程

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-CHAT-01 | 用户可以创建、打开、重命名、删除和搜索线程 | 空线程不进入历史列表；删除有明确确认和数据边界 |
| FR-CHAT-02 | 线程保存角色快照、Provider、模型、空间、上下文类型和当前分支 | 历史消息按产生时快照渲染，不被当前配置静默改写 |
| FR-CHAT-03 | 用户可发送文本、图片和支持的附件 | 图片在 AI 开始回复时即可呈现；附件写入受管目录 |
| FR-CHAT-04 | AI 回复支持流式显示、停止、失败、重试和恢复 | 已显示内容不丢；未显示内容不污染上下文、搜索、摘要和记忆 |
| FR-CHAT-05 | 用户可编辑历史用户消息并创建新分支 | 旧路径保留；新路径从编辑点继续；当前 adopted route 唯一 |
| FR-CHAT-06 | 用户可重新生成、继续生成和查看消息版本 | 版本关系可追溯；当前展示与持久化状态一致 |
| FR-CHAT-07 | 用户可在当前分支内搜索消息并定位 | 搜索结果不跨分支串入；返回后保留阅读位置 |
| FR-CHAT-08 | 用户可收藏 AI 消息并从收藏中心返回 | 收藏显示来源线程和定位消息 |
| FR-CHAT-09 | 用户可切换沉浸对话/日常陪伴模式 | 切换影响下一轮；历史消息保留 modeSnapshot |

### 6.2 角色、记忆与陪伴运行时

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-ROLE-01 | 用户可创建和编辑角色卡 | 角色名、提示词、首条问候、头像、标签和模型偏好可保存 |
| FR-ROLE-02 | 支持从 SillyTavern V2 PNG 角色卡导入 | 解析失败可降级为头像导入；不联网、不覆盖原图 |
| FR-MEM-01 | 记忆按空间、线程、角色、IP/知识库等作用域管理 | 上下文组装不得越过作用域 |
| FR-MEM-02 | 记忆记录保存来源、状态、版本和用户操作 | 用户可查看、忽略、撤销、重置或清空 |
| FR-COMP-01 | Companion Event 只从有证据的完整用户消息产生 | 引用、否定、假设、玩笑和第三方转述不得直接形成高影响事实 |
| FR-COMP-02 | 角色日记、梦境和思绪使用冻结来源快照 | 重试复用冻结输入；来源失效时显示可操作状态 |
| FR-COMP-03 | 内心产物进入上下文前需要作用域与用户许可 | 梦境/日记/思绪标记为低权限、非事实、非指令材料 |

### 6.3 材料、IP 与媒体

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-MAT-01 | 用户可导入图片、视频、ZIP/PIXORYPACK 和 AI 文档 | 先复制原件，再读元数据、生成缩略图、写数据库记录 |
| FR-MAT-02 | 导入前执行数量、单文件、总容量和磁盘余量 gate | 当前混合导入上限按实现矩阵执行，不得绕过 |
| FR-MAT-03 | 用户可按 IP、分组、标签、收藏和搜索结果浏览 | 采用分页/虚拟列表；筛选阅读器携带完整查询 scope |
| FR-MAT-04 | 用户可批量移动、打标签、整理和撤销 | 批量操作有事务边界和可回退快照 |
| FR-MAT-05 | 重复检测支持 exact hash 和 visual hash | 导入可跳过 exact duplicate；审查后使用软删除 |
| FR-MAT-06 | 删除默认进入回收站 | 可恢复；只有明确清空回收站才物理删除文件 |
| FR-MAT-07 | AI 文档支持解析、切片、检索、引用和阅读 | 引用可回到来源；缺少闭环的能力标记为部分实现 |

### 6.4 隐私、备份与安全

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-PRIV-01 | normal 与 personal 使用独立数据库和受管文件目录 | 路由、查询、缓存、后台任务和备份均携带 space |
| FR-PRIV-02 | Personal 锁定后使任务令牌失效并等待任务停稳 | 不继续写入 Personal；内存图片、reader session 和临时文件清理 |
| FR-PRIV-03 | 密码、图案、恢复密钥和生物识别可管理 | 失败锁定、防爆破和重置流程可解释、可恢复 |
| FR-BACK-01 | 备份包含数据库、原件、缩略图、文档、附件、头像和 manifest | SecureStore 中 Provider API Key 不进入备份 |
| FR-BACK-02 | 恢复前校验版本、相对路径、大小和 SHA-256 | 事务失败、取消或锁定时回滚数据库并清理本次文件 |
| FR-BACK-03 | 备份按空间和类型隔离 | normal 备份不包含 Personal；Personal 备份需验证 |

### 6.5 性能、诊断与发布

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-OPS-01 | 长列表使用 keyset cursor、虚拟化和有界并发 | 不因数据量增长创建无界 Promise 或查询循环 |
| FR-OPS-02 | 流式 UI 发布与持久化节奏分离 | 网络 delta 不得逐 token 触发整棵消息树刷新 |
| FR-OPS-03 | 诊断日志不阻塞聊天主流程 | 日志区分未采集、被过滤、保留、失败和真实异常 |
| FR-REL-01 | 版本号、runtimeVersion、APK、官网和更新 JSON 同步 | 构建前 clean；APK 成功后才归档过程文档 |
| FR-REL-02 | 应用内产品文档与官网手册保持事实一致 | 修改用户手册时同步内嵌副本 |

## 7. 数据与状态约束

### 7.1 数据边界

- SQLite 保存线程、消息、版本、分支、角色、记忆、材料元数据、任务和审计所需状态。
- 原始图片/视频复制到受管存储；缩略图、预览、缓存和临时文件分开保存。
- API Key 仅保存于 SecureStore；不进入 SQLite、备份、诊断包或远程日志。
- 所有 AI 上下文必须按顺序区分：稳定指令、角色快照、记忆快照、检索上下文、对话历史、当前请求。

### 7.2 关键状态机

| 对象 | 状态 | 关键不变量 |
| --- | --- | --- |
| AI 生成 | queued → generating → completed/failed/stopped | generationId、space、thread、branch 必须一致；终态可恢复 |
| 导入批次 | preflight → copying → metadata → committing → completed/failed/cancelled | 记录不存在原件缺失；失败清理本次文件 |
| 记忆事件 | candidate → accepted/ignored/expired/reset | 只有有效来源和当前作用域可进入上下文 |
| 回收站素材 | active → soft_deleted → restored/permanently_deleted | 默认不物理删除 |
| Personal 任务 | leased → running → settled/cancelled/retryable | 锁定先撤销 token，再等待任务停稳 |

## 8. 非功能要求

1. **可靠性**：异常、取消、后台、路由切换和进程重启后不产生重复落库、错线程或幽灵任务。
2. **性能**：聊天和媒体列表必须采用已有 cursor、虚拟化、缓存和有界并发策略；具体 Android 门禁以测试/真机记录为准。
3. **安全**：密钥不出 SecureStore；Personal 数据不出 Personal；诊断包默认脱敏。
4. **可访问性**：重要按钮有可读标签、合理触控区域、错误反馈和清晰空状态。
5. **兼容性**：Android 优先，Provider 采用 OpenAI-compatible 兼容策略；不得假设 `/models` 一定可靠。
6. **可维护性**：功能矩阵是最新能力事实源；版本过程文档按正式版本本地归档。

## 9. 指标与验收门禁

### 9.1 必须持续追踪的产品指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 首次成功对话率 | 新用户完成第一条消息并获得可见终态回复的比例 | 判断首轮体验和 Provider 配置问题 |
| 7/30 日连续对话率 | 同一用户在 7/30 日内返回并继续线程的比例 | 判断长期陪伴价值 |
| 回复恢复成功率 | 中断或后台后能恢复到可操作终态的生成比例 | 判断可信度 |
| 记忆纠错率 | 用户忽略、撤销、重置记忆事件的比例 | 监控记忆过度推断 |
| 材料引用可用率 | 引用可打开且来源内容匹配的回答比例 | 判断 RAG 闭环 |
| Personal 越界事件 | normal/personal 交叉读取、写入或缓存命中次数 | 安全硬门禁，目标为 0 |
| 原件安全率 | 导入后原件 hash/大小保持一致的比例 | 判断资产安全 |
| 崩溃/白屏/卡住率 | 按版本、设备和入口分桶 | 判断稳定版本质量 |

当前文档不虚构已达成数值；每次版本发布前由测试、诊断和运营记录具体基线、目标和实测结果。

### 9.2 稳定版本发布门禁

- `pnpm typecheck`、`pnpm test`、`git diff --check` 通过，或把已知失败及影响边界记录在版本文档。
- 关键聊天、分支、记忆、Personal、导入、备份恢复、回收站和更新链路完成回归。
- 关键 Android 真机门禁未验证时，发布说明不得写“完全验收”。
- 版本号、runtimeVersion、APK、官网、更新 JSON、公告和功能矩阵保持一致。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Provider 响应格式/模型列表不稳定 | 无法发送或模型误判 | 采用兼容探测、白名单、明确错误和本地配置 |
| 长线程和流式渲染性能下降 | 卡顿、错位、白屏 | 保持 adopted route、keyset、流式批次和 Android 门禁 |
| 记忆或 RAG 越权 | 信任和隐私受损 | 强制作用域、来源、版本和 fail-closed |
| Personal 后台任务越界 | 高风险隐私事故 | task token、锁定屏障、独立数据库/目录和审计 |
| 备份不完整或恢复冲突 | 数据丢失 | Manifest V2、hash/size 校验、事务合并和真实设备验收 |
| 继续扩张未验证能力 | 稳定版本延期 | 路线图按稳定化优先，实验能力默认不上线 |

## 12. 变更规则

当用户可见功能、数据模型、隐私边界、导入/备份/发布流程或 AI 能力发生重大变化时：

1. 先更新功能矩阵和对应用户故事/流程。
2. 在当前版本目录新增或更新版本过程文档，不覆盖历史归档。
3. 发布前复核 PRD、测试、Release Notes、官网手册和版本索引。
4. 已上线、部分实现、待验证和规划状态必须保持可区分。
