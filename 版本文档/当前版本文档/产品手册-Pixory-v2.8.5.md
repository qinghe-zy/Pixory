# Pixory 产品手册

## 1. 产品定位

Pixory 是“本地材料底座 + 长期陪伴式 AI”的 Android-first 产品。它把角色身份、线程历史、记忆、分支、IP/知识库材料、原始资产和隐私空间放在同一条可恢复链路上。

## 2. 产品组成

| 产品域 | 责任 |
|---|---|
| 陪伴聊天 | 角色对话、流式回答、恢复、收藏、搜索 |
| 角色系统 | 角色卡、提示词、开场白、头像、边界 |
| 记忆系统 | 事实、事件、关系信号、任务和用户治理 |
| 材料系统 | IP、图片/视频、AI 文档、标签、引用 |
| Personal | 私密数据、认证、任务隔离和跨空间风险 |
| 数据系统 | SQLite、文件目录、备份 Manifest、缓存 |
| 质量系统 | 生成指标、性能窗口、诊断、版本文档 |

## 3. 产品运行模型

### 3.1 本地优先

聊天和材料元数据首先落本地，网络只负责调用配置的 AI 提供商或明确立项的服务端网关。用户可以在无网络时浏览历史、管理角色、查看材料和处理记忆。

### 3.2 空间隔离

普通空间和 Personal 是两个数据边界，而不是一个页面上的筛选条件。数据库、文件、缓存、任务令牌和路由均需经过空间检查。

### 3.3 可恢复生成

生成不是一次 API 调用，而是可观测状态机。每次请求都有 generationId、持久化阶段、恢复租约和最终收敛状态。

### 3.4 证据化上下文

提示词由稳定策略、角色、材料规则、记忆快照、历史、运行时状态、检索材料和当前问题组成。动态内容可裁剪，角色和安全规则有最小保留长度。

## 4. 业务操作规范

1. 新功能先更新功能矩阵，再补 PRD、Spec 和验收故事。
2. 任何记忆字段变化必须说明作用域、来源、撤销和迁移。
3. 任何材料导入变化必须验证原文件安全和备份兼容。
4. 任何服务端或缓存设计必须说明个人空间隔离、保留期和删除传播。
5. 发布前检查版本文件、网站更新信息、APK 和版本文档是否一致。

## 5. 角色分工

| 角色 | 责任 |
|---|---|
| 产品经理 | 需求基线、版本目标、用户故事、验收和路线图 |
| 设计 | 移动端流程、空状态、风险确认、可解释入口 |
| 客户端 | Expo/React Native、路由、UI、流式和本地存储 |
| AI/算法 | 提示词组装、检索、记忆、缓存和提供商适配 |
| 数据/基础设施 | SQLite、迁移、备份、文件安全、诊断 |
| 测试/发布 | 自动化、真机、签名、APK、文档归档 |

## 6. 关键质量闸门

- P0：Personal 隔离、生成恢复、记忆治理、原图安全、备份一致性。
- P1：流式帧率、列表性能、材料引用、搜索、回收站。
- P2：视觉增强、实验能力、未验证的后台行为。

## 7. 指标解释

- 连续性：恢复成功率、线程重开可用率、重复回答率。
- 信任：引用可定位率、记忆撤销完成率、冲突处理率。
- 性能：首字节、首个 UI 可见、首个 UI patch、JS/UI p95。
- 安全：Personal 越权、敏感字段诊断命中、备份校验失败。
- 成本：输入/输出 token、缓存命中、提供商错误和超时。
