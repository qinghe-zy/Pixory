# Pixory 产品路线图（全量版）

## 1. 路线图口径

路线图以 v2.8.5 为稳定基线，按“已交付能力—当前收口—下一阶段—中长期探索”组织。日期是规划窗口，不是对外承诺；每项能力以功能矩阵状态为准。

## 2. 已交付演进

| 阶段 | 主要成果 | 产品意义 |
|---|---|---|
| v2.1.x–v2.4.x | IP、图片/视频、分组、标签、批量导入、浏览、回收站 | 建立本地材料安全底座 |
| v2.5.x–v2.6.x | AI 文档、角色、线程、记忆、Personal、备份 | 从资产管理走向可持续对话 |
| v2.7.x | 分支、上下文、视频窗口、陪伴运行时、诊断 | 提升长线程可用性和可解释性 |
| v2.8.1–v2.8.5 | 角色日记、记忆治理、流式恢复、上下文缓存、监测 | 形成稳定版的连续陪伴闭环 |

## 3. 当前周期：v2.8.5 → v2.8.6

### 目标

1. 将稳定版核心链路从“功能可用”提升为“可验证、可恢复、可审计”。
2. 补齐真实 Android 设备上的备份恢复、后台生成和 Personal 边界验证。
3. 收拢 AI 文档统一入口、来源更新和跨材料搜索。

### 交付主题

| 主题 | 交付结果 | 验收信号 |
|---|---|---|
| 生成可靠性 | 中断恢复、停止、路由切换行为统一 | 失败线程可恢复，重复回答率下降 |
| 记忆可信度 | 冲突/过期/用户锁定的 UI 和操作闭环 | 用户能定位来源并撤销 |
| 材料体验 | 文档入口、版本、引用跳转统一 | 回答引用可回到原片段 |
| Personal 验证 | 锁定、任务令牌、跨空间移动回归 | 无越权读写 |
| 发布质量 | 设备测试、性能基线、诊断报告 | 发布门槛有记录 |

## 4. 下一阶段：v2.9.x

1. **会话工作台**：线程搜索、收藏、分支和记忆治理统一入口。
2. **材料工作台**：IP、AI 文档、图片/视频和引用关系统一浏览。
3. **伴侣档案**：用户可见的关系摘要、偏好、承诺和修复入口。
4. **更细的本地性能策略**：按设备压力、线程长度、内容密度动态调节。
5. **可选的安全 AI 网关评估**：先做威胁模型、密钥边界、缓存范围和删除策略，再决定是否开发。

## 5. 中长期：v3.x

### 5.1 可控服务端能力（规划）

- 提供商路由、密钥托管、提示词前缀缓存和成本观测。
- 默认不将 Personal 内容纳入语义缓存。
- 设计空间、线程、角色、IP、知识库和分支维度的缓存隔离。
- 明确保留期、删除传播和故障降级。

### 5.2 更深的陪伴能力（探索）

- 角色日记、离线想法和梦境的可配置编排。
- 多气泡回答和跨日关系线索。
- Live2D 作为独立验收项目，不与稳定聊天链路强耦合。

### 5.3 备份与迁移（强化）

- 真实设备端到端恢复矩阵。
- 大型材料增量备份和校验报告。
- 跨版本迁移的可回滚演练。

## 6. 路线图决策规则

1. 任何新功能先回答：是否提升陪伴连续性、信任、隐私或材料可用性。
2. 需要服务端的能力必须先完成隐私边界、缓存范围、删除行为和失败降级设计。
3. 复杂视觉能力不应挤占生成恢复、记忆正确性和原文件安全资源。
4. 规划项没有验收证据前，不写入“已实现”。

## 7. 关键指标

| 方向 | 指标 |
|---|---|
| 连续性 | 线程恢复成功率、生成中断可恢复率、消息重复率 |
| 可信度 | 记忆冲突修复率、用户撤销成功率、引用可定位率 |
| 性能 | 首字节、首个 UI 可见、首个 UI patch、JS/UI 帧 p95 |
| 稳定性 | 崩溃率、空白屏嫌疑率、数据库锁等待、导入失败率 |
| 隐私 | Personal 越权事件数、敏感诊断字段命中数 |
| 成本 | 提示词 token、缓存复用率、提供商错误率 |
