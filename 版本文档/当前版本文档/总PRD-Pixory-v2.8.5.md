本 PRD 是 Pixory 从开发至今适合沉淀为产品基线的统一说明。它描述用户价值、业务边界、交互契约、数据边界、验收口径和后续演进原则；不替代各版本 Spec、技术设计和测试报告。

## 2. 产品定义

Pixory 是一个 Android-first 的本地优先陪伴式 AI 应用。产品中心是可持续的 AI 对话，而不是一次性问答。用户可以创建角色卡、建立长期线程、管理记忆、分支对话、挂载 IP/知识库材料，并在正常空间与 Personal 私密空间之间保持明确的数据隔离。

传统 IP 图片/视频资产库是对话上下文的本地材料基础：原图、视频、角色头像、文档、标签、分组和引用关系都需要可管理、可检索、可备份。任何 AI 功能不得破坏原始素材，不得用缩略图替代原文件。

## 3. 用户与场景

### 3.1 目标用户

| 用户 | 主要目标 | 关键痛点 |
|---|---|---|
| 长期陪伴用户 | 与固定角色持续聊天，保持关系连续性 | 换设备、切线程、上下文过长后角色失忆 |
| 角色创作者 | 维护角色设定、头像、开场白和行为边界 | 角色配置分散，改动后难以验证 |
| IP/世界观创作者 | 让角色引用本地图片、文档和设定 | 材料难检索，引用不透明，原文件容易丢 |
| 高隐私用户 | 在本地保存私密聊天和材料 | Personal 数据容易与普通数据混淆 |
| 技术/运营人员 | 管理版本、诊断生成异常和成本 | 缺少可追踪的生成链路和指标 |

### 3.2 核心任务

1. 30 秒内开始一个可继续的角色对话。
2. 在长线程中恢复最近上下文，并能追溯更早的关键事实。
3. 明确看到记忆来源、作用范围和修改/撤销入口。
4. 从本地导入素材，让 AI 在得到许可后引用并给出来源。
5. 在生成中切后台、切路由、停止或网络失败后，尽量恢复而不是丢消息。
6. 备份数据库、原文件和 AI 材料，恢复后保持关系与引用完整。

## 4. 产品原则

1. **陪伴连续性优先**：不以短期视觉完成度换取对话、记忆或分支丢失。
2. **隐私边界可见**：普通空间与 Personal 空间分库、分文件目录、分路由。
3. **用户控制记忆**：自动记忆保守；用户可查看、编辑、锁定、撤销和删除。
4. **原始素材不可损坏**：导入只复制原文件；预览和缩略图是独立文件。
5. **可恢复生成**：每次生成均具备本地落盘、状态机和恢复租约。
6. **证据优先**：没有足够记忆或材料证据时，模型应保守表达，而不是编造。
7. **能力状态透明**：实验、规划、待验证能力不能伪装成稳定能力。

## 5. 功能范围总览

### 5.1 已实现或已具备稳定基础的能力

- AI 陪伴聊天：线程、角色卡、流式回答、停止/重试/恢复、收藏、搜索、编辑、重新生成。
- 分支对话：消息版本、分支路由、冻结采用的角色提示/摘要/源消息。
- 记忆：全局、角色、IP、知识库、线程、分支等范围；确认、冲突、过期、压制和删除状态。
- 材料上下文：AI 文档解析、分块、关键词/混合检索、引用标记和本地素材检索。
- IP 资产：图片/视频、分组、标签、备注、封面、批量导入、重复识别、回收站。
- Personal 空间：独立数据库、文件空间、密码/图案/恢复密钥/生物识别入口及任务隔离。
- 备份恢复：Manifest V2，包含 SQLite、原图、缩略图、AI 文档、聊天附件、角色头像。
- 诊断基础设施：生成指标、窗口聚合、空白屏检测、脱敏、保留策略。

### 5.2 部分实现或需持续完善

- 陪伴手帐与数据面板。
- AI 文档统一入口、术语管理、来源更新和跨材料搜索。
- 多气泡回复、更多后台陪伴任务。
- 全量真实设备导出→清空/重装→导入恢复验证。

### 5.3 实验、规划与不纳入稳定承诺

- “无界沉浸文学”实验能力。
- DeepSeek V4 视觉白名单能力。
- Live2D：源码和资源保留，但当前不作为上线能力。
- 服务端 AI 网关、提供商级缓存和更复杂的语义缓存，仅在明确立项后实施。

## 6. 功能需求

### FR-01 线程与对话

**目标**：用户可以创建、继续、搜索和管理长期线程。

**要求**

1. 线程必须绑定空间、上下文类型、角色快照、提供商/模型配置和分支路由。
2. 用户消息发送前先本地持久化；生成消息创建后再发起提供商请求。
3. 线程支持收藏、标题、搜索、删除/恢复和最近访问。
4. 同一 space:thread 只允许一个活动生成任务；新任务必须终止或接管旧任务。
5. 路由失焦、应用切后台时停止发布 UI patch，但不得丢失已持久化内容。

**验收**

- 断网或切后台后，已生成内容可在重进线程时恢复。
- 同线程重复点击发送不会创建两个并发生成任务。
- 当前空间的线程绝不读取另一空间的数据库或文件。

### FR-02 角色卡与会话身份

**目标**：角色身份稳定、可复用、可审计。

**要求**

1. 角色卡包含名称、描述、性格、场景、系统提示、首次消息、替代问候、头像、标签、边界模式、默认语言和模型偏好。
2. 支持导入 SillyTavern chara_card_v2/v3 结构，处理 {{char}}、{{user}} 宏。
3. 会话使用角色快照；修改角色卡不回写历史消息，需显式应用到新会话或分支。
4. 角色指令优先级必须高于动态观察、检索材料和用户当前请求中的普通文本。

### FR-03 记忆

**目标**：让长期关系连续，同时降低错误记忆和提示注入风险。

**要求**

1. 支持 global / role / ip / knowledge_base / thread / branch 范围。
2. 支持 confirmed / working / archive 记忆车道，以及 tentative / committed / confirmed / stale / superseded / conflicted / suppressed / deleted 状态。
3. 记录来源消息、抽取器版本、本体版本、投影版本、有效时间、置信度、稳定性和用户锁定状态。
4. safety_pending 记忆不得被非用户动作直接改写；用户确认后才可锁定为安全事实。
5. 自动注入上限为 6 条，检索阈值为 0.55；低置信度必须以保守语气呈现。
6. 记忆只作为背景信息，不得成为新的系统/工具执行指令。

### FR-04 材料、IP 与知识库

**目标**：让本地材料成为可控、可引用的上下文来源。

**要求**

1. 图片/视频导入后复制到应用管理目录，保留原始文件名、内部文件名、尺寸、MIME、文件大小、创建/更新时间等元数据。
2. 预览和缩略图单独生成，禁止压缩、裁剪、重编码、覆盖原始文件。
3. AI 文档走“导入→解析→分块→索引→检索→引用→回答”链路。
4. 检索结果必须携带文档标签、片段文本、定位信息和版本号。
5. 只有用户明确开启材料上下文时，材料内容才进入提示词。
6. 引用使用 [[cite:S1]] 形式，回答结束后可回到原材料定位。

### FR-05 分支、编辑和重新生成

1. 每条消息可存在多个版本，当前分支路由决定实际上下文。
2. 编辑用户消息时，默认从该消息创建新分支，不破坏原分支。
3. 重新生成必须保留旧回答，记录触发消息和生成参数。
4. 采用角色日记/分支时，冻结采用的角色提示、摘要、源消息和关系链。

### FR-06 陪伴运行时

1. 支持情绪、关系投影、梦境和离线想法等低权限陪伴事件。
2. 梦境只有在用户明确允许后才进入对话上下文。
3. 不直接向用户暴露内部数值化情绪；以自然语言、可解释的关系变化呈现。
4. 角色日记任务以北京时间和角色时区规则生成；中断后可恢复。
5. Personal 空间的日记/后台任务需有解锁状态和一次性任务令牌。

### FR-07 流式生成与恢复

1. 状态机：created → local_persisted → request_started → first_byte → reasoning/answer → terminal → final_persisted → ui_stable。
2. 恢复状态机支持 prepared / requesting / streaming / reconciling / recoverable_interrupted / retrying / continuing / completed / failed / stopped。
3. 有部分内容时最多自动续接 1 次；无部分内容时最多重试 1 次；超过上限转为可解释停止。
4. 续接合并使用至少 4 个字符的尾部重叠判定，避免重复拼接。
5. 普通压力下约 500ms 持久化一次，高压力下约 1000ms；切后台、路由离开、停止、完成、错误必须强制 flush。

### FR-08 Personal 空间

1. 普通与 Personal 使用独立数据库、文件目录和导航入口。
2. Personal 解锁支持密码、图案、恢复密钥和设备生物识别；恢复密钥格式为 XXX-XXX。
3. 失败次数触发渐进式反暴力策略；锁定时任务令牌失效、等待任务结束、关闭数据库。
4. 普通空间与 Personal 之间移动需双重风险确认；IP/知识库绑定线程不得直接移动。
5. Personal 图片缓存仅内存存留，退出或锁定后清理。

### FR-09 导入与原始文件安全

1. 导入流程：选择→复制原文件→读取元数据→生成缩略图→写入 SQLite→绑定 IP/组/标签→展示结果。
2. 混合导入门槛：单次 1000 项、图片 256MB、视频 20GB、批次 32GB、未知文件 256MB，并保留至少 512MB 磁盘空间。
3. 最多 4 个并发 worker；导入批次可暂停、失败重试并展示失败原因。
4. Android 11+ 删除原文件必须经过系统确认；应用永不隐式物理删除。

### FR-10 浏览、搜索与回收站

1. 图片使用 48 项 keyset 游标分页，视频使用 61 项锚点与 40 项游标页。
2. 图片使用有界 FlatList；视频只保留当前及前后窗口，最多准备 3 个播放器实例。
3. 支持 IP、组、标签、收藏、最近查看、文件名、备注和来源批次过滤。
4. 删除默认软删除；回收站支持恢复，只有“清空回收站”才物理删除原图和缩略图。

### FR-11 备份与恢复

1. Manifest V2 必须包含 SQLite、原图、缩略图、AI 文档、聊天附件、角色头像和文件校验信息。
2. 路径使用相对路径并做安全校验；恢复使用事务、ID 映射和 FTS 重建。
3. SecureStore 中的 API key 等机密不进入备份包。
4. 恢复失败必须可回滚，并给出可行动的错误信息。

### FR-12 提供商与密钥

1. 支持多提供商配置，模型、聊天模式、生成参数和空间范围进入生成记录。
2. 设备端密钥只能放入 SecureStore；服务端密钥不得下发移动端。
3. 提供商不可用时显示“无法生成/可重试”状态，不伪造完成。
4. 提供商级 prompt cache 必须带模型、版本、空间、分支、记忆 epoch、检索版本和生成参数。

### FR-13 诊断与监测

1. 记录 trace、span、generation、空间和线程哈希等关联字段，不记录提示词、回答正文、文件路径和密钥。
2. 支持标准/深度两种导出级别，默认保留 7 天或最多 20,000 条事件。
3. 监测首个 UI 可见、首字节、空白屏时长、掉帧、内存、数据库锁等待、缓存复用等指标。
4. 诊断异常必须允许用户导出、清理和关闭深度采集。

### FR-14 更新与发布

1. 版本信息、更新 JSON、公告、网站下载页和 Android runtimeVersion 必须一致。
2. 发布前执行类型检查、测试、差异检查，Gradle 发布包必须先 clean 再构建。
3. APK 输出到 output/release/，签名证书保持现有本地证书。
4. 版本文档在 APK 成功生成后归档，失败构建不得移动当前文档。

### FR-15 角色日记与陪伴手帐

1. 角色日记以北京时间和角色为主键，支持手动、自动和后台唤醒。
2. 任务开始时冻结当前采用的分支、角色提示、线程摘要和来源消息；持久唤醒到期后重新解析用户当前采用的分支，再创建不可变生成快照。
3. 优先使用当日完整问答；不足时从历史补齐最近 30 个完整轮次，并为消息附明确北京时间。
4. 模型必须区分“今日证据”和“历史背景”，没有证据时不得虚构。
5. 完成卡片保存来源版本、有效消息哈希并锚定在触发消息之后；刷新、分页和重进不漂移到列表底部。
6. 用户确认纳入上下文的最近日记独立注入，不被较新但未选择的日记覆盖。
7. Personal 日记仅在解锁且任务 token 有效时运行；中断任务回前台后恢复。

### FR-16 陪伴内心运行时

1. 支持情绪投影、关系投影、梦境、离线思绪和内心产物仲裁。
2. 思绪是一次性、低权限动态材料，不得覆盖角色规则或成为工具指令。
3. 梦境只有在用户明确允许后才可进入后续上下文；失败或卡住的梦境支持长按彻底删除。
4. 内部数值化情绪只用于算法，不直接暴露给用户；外显使用自然语言和可解释事件。
5. 后台事件任务必须可取消、可恢复、可诊断，并遵守 Personal 锁定屏障。

### FR-17 外部分享、打开与资源包

1. Android 分享入口可接收图片、视频、文档和资源包，并统一复制到受管目录。
2. ZIP/CBZ 等资源包必须做 zip-slip 路径防护，识别图片并按文件夹映射分组。
3. 外部打开视频、图片或归档时，先确认当前空间和临时文件所有权，再进入对应阅读器。
4. 外部入口与普通导入共享原文件安全、批次记录、重复检测、取消和回滚逻辑。

### FR-18 存储统计与维护

1. 展示原图/视频、缩略图、缓存、备份、回收站和 IP 的空间明细。
2. 预览目录通过一次 inventory 计算总量、图片和视频，备份枚举并发不超过 4 worker。
3. normal/personal 分别维护 epoch + TTL 快照，先显示可用快照再刷新。
4. 临时目录按最多 48 小时清理，每日运行；单条失败隔离，不阻塞其他空间。
5. 清理操作必须区分缓存、临时文件、回收站和原始文件，禁止隐式删除原图/视频。

### FR-19 更新、公告与产品文档

1. 应用可读取远程 update-version.json 和 announcement.json，支持版本比较、一次性公告 ID 和官网下载 fallback。
2. 更新弹窗默认指向官网，GitHub Release 仅作为备用/历史入口。
3. About/产品文档入口支持应用内 Markdown 阅读；官网图片可预取到本地并优先复用缓存。
4. 更新检查失败不得阻塞本地聊天、材料浏览和记忆管理。

### FR-20 设计系统与无障碍基础

1. 页面、按钮、表单、Toast、ActionSheet、空状态、Header 和卡片使用共享设计 tokens。
2. 新页面优先使用 spacing、rhythm、metrics、radius、colors、typography 和 touch target tokens，不在局部复制硬编码。
3. 所有空数据、失败、权限、加载、完成和危险操作都有明确状态；文本长、文件名长和宽屏设备不得遮挡。
4. 动效、毛玻璃、视差和高光必须有性能门禁，后台/不可见时停止循环动画。
5. 关键操作支持 Android 返回、系统手势、读屏可识别标签和足够触控区域。

## 7. 核心数据模型

| 聚合 | 关键字段 | 关系 |
|---|---|---|
| Thread | space、contextType、roleSnapshot、provider、branchRoute | 包含消息、记忆引用、材料引用 |
| Message | threadId、branchId、version、role、content、generationId | 可形成版本树 |
| RoleCard | prompt、firstMessage、avatar、boundaryMode、defaultLanguage | 被线程快照引用 |
| MemoryClaim | scope、lane、status、confidence、sourceMessageId、validTime | 由检索服务选择性注入 |
| Material/IP | documentVersion、chunk、locator、asset metadata | 可被线程授权引用 |
| GenerationJob | generationId、phase、recoveryState、lease | 与本地消息落盘关联 |
| DiagnosticEvent | traceId、category、metric、privacyLevel、timestamp | 不含正文和密钥 |

## 8. 关键业务流程

### 8.1 发送一条消息

1. 校验空间解锁、线程和角色快照。
2. 本地保存用户消息与生成占位消息。
3. 编译稳定策略、角色、材料规则、记忆快照、历史、运行时、检索和当前问题。
4. 按上下文预算裁剪动态块，保留当前问题、摘要桥和记忆快照。
5. 解析提供商并启动生成状态机。
6. 流式 patch 只在页面活跃时发布；所有关键节点持久化。
7. 完成后写入消息版本、摘要、指标并将 UI 标记为稳定。

### 8.2 导入素材

选择文件后先复制原文件，再生成缩略图和元数据，最后在单一事务中写入资产、批次、IP/组/标签关系。任一步失败都保留原文件并允许重试，不把临时 URI 作为长期引用。

### 8.3 Personal 解锁与锁定

解锁成功才打开 Personal 数据库和路由；锁定时撤销任务令牌、停止或等待后台任务、清理内存缓存、关闭数据库。跨空间操作需重新确认风险。

## 14. 详细业务规格

本章用于产品评审和研发拆解。每条需求同时包含用户可见行为、系统动作、不可变约束和失败结果；实现时不得只完成“主流程能走通”。

### 14.1 线程生命周期

| 状态 | 进入条件 | 允许动作 | 离开条件 |
|---|---|---|---|
| draft | 新建线程但尚未发送 | 编辑标题、角色、模型、材料授权 | 首次发送或删除 |
| active | 至少存在一条消息 | 发送、搜索、分支、收藏、导出 | 归档或删除 |
| generating | 存在活动 generationId | 停止、离开、后台、恢复 | terminal 或 stopped |
| recoverable | 生成中断但有本地快照 | 继续、重试、放弃 | completed/failed/stopped |
| archived | 用户主动归档 | 查看、恢复、删除 | active 或 deleted |
| deleted | 软删除 | 恢复、彻底删除 | archived 或物理清理 |

系统必须拒绝非法跃迁，例如 deleted 线程不能直接发消息，Personal 锁定时不能从 generating 进入新的网络请求。

### 14.2 一次生成的输入契约

生成请求的逻辑输入必须至少包括：

~~~json
{
  "space": "normal|personal",
  "threadId": "本地线程标识",
  "branchRoute": "当前分支路由",
  "roleSnapshot": "会话开始时冻结的角色配置",
  "provider": "提供商标识",
  "model": "模型标识",
  "chatMode": "companion|roleplay|knowledge|personal",
  "historyWindow": "完整轮次集合",
  "memoryEpoch": "记忆投影版本",
  "retrievalVersion": "材料检索版本",
  "generationParams": "温度、最大输出、停止词等"
}
~~~

任何一个作用域字段缺失，都不得使用跨空间或跨分支的默认值兜底。请求建立后，角色快照和分支路由不可被同一 generation 中途修改。

### 14.3 角色卡字段优先级

优先级从高到低为：应用安全策略 > 角色边界和核心提示 > 材料授权规则 > 用户确认的记忆背景 > 角色运行时状态 > 历史摘要与对话 > 当前用户请求中的普通文本。该优先级不是模型“建议”，而是提示词组装的结构性约束。

### 14.4 记忆写入门槛

自动记忆抽取不能因为一句孤立文本就直接写入长期确认车道。至少经过以下检查：

1. 识别 speechMode，排除引用、玩笑、假设、角色扮演和不确定表达。
2. 计算来源完整性、时间有效性、置信度和与既有 canonicalClaim 的关系。
3. 判断是否涉及安全、身份、财务、健康或其他高风险主题。
4. 高风险或冲突内容进入 safety_pending / conflicted，等待用户动作。
5. 只有用户确认、或低风险且多次一致的事实，才可进入 confirmed。

### 14.5 材料授权矩阵

| 线程状态 | 普通 IP 材料 | Personal 材料 | 未授权材料 |
|---|---|---|---|
| 未绑定 | 不检索 | 不检索 | 不检索 |
| 已绑定 | 可按范围检索 | 仅同一 Personal 空间 | 不检索 |
| 明确关闭 | 不检索 | 不检索 | 不检索 |
| 恢复中 | 使用冻结版本 | 仅使用冻结版本 | 不检索 |

材料更新后，旧 generation 仍使用生成开始时的 documentVersion；新 generation 才读取最新版本。

### 14.6 导入事务边界

导入一个文件的最小事务由四部分组成：

1. 文件复制结果：原始路径、大小、hash。
2. 派生结果：缩略图/视频封面路径和生成状态。
3. 业务记录：媒体、IP、分组、标签、批次关系。
4. 用户结果：成功、跳过、失败和原因。

复制成功但数据库失败时，文件进入可清理的 staging 清单；数据库成功但缩略图失败时，原文件记录保留并标记 previewPending，禁止把缺少缩略图误报成导入失败。

## 16. 产品决策与取舍

### 为什么本地优先而不是先做云同步？

Pixory 的核心数据包含私密对话、角色关系和原始素材。先本地落盘可以在无网时继续浏览和管理，也能把 Personal 隔离落实到数据库和文件层。代价是需要自行处理迁移、备份、冲突和多设备同步；在服务端能力立项前，不把云同步假设为隐含能力。

### 为什么记忆不全部塞入提示词？

全部塞入会造成 token 浪费、旧事实污染和提示注入面扩大。Pixory 采用范围、状态、置信度和来源治理，再按问题选择性注入，牺牲少量召回复杂度换取可解释和可撤销。

### 为什么生成必须先本地持久化？

网络请求可能超时、被系统杀进程或提供商返回部分内容。先保存用户消息和占位消息，才能在恢复时知道“用户想说什么、模型生成到哪里、当前属于哪条分支”。

### 为什么实验能力隔离？

实验模式可能改变提示词、模型行为和风险边界。与默认模式完全隔离可以让稳定版回归有确定基线，实验失败不会污染普通线程和缓存。

## 17. 核心产品逻辑说明

Pixory 的最小产品单元不是一次问答，而是“空间 + 线程 + 角色快照 + 记忆投影 + 材料授权 + 可恢复生成”。这些要素共同决定当前对话的身份、数据范围、可用证据和故障恢复路径，使用户能够持续维护关系，而不是在每次会话中重复解释背景。

记忆被定义为带来源、范围、置信度和生命周期的数据，而不是绝对正确的事实文本。系统通过确认、冲突、过期、替代、压制和撤销状态显式管理不确定性，目标是使错误能够被发现、修正和追溯。

情绪和关系数值属于陪伴运行时的内部计算变量，不构成用户可验证事实。产品不直接展示这些数值，而是通过自然语言、事件和关系变化呈现结果，避免制造不必要的精确感或诱导用户把算法状态理解为客观心理测量。
