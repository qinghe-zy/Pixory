# Pixory 总用户故事与验收标准

## 1. 使用说明

本文件将功能矩阵转化为可交付、可测试的用户故事。编号稳定，后续版本只新增或标记状态，不复用已废弃编号。验收采用“给定条件—执行动作—预期结果”表达。

## 2. 角色

- **陪伴用户（U1）**：持续与一个或多个角色交流。
- **角色创作者（U2）**：创建、导入、维护角色卡。
- **材料管理员（U3）**：维护 IP、图片、视频、文档和标签。
- **隐私用户（U4）**：使用 Personal 私密空间。
- **技术/运营人员（U5）**：处理版本、备份、诊断和故障。

## 3. 核心故事

### US-001 开始陪伴

作为 U1，我希望选择角色后一键开始对话，以便快速进入状态。

**验收**

- 给定已有角色卡，点击开始后 30 秒内进入可发送界面。
- 首次消息、角色快照、空间和模型配置在本地有记录。
- 失败时显示可重试状态，不生成伪造回答。

### US-002 继续线程

作为 U1，我希望重新打开线程仍能看到上下文，以便关系连续。

**验收**

- 线程按时间和分支路由恢复。
- 最近消息可见，摘要桥和记忆快照参与下一次生成。
- 数据库读取失败时不清空本地历史。

### US-003 角色身份稳定

作为 U2，我希望角色设定在长对话中保持优先级，以便角色不漂移。

**验收**

- 角色描述、性格、边界和语言偏好进入稳定提示层。
- 动态检索内容不得覆盖角色安全边界。
- 角色卡编辑不修改已有线程的角色快照。

### US-004 导入角色卡

作为 U2，我希望导入 SillyTavern chara_card_v2/v3 文件，以便复用已有角色设定。

**验收**

- 解析角色描述、性格、场景、系统提示、示例对话和后置指令。
- {{char}}、{{user}} 宏在会话中按当前名称替换。
- 不支持的字段保留原文或给出明确提示。

### US-005 编辑与重新生成

作为 U1，我希望编辑自己的问题或重新生成回答，以便修正路线。

**验收**

- 编辑从当前消息创建新分支。
- 原分支可回看，旧回答不被覆盖。
- 重新生成记录触发消息、参数和生成时间。

### US-006 流式阅读

作为 U1，我希望回答逐步出现且滚动稳定，以便自然阅读。

**验收**

- 底部锁定时跟随最新内容；用户上滑后不强制跳回底部。
- 切后台或离开路由不再发布 UI patch，但重返后可恢复内容。
- 大文本下帧率策略自动降级，不无限堆积 patch。

### US-007 中断恢复

作为 U1，我希望网络或应用中断后能继续回答，以便不丢失生成结果。

**验收**

- 有部分内容时最多自动续接一次，合并不重复。
- 无内容时最多重试一次。
- 仍失败时保留已生成内容并显示停止原因。

### US-008 搜索线程

作为 U1，我希望按标题或内容定位旧线程，以便找到重要对话。

**验收**

- 搜索结果按当前空间过滤。
- 无结果有标题、解释和清除搜索入口。
- 搜索不会把 Personal 内容暴露到普通空间。

### US-009 管理记忆

作为 U1，我希望查看和修改记忆，以便控制 AI 记住什么。

**验收**

- 可查看记忆范围、来源、状态、置信度和最近更新时间。
- 用户可以确认、锁定、编辑、标记过期、撤销或删除。
- safety_pending 不得被后台自动写成确认事实。

### US-010 记忆保守表达

作为 U1，我希望不确定事实不会被 AI 当成确定事实，以便减少误解。

**验收**

- 高置信确认记忆可直接用于事实陈述。
- 低置信或冲突记忆使用保守措辞或先询问。
- 已删除、压制、替代记忆不会被检索注入。

### US-011 绑定 IP 材料

作为 U3，我希望给线程绑定 IP 或知识库，以便回答参考本地设定。

**验收**

- 绑定范围清晰显示在会话入口。
- 未授权的 IP/知识库不会进入检索。
- 结果带材料名称、片段定位和版本号。

### US-012 引用材料

作为 U1，我希望看到回答依据的材料来源，以便判断可信度。

**验收**

- 回答中出现 [[cite:S1]] 等引用标记。
- 点击引用可定位原文档或素材记录。
- 材料版本更新后，旧引用仍能识别版本差异。

### US-013 导入原始图片/视频

作为 U3，我希望导入后保留原文件，以便后续备份和引用。

**验收**

- 原文件复制到应用管理目录。
- 缩略图是独立文件，不能替代原图。
- 导入失败显示失败项，已成功项不回滚成不可见状态。

### US-014 批量导入边界

作为 U3，我希望大批量导入有预检，以便避免空间耗尽。

**验收**

- 超过 1000 项、图片 256MB、视频 20GB、批次 32GB 等限制时提前提示。
- 预估空间不足 512MB 时阻止或要求清理。
- 并发 worker 不超过 4 个。

### US-015 浏览与筛选

作为 U3，我希望按 IP、分组、标签、收藏和最近查看筛选，以便快速找素材。

**验收**

- 图片列表有界渲染，滚动不无限增长内存。
- 视频只准备当前及相邻窗口，当前视频独占声音。
- 空筛选结果有明确空状态和清除入口。

### US-016 回收站恢复

作为 U3，我希望误删素材可恢复，以便避免误操作损失。

**验收**

- 删除默认写入 deleted 状态，不物理删除。
- 恢复后原 IP/分组/标签关系保留。
- 只有显式清空回收站才删除原图和缩略图。

### US-017 创建 Personal 空间

作为 U4，我希望私密内容与普通内容隔离，以便降低泄露风险。

**验收**

- Personal 使用独立数据库、目录和导航。
- 普通空间搜索、备份和诊断默认不读取 Personal 正文。
- 锁定后任务令牌失效，后台任务不能继续写入。

### US-018 恢复密钥

作为 U4，我希望在忘记密码时使用恢复密钥，以便找回访问能力。

**验收**

- 恢复密钥按 XXX-XXX 展示并支持复制/确认。
- 失败尝试触发反暴力策略。
- 恢复流程不把密钥写入诊断和普通备份。

### US-019 跨空间移动

作为 U4，我希望将素材移出 Personal 前看到风险，以便做出知情决定。

**验收**

- 移动操作至少两次确认。
- IP/知识库绑定线程不可静默移动。
- 移动失败不产生半完成关系。

### US-020 备份完整数据

作为 U5，我希望备份包含聊天和原始材料，以便灾难恢复。

**验收**

- 包含 SQLite、原图、缩略图、AI 文档、聊天附件、角色头像和 Manifest。
- 包含大小与 SHA-256 校验。
- SecureStore 密钥不进入备份。

### US-021 恢复数据

作为 U5，我希望恢复后关系、分支和引用仍然可用，以便继续工作。

**验收**

- 恢复过程使用事务和 ID 映射。
- FTS 索引重建成功。
- 任一关键步骤失败时可回滚并给出报告。

### US-022 诊断生成延迟

作为 U5，我希望看到首字节、首个 UI patch 和持久化耗时，以便定位慢点。

**验收**

- 生成指标包含完整时间点和 provider/model 等维度。
- 不记录提示词、回答正文、文件路径和密钥。
- 可按线程哈希和时间范围导出。

### US-023 发现空白屏

作为 U5，我希望系统识别“有数据但页面空白”，以便快速处理线上问题。

**验收**

- 当可见项/挂载项为 0、内容高度存在或生成 UI 提交延迟超过阈值时触发嫌疑标记。
- 记录窗口、滚动、布局、内存和线程匹配信息。
- 诊断事件可去重并控制保留期。

### US-024 版本可追溯

作为 U5，我希望每个版本有中文 Plan/Spec/Review 和开发记录，以便审计变更。

**验收**

- 版本目录按 当前版本文档 和 历史文档/vX.Y.Z 归档。
- 发布失败不移动当前文档。
- 最终归档记录版本、时间、Commit、Tag 和 APK 信息。

### US-025 角色日记

作为 U1，我希望角色能根据当天完整对话生成日记，以便长期关系有可回看的时间线。

**验收**

- 手动、自动和后台生成使用同一份冻结快照。
- 今日证据与历史背景分开，缺少证据时不虚构。
- 日记卡锚定触发消息之后，刷新和分页不漂移。

### US-026 管理梦境与离线想法

作为 U1，我希望梦境和思绪可控，以便陪伴体验不会偷偷改变对话事实。

**验收**

- 梦境进入上下文前需要明确允许。
- 失败或卡住的梦境可长按删除。
- 思绪不会覆盖角色规则或触发工具操作。

### US-027 外部分享导入

作为 U3，我希望从 Android 分享菜单把图片、视频或资源包导入 Pixory，以便减少中间步骤。

**验收**

- 外部 URI 先复制到受管目录再持久化。
- ZIP/CBZ 做路径穿越防护并保留批次记录。
- 取消或失败不删除非本次创建的临时文件。

### US-028 查看存储并清理

作为 U3，我希望知道空间由什么占用，以便安全清理缓存。

**验收**

- 原图、缩略图、缓存、备份和回收站分别统计。
- 清理缓存不会删除原图或 Personal 数据。
- 统计刷新失败时保留上次快照并提示时间。

### US-029 获取更新和公告

作为 U1，我希望在应用内看到可靠的更新入口，以便及时修复问题。

**验收**

- 更新检查失败不阻断核心功能。
- 公告使用唯一 ID，用户关闭后不重复打扰。
- 下载优先官网，备用入口可追溯到版本发布页。

### US-030 阅读产品文档

作为 U5，我希望从 About 页面阅读产品与隐私说明，以便问题反馈有共同语境。

**验收**

- Markdown 文档在应用内可打开、返回和继续阅读。
- 图片缓存失败时不阻断文字内容。
- 文档版本和当前应用版本可追溯。

### US-031 使用无障碍和响应式界面

作为不同设备和能力的用户，我希望文字、按钮和返回行为稳定，以便在手机、平板和读屏环境中完成任务。

**验收**

- 长文本、长文件名和宽屏不发生遮挡或横向溢出。
- 动效可按 Reduce Motion 或后台状态降级。
- 核心控件有可识别标签和足够触控区域。

## 4. P0 验收清单

- [ ] 普通/Personal 数据隔离可证明。
- [ ] 生成中断可恢复且不重复拼接。
- [ ] 记忆来源、范围和用户撤销可用。
- [ ] 原始素材导入、回收站和备份不损坏文件。
- [ ] 关键监测字段脱敏。
- [ ] 已实现与待验证状态在文档和发布说明中一致。

## 5. 非功能验收

1. Android 真机验证：导入、Personal、流式、后台恢复、备份恢复。
2. 自动化验证：类型检查、单元测试、数据库迁移、提示词预算、检索阈值、状态机。
3. 文档验证：UTF-8、链接有效、旧版文档未改动、版本目录无碰撞。
