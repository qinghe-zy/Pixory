# Pixory 页面视觉减压与优化规则

更新时间：2026-05-03

## 目的

这份文档用于把 Pixory 已完成页面的视觉减压方法固化下来，后续新页面或旧页面重做时直接复用，避免每次从零判断。

适用页面包括但不限于：

- 首页
- IP 详情
- 全部图片
- 标签总览
- 我的
- 回收站
- 后续新增的列表页、详情页、入口页、空状态页

这套规则默认服务于 Pixory 的产品定位：

- Android first
- 本地离线
- 图片资产管理
- calm / premium / practical
- 信息密度高，但不能挤

## 核心目标

页面优化的目标不是“更花”，而是下面 5 件事：

1. 让第一屏更容易读
2. 让图片或核心内容成为主角
3. 让控件和装饰退后
4. 让页面层级更稳定
5. 让 Android 真机截图看起来像真实产品，而不是堆卡片的 AI 草图

## 不要做的事

做页面优化时，默认不要顺手改这些内容，除非需求明确要求：

- 业务逻辑
- SQLite 结构
- 文件系统逻辑
- 导入链路
- 删除链路
- 回收站逻辑
- 路由结构
- 大范围组件重构
- 与页面优化无关的命名整理

页面优化优先做“轻量、局部、可验证”的改动。

## 页面优化总原则

### 1. 先定主角，再定配角

每个页面第一屏必须只有一个主角：

- 首页：IP 列表与封面氛围
- IP 详情：封面与 IP 身份信息
- 全部图片：图片网格
- 标签页：标签层级与结果入口
- 我的页：个人入口与状态信息
- 回收站：待恢复内容与危险操作层级

如果第一屏有两个以上区域都在抢注意力，就继续减压。

### 2. 背景必须后退

Pixory 的背景应该提供气质，不应该抢内容。

规则：

- 页面背景使用暖浅色
- 避免背景块比内容卡更显眼
- 避免大面积强对比色
- 避免用深阴影制造“假层级”

### 3. 重卡片优先拆轻

Pixory 不适合一屏堆很多厚卡片。

优先级：

1. 大重卡片改为轻表面
2. 强阴影改为弱阴影
3. 粗边框改为细边框
4. 整块容器改为列表行或轻分组

### 4. 控件必须变薄

如果搜索框、chip、统计块、快捷操作比图片还重，说明控件太厚。

默认优化方向：

- 降低高度
- 降低填充
- 降低阴影
- 降低对比
- 降低装饰性

### 5. 信息密度可以高，但不能糊成一片

Pixory 允许信息密度高，但必须有呼吸感。

重点依赖：

- 分组间距
- 标题与内容距离
- 主次字号差
- 轻量分隔
- 控件尺寸统一

## 通用视觉减压动作

### 1. 先调 token，再调页面样式

如果多个页面都在出现同类问题，优先改 token，而不是每页单独硬修。

常见优先项：

- `layout.pagePaddingHorizontal`
- `layout.sectionGap`
- `metrics.cardPadding`
- `metrics.chipHeight`
- `metrics.searchHeight`
- `shadows.xs / sm / hero`
- `colors.background.*`
- `colors.border.*`
- `typography` 的标题、caption、meta

### 2. 默认减少这些重量

- Hero 高度
- SearchBar 厚度
- Filter chip 高度与填充
- Card 阴影
- Card 边框对比
- 统计模块的体积
- 列表行高度
- 大标题字号

### 3. 默认增加这些空间

- 页面左右留白
- section gap
- 标题与正文间距
- 内容块之间的垂直节奏
- 底部 Tab 以上的安全距离

### 4. 优先减少文字噪音

常见做法：

- 卡片里只保留最关键 meta
- 把“说明句”缩成一行
- 长日期优先缩成短日期
- 长文件名 / 长 IP 名允许截断，不强行全展示
- 标签、分组名优先让图片先被看见

## 各类页面的复用规则

### A. 首页 / 入口页

目标：不挤、轻、图片主导。

规则：

- Hero 只保留一个，不要太高
- 搜索框使用轻背景，不要做成厚卡
- 顶部筛选使用轻量 chip
- IP 卡片优先保证图片区域占比
- 卡片里的文案只留标题、图片数、更新时间
- 卡片间距稳定，不要局部忽大忽小

验收自查：

- 第一屏是否一眼先看到图片和结构，而不是一堆控件
- Hero 是否退到辅助位
- 搜索与筛选是否明显比图片轻
- 背景是否没有压过卡片内容

### B. 详情页

目标：封面优先、信息次之、操作轻量。

规则：

- 第一屏优先给封面
- 标题要允许长文本安全换行或缩放
- 统计区用轻条带，不用厚卡
- 快捷操作用轻入口，不做大按钮墙
- 分组入口优先用列表行
- 最近图片优先给网格空间

验收自查：

- 是否先看见封面，再看见信息
- 长标题是否挤压下方内容
- 统计是否存在截断
- 快捷操作是否比内容还重

### C. 图片网格页

目标：图片成为绝对主角。

规则：

- 顶部摘要要短
- chip 只做筛选，不做装饰
- 标签、分组筛选尽量轻
- 图片 tile 文本越少越好
- 网格留白要稳定
- 不要让筛选区比网格更显眼

验收自查：

- 第一眼是不是图片网格
- 筛选区是否抢视觉
- 文字是否明显少于图片

### D. 标签页

目标：有层级，不乱铺。

规则：

- 标签不能满屏无差别平铺
- 必须建立“热门 / 全部 / 结果入口”的层级
- 热门标签可以做较强一点，但仍保持轻表面
- 全部标签优先用 pill，而不是一堆等权卡片
- 当前选中标签应有清楚但不厚重的反馈

验收自查：

- 热门标签是否明显高于全部标签
- 标签结果入口是否清楚
- 是否仍然像满屏撒点一样杂乱

### E. 我的页

目标：主卡有质感，但整页不能笨重。

规则：

- 顶部主卡可以略强，但只允许一个主卡
- 统计模块优先变轻
- 菜单入口做成舒展列表
- 本地存储信息要自然并入，不要突然出现一块“工具卡”
- 危险入口与普通入口要分层，但不要靠刺眼红色硬分

验收自查：

- 主卡是否有质感但不压页面
- 菜单列表是否比旧版更舒展
- 存储信息是否像页面的一部分，而不是外来卡片

### F. 回收站

目标：风险清楚，但不刺眼。

规则：

- 顶部说明区轻量即可
- 图片项优先用列表行，不要做重栅格
- 恢复动作保持清楚，但不要压过图片内容
- 清空回收站是危险动作，要单独分层
- 危险色只用于强调，不做大面积底色

验收自查：

- 顶部说明是否太厚
- 恢复按钮是否比内容还抢眼
- 清空回收站是否清楚但不过度刺眼

## 页面优化执行顺序

后续新页面默认按这个顺序优化：

1. 确认页面主任务  
   先回答：用户进这个页面第一件事要看什么？

2. 找视觉压力点  
   重点排查：
   - 大卡片
   - 大阴影
   - 高 chip
   - 大标题
   - 多段 meta
   - 过满第一屏

3. 先改全局 token  
   如果问题是共性的，先收 token。

4. 再改页面局部布局  
   只动：
   - 间距
   - 字号
   - 卡片高度
   - 图片比例
   - chip 厚度
   - 背景颜色
   - 阴影强度
   - 列表项高度
   - 底部 Tab 遮挡
   - 标题与内容距离

5. 真机 / 模拟器截图验收  
   不接受“只看代码感觉差不多”。

## Android 截图验收规则

每次页面视觉优化完成后，默认都要走 Android 截图验收。

标准流程：

1. 停掉旧 Metro
2. 运行：

```bash
pnpm exec expo start --android -c
```

3. 确认模拟器加载的是最新 bundle，不是旧缓存
4. 尽量进入真实 SQLite 数据状态，不只看空状态
5. 对目标页逐页截图
6. 只修截图里真实出现的问题

### 截图验收时必须检查

- 第一屏是否有主次
- 页面是否明显比旧版更松
- 底部 Tab 是否遮挡
- 长标题 / 长标签 / 长日期是否截断得难看
- 图片是否被压缩得过小
- 控件是否比内容更重
- 危险色是否过强
- 空白是否是真留白，而不是内容缺失

### 这些状态不算有效验收

- Expo Go 透明前台
- Expo Go 自更新遮挡
- 旧 bundle 缓存页
- 只有空状态，没有真实数据
- 页面正在 loading，没有进入稳定内容态

## 新页面交付时的输出模板

以后做新页面优化，默认输出至少包含：

1. 本轮优化页面
2. 用了哪些共性规则
3. 做了哪些局部视觉修正
4. Android 截图验收结果
5. 仍存在的问题
6. 下一轮最值得继续优化的页面
