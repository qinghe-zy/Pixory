# Pixory V2 体验升级规划

这一阶段主要解决用户日常使用中的几个痛点：如何更快地存入资源，以及在操作失误或管理大批量素材时，系统如何提供更合理的容错和清理机制。

## 1. 快捷收集与批量操作

### 系统分享面板 (Bottom Sheet UI)
目前从其他 App（如 Twitter、浏览器）存入图片需要全屏拉起 Pixory，强制中断了用户当前的浏览。我们需要支持系统级的分享接入：
*   **交互逻辑**：用户点击分享选择 Pixory 后，只在底部滑出一个半透明卡片。
*   **功能点**：卡片内预览缩略图，默认保存到上次使用的 IP，提供修改 IP/Group 的入口和标签输入框。
*   **体验改进**：点击保存后卡片直接消失，用户停留在原 App。
*   **技术点**：Android 端配置 `intent-filter`，利用 `expo-share-intent` 或原生透明 Activity 实现。

### 滑动连选 (Swipe-to-Select)
批量管理 200+ 图片时，逐个点击非常低效。
*   **改进**：长按进入多选后，手指不抬起直接滑动即可框选。支持手指到边缘时的列表自动滚动。
*   **实现**：基于 `react-native-gesture-handler` 监听滑动坐标，映射到网格索引更新状态。

## 2. 容错与清理机制

### 撤销删除 (Undo Snackbar)
为了提高效率，我们打算取消生硬的“确认删除”弹窗，改为“先执行，后反悔”模式。
*   **逻辑**：删除操作触发后 UI 立即更新（图片消失），同时底部弹出 Snackbar 提示“已移至回收站”，并提供“撤销”按钮。
*   **细节**：Snackbar 停留约 4 秒。因为底层已支持 `deletedAt` 软删除，点击撤销只需重置该字段。

### 回收站管理与自动清理
由于 Pixory 涉及物理文件存储，软删除后的文件若不清理会挤占空间。
*   **入口**：设置或侧边栏新增「回收站」视图。
*   **功能**：显示所有已删除媒体及剩余保留天数。支持一键清空或恢复。
*   **自动处理**：默认保留 30 天。应用启动闲时触发后台任务，彻底删除磁盘上超过 30 天的源文件 and 数据库记录。
