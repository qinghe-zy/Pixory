# Pixory v2 视频与导入规格

本文细化了 v2 版本中视频资产、媒体导入、临时查看及跨空间迁移的具体实现规则。

## 视觉参考

播放器交互原型图：
![Pixory v2 video player visual reference](./assets/v2-video-player-visual-reference.png)

*   **设计要点**：沉浸式播放界面，底部单行控制栏，轻量返回按钮。
*   **注意**：图片不含系统状态栏，实现时以本规格定义的逻辑和安全规则为优先。

## 核心范围

*   **视频支持**：导入、封面生成、详情展示与全屏播放。
*   **临时查看**：支持外部视频分享打开，以及压缩包内图片的直接阅读。
*   **资产迁移**：IP 在普通空间与隐私空间之间的互转。
*   **系统衔接**：与现有的备份、搜索、标签及分组系统打通。

**不涉及**：视频编辑/转码、云同步、远程播放、以及将外部 URI 直接登记为资产。

## 数据模型

资产记录增加对视频的支持。允许复用现有的 `image_assets` 命名，但通过 `mediaType` 区分图片和视频。

*   **新增字段**：`mediaType` (image|video), `durationMs`, `lastPlaybackPositionMs`, `coverThumbnailFileUri` 等。
*   **规则**：
    *   SQLite 只存路径和元数据，不存二进制大文件。
    *   视频的 `thumbnailFileUri` 指向封面；若封面和缩略图分离，需保持备份逻辑兼容。
    *   列表查询默认需支持按类型过滤。

## 导入页面设计

入口语义需保持准确：`选择图片`、`选择视频` 或 `选择资源包`（.zip / .pixorypack）。
*   **文案去噪**：移除如“复制原图，缩略图单独生成”这类内部逻辑说明。
*   **视觉**：`当前 IP` 下方不再显示重复文字，IP 名使用标签或胶囊状徽标突出。分组选项保留简短提示（如：导入到当前 IP）。

## 视频导入逻辑

视频导入需包含：空间检查、流式复制到临时目录、元数据提取（宽高、时长等）、封面生成、以及落库记录。

*   **关键点**：
    *   严禁将视频文件读入 JS 内存（Base64）。
    *   封面生成失败不应阻断整个导入流程，允许后续重试封面生成。
    *   大文件导入需配合进度条显示，并在失败时提供明确的原因和重试入口。

## 进度追踪

适用于视频导入、批量图片导入、资源包解压、备份恢复及跨空间迁移。

*   **显示规范**：能获取字节流进度时显示百分比，否则显示当前阶段（如 `copying`, `generatingPreview`）及已处理数量。
*   **体验限制**：不使用伪造的进度条。任务需在后台执行，不得阻塞用户的浏览和搜索操作。

## 播放器功能

视频播放器通过系统原生组件实现，JS 层仅负责传递 URI 与监听状态，不直接读取二进制流。

*   **交互控制**：
    *   **布局**：支持横竖屏自动切换，控制栏在 3 秒无操作后自动隐藏。
    *   **进度与快进**：支持左右滑动调整进度及长按倍速快进，倍速范围涵盖 0.25x 至 3x。
    *   **辅助功能**：右上角菜单提供保存本地及保存到 IP 入口，右下角提供当前 IP 内的视频切换列表。
*   **资源管理**：页面退出或进入后台时，播放器实例会被强制卸载以释放内存。

## 临时查看器 (外部视频与压缩包)

用于处理非正式资产（文件管理器打开或分享进入）。

*   **视频**：不产生数据库记录，仅通过授权 URI 播放。支持保存到普通模式下的 IP（不建议直接存入隐私空间）。保存过程应尽量无感，成功后留在查看器原位，不跳转首页。
*   **压缩包**：采用按需解压策略。
    *   **Session 管理**：建立临时 session，仅解压当前阅读及前后少量图片。
    *   **安全**：严格防御 zip-slip、超大文件及压缩炸弹。退出阅读后需清理临时 session 缓存。
    *   **保存**：长按图片可将其存入相册或通过正式导入流程存入 Pixory。

## 跨空间迁移 (IP 迁移)

IP 在普通空间与隐私空间之间的移动涉及物理文件的迁移。

*   **流程顺序**：先复制文件并写入目标库，校验无误后再清理源空间。必须保证过程的原子性，防止因中断导致两边数据不可用。
*   **逻辑处理**：
    *   **ID 映射**：标签按名称匹配，目标空间若有同名标签则复用。
    *   **授权**：移入隐私空间需验证密码。
*   **状态反馈**：迁移作为可见任务执行，需反馈迁移进度及最终校验结果。

## 备份、搜索与错误处理

*   **备份**：manifest 需区分资源类型。大容量场景优先考虑目录备份或分卷，避免强依赖单一巨型压缩包。
*   **搜索与过滤**：视频应带有时长标识。支持按类型快速筛选，但视频条目不参与图片的专属滤镜（如全景图筛选）。
*   **异常捕获**：系统需明确处理磁盘不足、权限失效、编码不支持及封面生成失败等情况，并提供可理解的错误说明和重试入口。
