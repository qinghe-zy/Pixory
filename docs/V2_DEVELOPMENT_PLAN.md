# Pixory v2 Development Plan

本文件是 v2 阶段的干净规划入口。旧版页面升级、旧版验收、旧版发布记录和一次性开发过程不再放入这里。

## v2 目标

- 接入视频导入、视频封面、视频详情和视频查看。
- 视频播放器必须支持横屏、竖屏、流畅拖拽、长按快进和同 IP 视频待播放列表。
- 支持压缩包图片临时阅读，不入库、不污染正式资产库，看完释放临时资源。
- 支持外部视频临时查看，右上角三点菜单可保存本地或保存到普通模式 IP，保存后回到原查看位置。
- 保持 Pixory 的 Android-first、local-only、offline-first 定位。
- 面向几万资产、几百 GB 本地文件规模提前治理性能和数据安全。
- 保持图片能力稳定，不因为视频模块改坏现有图片导入、查看、备份、回收站和隐私空间。
- 视频上传、压缩包上传、图片批量上传必须有明确进度反馈，不能让用户误以为应用卡死。
- 重复素材检测作为后续增强，不混入 v2.0.4 发布；详细分档计划见 `docs/DUPLICATE_DETECTION_ROADMAP.md`。

## 必守边界

- 原图、原视频永远只复制保存，不压缩、不转码、不裁剪、不覆盖。
- 缩略图、视频封面、缓存和预览文件都是可重建派生资源。
- SQLite 只保存结构化元数据，不保存大二进制文件。
- 列表页只读取元数据和预览资源，不读取原图或原视频。
- 删除默认软删除，物理删除只发生在用户明确清空回收站之后。
- 隐私空间继续和普通空间隔离。

## 视频模块拆分

1. 数据模型
   - 为资产记录补充 `mediaType`。
   - 视频资产需要记录 duration、width、height、mimeType、fileSize、originalFileUri、coverThumbnailFileUri。
   - 保持现有图片字段兼容，避免一次性大重构。

2. 导入流程
   - 选择视频后先复制原视频到应用私有目录。
   - 复制完成后读取元数据并生成单张封面。
   - 入库前后校验文件存在、文件大小和记录一致性。
   - 大视频导入必须有进度、失败记录和可重试路径。
   - 视频上传、压缩包上传、图片批量上传必须统一走任务化进度模型。
   - 如果底层 API 无法提供字节级进度，必须显示真实阶段进度，例如准备中、复制中、校验中、生成预览中、写入数据库中、完成。

3. 列表和详情
   - 网格显示视频封面、播放标识和时长。
   - 详情页显示视频尺寸、时长、文件大小、文件名、备注、标签、分组、收藏状态。
   - 图片查看器和视频查看器按 `mediaType` 分支，不互相污染交互。

4. 播放器
   - 支持竖屏播放和横屏播放，横竖屏切换不能丢失当前播放进度。
   - 支持播放速度选择：0.25x、0.5x、0.75x、1x、2x、3x。
   - 8x、16x 作为高级可选能力；只有在真实设备验证稳定后开放，不稳定时必须隐藏或降级。
   - 支持长按快进，长按快进倍数必须可设置。
   - 长按视频只用于播放控制，不作为保存入口，避免与长按倍速冲突。
   - 支持左右滑动拖拽进度，不要求用户必须点到细进度条。
   - 拖拽时必须实时显示当前时间和当前帧预览，松手后跳转播放。
   - 右上角提供轻量三点菜单，包含“保存本地”和“保存到 IP”等非播放动作。
   - 右下角提供待播放入口，点击后显示当前 IP 下的其他视频。
   - 待播放列表支持一键切换视频，切换时保留当前 IP 上下文。
   - 同一时间只允许一个视频播放器实例活跃，离开页面必须暂停并释放播放资源。

5. 备份和恢复
   - 备份 manifest 必须区分 image / video。
   - 备份必须包含原视频，不能只保存封面。
   - 恢复时先校验 manifest，再分批恢复数据库和文件。

6. 压缩包临时阅读器
   - 支持从系统文件管理器或分享入口用 Pixory 临时打开图片压缩包。
   - 临时阅读不写正式资产记录，不进入 IP、分组、标签、收藏、最近查看、回收站和备份。
   - 只按需解压当前图片和前后少量图片，不一次性全解压。
   - 退出阅读 session 后清理临时文件；异常退出后下次启动按 TTL 清理残留。
   - 长按图片提供“保存到相册”和“保存到某个 IP”。
   - “保存到某个 IP”必须走正式图片导入逻辑：复制到 originals、生成缩略图、写 SQLite、校验文件。
   - 保存到 IP 后不强制切换到主页面，不打断当前临时阅读体验。
   - 保存到 IP 的结果进入待处理/导入结果状态，用户下次进入应用时可以继续处理分组、标签和备注。
   - 临时文件不能直接作为正式 original 路径使用。

7. 外部视频临时查看器
   - 支持从系统文件管理器或分享入口用 Pixory 临时打开外部视频。
   - 外部视频临时查看不写正式资产记录，不进入 IP、分组、标签、收藏、最近查看、回收站和备份。
   - 右上角三点菜单提供“保存本地”和“保存到 IP”。
   - 长按视频只触发播放器长按快进，不触发保存动作。
   - 保存目标只能看到普通模式 IP，不显示隐私空间 IP。
   - 保存到已有 IP：进入选择 IP 界面，用户选择后走正式视频导入逻辑。
   - 保存到新建 IP：进入新建 IP 界面，新建完成后走正式视频导入逻辑。
   - 正式视频导入必须复制原视频到 originals、生成视频封面、写 SQLite、校验文件。
   - 保存完成或新建完成后必须立即回到原来的外部视频查看位置，只显示保存完成反馈。
   - 不引导用户进入应用主页，不自动跳转到 IP 详情，不打断临时查看体验。
   - 临时外部 URI 不能直接登记为正式 original 路径。

8. 导入页 UI 收口
   - 导入页禁止重复解释同一信息，能由选项本身表达的说明要删除。
   - “复制原图，缩略图单独生成。”这类实现细节型解释文案删除。
   - “.zip / .pixorypack 会先解压到 Pixory 私有临时目录，再导入原图。”这类流程解释文案删除。
   - “选择资源包”可以保留“支持 .zip / .pixorypack”，后面的文件夹映射、解压说明等长解释删除。
   - 新增“选择视频”“选择素材”等入口时，不写实现细节型说明，只保留用户决策需要的信息。
   - “当前 IP”下面不再单独显示“未选择分组时导入到当前 IP”这类重复说明。
   - IP 名不另起一行，放在“当前 IP”右侧。
   - IP 名需要特殊视觉标识，例如胶囊、标签、徽标或轻量描边，避免普通名称被误认为说明文字。
   - 目标归属里的分组说明只保留在具体选项下，例如“暂不分组 / 导入到当前 IP”。

9. IP 隐私空间迁移
   - 首页 IP 长按弹窗加入“移入隐私空间”和“移出隐私空间”。
   - 普通空间 IP 才显示“移入隐私空间”；隐私空间 IP 才显示“移出隐私空间”。
   - 移入隐私空间前必须完成隐私密码校验；如果尚未设置隐私密码，则先引导设置密码。
   - 不要求每次移入都修改密码；只有用户主动改密码时才进入修改密码流程。
   - 从当前数据库结构看，普通空间和隐私空间是两套 SQLite 数据库和两套文件目录，迁移不能只改一个字段。
   - 迁移必须作为任务执行：复制 IP、分组、图片/视频资产、标签关系、封面、import batch 记录和原始文件/缩略图/视频封面。
   - 跨空间迁移不能复用源空间的数据库 ID，必须建立 ID 映射：normalIpId -> personalIpId、normalGroupId -> personalGroupId、normalImageId -> personalImageId、tagName -> targetTagId。
   - 标签按名称复用：目标空间已有同名标签时复用目标空间 tagId；没有同名标签时创建新标签。
   - 标签迁移以规范化后的标签名为准，不把普通库 tagId 写入隐私库。
   - 分组属于 IP 内部结构，迁移时随 IP 复制并建立 groupId 映射，不按全局名称合并。
   - 迁移完成前不能删除源空间数据；必须先复制文件、写入目标数据库、校验数量和文件大小，再软删除或清理源空间。
   - 迁移失败时优先保护源空间原始文件和源数据库记录，不能出现两边都不可用。
   - 移出隐私空间同样必须在隐私空间已解锁状态下执行。

## 性能要求

- 所有资产列表必须分页或游标加载。
- 常用查询必须有 SQLite 索引。
- 搜索优先使用 FTS 或等效索引方案，而不是全表模糊扫描。
- 启动阶段不做全库文件扫描和全量统计。
- 大任务分批执行，避免一次性把文件列表、资产记录或备份内容放进内存。
- 大文件上传、压缩包导入和图片批量导入必须显示进度、当前阶段、已处理数量和失败数量。
- 压缩包临时阅读必须限制预加载窗口和临时缓存大小，不能把整包内容读入内存。
- IP 隐私空间迁移必须显示进度，至少包含复制文件、写入数据库、校验、完成或失败阶段。
- 视频列表只加载封面，不自动加载原视频。
- 视频播放必须走本地文件 URI，不允许把视频读入 JS 内存或转成 base64。
- 外部视频临时查看也必须走原生播放器 URI，不允许把视频读入 JS 内存或转成 base64。
- 视频列表、搜索页、标签页和分组页不能挂载播放器，只显示封面和元数据。
- 拖拽进度要节流更新 UI 和 seek 请求，避免每个手势事件都触发重 seek。
- 当前帧预览优先使用播放器原生能力；如果原生能力不足，使用低频 seek 或预生成关键帧，不能牺牲主播放流畅度。
- 3x 播放必须验证真实设备稳定性；更高倍速如 8x、16x 不支持时不展示或降级为连续 seek 快进，不让播放管线卡死。

## 数据安全要求

- 导入顺序：复制原文件 -> 校验文件 -> 写数据库 -> 生成预览 -> 更新记录。
- 任何失败都要能留下可诊断状态，不能静默丢失原文件。
- 数据库记录和文件系统状态不一致时，优先保护原文件。
- 清理缓存只能清理可重建文件，不能触碰 originals。
- 备份和恢复要记录成功、失败、跳过和校验结果。
- 压缩包临时阅读必须防 zip slip、假扩展名、超大文件、超多条目和解压炸弹。
- 从临时阅读器保存到 IP 时，必须重新走导入校验，不能把临时缓存文件登记为正式原图。
- 从外部视频临时查看器保存到 IP 时，必须重新走正式视频导入校验，不能把外部 URI 登记为正式原视频。
- 外部临时查看只能保存到普通模式 IP，不能写入隐私空间。
- IP 跨空间迁移必须先校验目标空间写入结果，再处理源空间；严禁先删除源数据。

## 大任务进度要求

- 所有视频上传、压缩包上传、图片批量上传、备份、恢复和批量清理都必须有可见任务状态。
- 进度文案必须表达真实阶段，不使用假百分比。
- 能获得文件大小和已复制字节时显示百分比；不能获得字节进度时显示阶段进度和已处理数量。
- 任务至少包含：准备中、复制中、校验中、生成预览中、写入数据库中、完成、失败。
- 失败时显示失败原因、已成功数量、失败数量和可重试入口。
- 用户离开页面后任务状态不能丢失；回到页面时要能看到当前状态或结果。
- 大任务不能阻塞普通浏览、搜索和查看已有资产。

## v2 完整交付要求

- v2 不是分阶段目标；完成标准是本计划、spec 和验收标准中的功能全部落地并通过验收。
- 必须完成视频导入、封面生成、视频详情、视频播放器、外部视频临时查看、压缩包临时阅读、大任务进度、导入页 UI 收口、备份恢复、搜索列表衔接和 IP 跨空间迁移。
- 必须补齐数据库 schema、repository、导入服务、查看器、备份服务、隐私空间迁移服务和 Android 文件/播放器能力。
- 必须补齐视频模块所需索引、分页、FTS 或等效搜索能力。
- 必须按真实 Android 设备验证：本地大文件播放、横竖屏切换、滑动拖拽、长按快进、0.25x 到 3x 倍速选择、待播放切换。
- 必须按真实 Android 设备验证：视频导入、图片批量导入、资源包导入、压缩包临时阅读和外部视频保存到 IP。
- 必须按真实 Android 设备验证：普通空间 IP 移入隐私空间、隐私空间 IP 移出普通空间、标签复用和失败保护。
