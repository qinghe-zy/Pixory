# Pixory Duplicate Detection Roadmap

本文档记录重复素材检测的后续计划。当前 v2.0.4 不实现该功能，只保留规划，避免把未完成的数据库迁移、原生计算和批量删除能力带入发布包。

## 当前状态

- 导入批次复核页已有“疑似重复”能力。
- 现有判断主要基于图片宽高和文件大小，速度快、风险低。
- 该方案适合作为导入后的轻量提示，但不能等同于真正的重复检测。
- 对同一内容但文件大小不同、重新保存过、截图裁切过、尺寸变化过的素材，现有方案可能漏检。
- 对尺寸和文件大小相同但内容不同的素材，现有方案可能误报。

## 第三档目标

第三档目标是做成可实际用于素材库治理的重复检测，而不是只在导入批次里提示“疑似重复”。

范围包括：

- 精确重复：基于原文件内容哈希识别完全相同文件。
- 视觉相似：基于图片感知哈希识别近似图片。
- 全库扫描：不仅支持当前导入批次，也支持已有素材库。
- 分组复核：把重复组按可信度、IP、分组、尺寸、文件大小展示。
- 安全处理：默认只软删除，物理删除仍只允许在回收站清空时发生。
- 可恢复：所有批量处理必须进入回收站，支持撤销或恢复。

## 推荐实现路径

### 1. 精确重复基础层

- 数据库为 `image_assets` 增加 `contentHash` 字段和索引。
- 导入时对复制后的原始文件计算 SHA-256。
- 只对已经复制到 Pixory 私有目录的文件计算哈希。
- 不读取大文件到 JS 内存，优先在 Android 原生层流式计算。
- 对历史素材提供后台补算任务。

验收标准：

- 完全相同文件能稳定归为同一组。
- 文件名不同但内容相同也能识别。
- 哈希为空的旧记录不会造成误报。
- 导入失败不会留下错误哈希。

### 2. 视觉相似层

- 数据库增加 `visualHash` 字段和索引。
- 图片导入时计算 dHash 或 pHash。
- 相似判断使用汉明距离阈值，而不是只看宽高和文件大小。
- 仅对图片做视觉相似检测，视频先只做精确重复。
- 阈值先保守，避免自动误删。

验收标准：

- 同一图片轻微压缩、重命名、重新保存后能进入相似组。
- 明显不同的图片不能频繁被归为一组。
- 相似组必须标注“需要人工复核”。
- 视觉相似不触发物理删除。

### 3. 复核和处理体验

- 重复检测页分为“精确重复”和“视觉相似”。
- 每组展示缩略图、文件名、尺寸、大小、IP、分组、导入时间。
- 精确重复支持“保留一张，软删除其余”。
- 视觉相似默认只提供逐张选择，不提供一键全删。
- 批量处理前必须二次确认。
- 处理后刷新列表，并提供进入回收站的路径。

验收标准：

- 用户能明确知道保留哪张、删除哪几张。
- 批量操作只修改删除状态，不删除 original 文件。
- 回收站可恢复被处理的素材。
- 不同 IP 下的重复素材默认不自动合并归属。

### 4. 全库后台任务

- 提供“扫描重复素材”入口。
- 任务显示阶段、已处理数量、重复组数量和失败数量。
- 扫描任务可中断，下次继续补算缺失哈希。
- 几万条记录下不能阻塞浏览、搜索和查看。

验收标准：

- 扫描过程中列表仍可正常浏览。
- 任务失败有可诊断原因。
- 重启应用后不会丢失已计算结果。
- 不在启动阶段自动全库扫描。

## 风险和边界

- 不做云端比对，不上传图片。
- 不做 AI 生成或 AI 语义识别。
- 不自动物理删除原图。
- 不在 JS 里一次性读取大文件。
- 不把缩略图哈希当作原图精确哈希。
- 视觉相似只能辅助整理，不能替代用户确认。
