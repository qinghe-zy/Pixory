# 素材导入顺序、原文件删除与批量整理设计

日期：2026-08-01
范围：Android 相册/文件/压缩包导入、导入批次整理、隐私空间入口性能、跨 IP 批量移动

## 目标

1. 相册导入完成后，用户确认删除原文件时必须调用 Android 系统的删除确认弹窗；用户拒绝或系统不支持时保留原文件并回退到现有删除 API。
2. 相册素材按来源创建时间正序保存来源序号，导入批次默认按该序号展示，不受批量复制完成时间影响。无法读取来源元数据的项目稳定地排在可识别项目之后，并保留选择顺序。
3. ZIP/PIXORYPACK 解包后的图片和视频严格按压缩包非目录条目的出现顺序写入 `sourceOrder`；若平台没有原生 ZIP 索引器，使用解包扫描顺序作为兼容回退。
4. 隐私空间首次解锁后，首页、整理、全部素材、分组素材和批量管理的数据加载延后到页面交互完成，避免进入隐私模式时多个重查询同时抢占 UI/SQLite。
5. “全部素材”和“分组素材”的批量“移动到 IP”同时支持图片和视频，复制原文件/缩略图/封面、迁移分组与标签后软删除源记录。

## 数据与排序

- `image_assets.sourceOrder INTEGER` 记录单次导入来源顺序；V56 创建列和 `(importBatchId, sourceOrder, id)` 索引。
- 导入批次默认 `sourceOrder ASC`，可切换“来源顺序/来源逆序”；普通素材列表继续使用原有时间排序。
- 迁移、备份恢复和编辑记录保留 `sourceOrder`；没有来源序号的历史记录按创建时间和 id 稳定兜底。

## Android 删除确认

- 原生模块接收 MediaStore asset id，解析为 `MediaStore.Files` content URI，并通过 `MediaStore.createDeleteRequest` 发起系统确认。
- 用户确认后 Promise 返回 `true`；取消、权限不足、API 低于 30、无前台 Activity 或桥接不可用时由 JS 回退到 `MediaLibrary.deleteAssetsAsync`，不阻断素材已复制到 Pixory 的结果。

## 性能约束

- 相册创建时间元数据按 32 项分批读取，未知元数据不阻塞导入。
- 页面首屏使用轻量初始数据，交互动画完成后再执行数据库加载；已有取消/卸载保护保持不变。
- ZIP 顺序索引只读取条目元数据，不解压第二份文件；解包仍复用现有安全路径和文件数量限制。

## 验收标准

- Android 11+ 选择相册素材并开启“导入后删除原文件”时出现系统删除确认；确认后原文件消失，拒绝后原文件仍在。
- 同一批次导入至少 3 个不同拍摄时间素材，正序/逆序切换结果与相册创建时间一致；批量复制耗时差异不改变顺序。
- ZIP 内以非字典序排列图片，导入批次顺序与 ZIP 条目顺序完全一致。
- 隐私空间首次进入首页/整理不出现重复初始化或明显闪退；加载在交互后开始。
- 选择混合图片和视频后，“移动到 IP”可用，目标 IP 中原文件、预览、分组、标签完整，源记录进入回收站。
