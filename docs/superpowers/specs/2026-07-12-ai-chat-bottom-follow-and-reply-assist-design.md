# AI 聊天底部流式恢复与帮答重试设计

## 目标

修复流式生成中从历史位置滑回最低处后，普通聊天的实时打字机光标和自动跟随没有恢复的问题，同时保持历史阅读期间的坐标稳定。改进 AI 帮答，使格式或长度不合格的响应自动纠错重试，并将长句模式放宽到 20–200 字。

## 底部流式恢复

- `nearBottom` 只用于预热 tail replay，不得切换 renderer。
- 只有原生列表 offset 不大于安全底部阈值、拖动结束、惯性滚动结束且滚动已稳定时，才请求退出 replay read mode。
- 退出顺序固定为：确认开放 tail 块已提升和测量、清偿高度债、合并 buffered patch、保留当前底部锚点、下一帧恢复普通 streaming renderer。
- 普通 renderer 恢复后重新显示内联打字机光标，并沿用现有 `followLatestMessage` 自动跟随新增行。
- 仍在拖动、仍有惯性、offset 只是接近底部、tail 未测量或高度债未清零时，不允许切换，避免整树替换和坐标抖动。
- 点击“回到最新”继续走同一安全恢复路径，但可主动滚动到 offset 0。

## AI 帮答纠错重试

- 每次帮答最多请求三次：首次请求加最多两次自动纠错重试。
- JSON 解析失败、候选数量错误、候选重复或长度不合格时，不向 UI 返回空页或原始校验错误。
- 第 2、3 次请求在动态 user prompt 中附加上一轮失败类型和明确纠错要求，不修改稳定 system prefix。
- provider 网络错误、取消信号或明确的上游错误仍立即失败，不把网络故障伪装成格式重试。
- 三次格式纠错均失败后，统一返回可操作错误“帮答生成失败，请重试。”，不把“输出不符合要求”展示成候选内容。

## 长句模式

- 长句模式固定返回一条候选。
- 合法长度为 20–200 个 Unicode 字符。
- 取消至少三句话的限制，由模型自行决定句数、停顿和节奏。
- 候选仍必须延续当前会话、像用户下一条消息且可直接发送。
- 短句模式保持三条候选和当前长度策略不变。

## 测试与验收

- 自动测试覆盖：接近底部不恢复、拖动中不恢复、offset 0 且稳定后恢复、恢复后启用普通 streaming renderer 和光标、未清高度债时不恢复。
- 自动测试覆盖：帮答第三次成功、三次均失败、纠错 prompt 包含失败原因、长句 20/200 字通过、19/201 字失败、单句长句通过。
- Android 验收使用长 reasoning 回复：上滑两个屏幕、缓慢滑到底、停手后观察光标与自动滚动恢复；整个切换过程不得抖动、跳位、重复或缺字。
- Android 验收同时检查点击“回到最新”、快速 fling 后到底、后台前台后到底，以及 AI 帮答长句和不合格自动重试。

## 非目标

- 不改变 inverted FlatList 架构。
- 不在 nearBottom 阶段提前切换 renderer。
- 不改变 provider、SQLite schema、消息持久化格式或短句帮答数量。
- 不无限重试，不把格式错误重试扩展到网络故障重试。
