# 陪伴产物时间线、日记、梦境与 Android 启动图修复设计

日期：2026-08-08

状态：已确认，待实现计划

## 1. 目标

本次设计同时解决四类问题：

1. 日记与梦境卡片在聊天历史中位置漂移，进入页面、刷新或阅读返回后位置不一致。
2. 角色日记的每日自动任务依赖进入具体聊天页，错过后台唤醒后缺少应用级补偿。
3. 梦境失败后重试没有可见反馈、部分失败无法通过原任务恢复，以及失败任务造成频繁制作的观感。
4. Android 12+ 启动图前景裁剪严重，原图方形蓝底与系统背景存在明显色差边界。

实现必须是可测试、可恢复的正式数据流，不以调整时间戳、强制滚动或页面刷新等表面补丁掩盖问题。

## 2. 已确认的产品规则

### 2.1 卡片位置

- 日记、已完成梦境和梦境任务卡都是陪伴产物，不写入 `ai_messages`。
- 每张卡片必须绑定一条真实来源消息，并固定显示在该消息之后。
- 卡片位置不再由 `createdAt`、`updatedAt`、`displayAt` 或页面进入时间决定。
- 分页尚未加载锚点消息时，卡片暂不显示；加载到锚点后再出现。
- 同一锚点存在多张卡片时，按任务创建时间和稳定 ID 排序。
- 旧记录缺少来源 ID 时，可回退到产物创建时间之前最近的可见消息；仍找不到时只在“内心独白”页面展示，不悬浮到聊天末尾。

### 2.2 日记来源与兜底

- 手动和自动日记使用同一套来源构建规则。
- 只读取同一线程、当前采用分支、状态为 `completed` 的用户与助手消息。
- “一轮”指一组完整的用户消息与助手回复。
- 先选取日记归属日的完整轮次；不足 30 轮时，从更早历史向前补足，总上限为 30 轮。
- 当模型上下文预算不足时，先删除最旧的历史兜底，不先删除当天消息。
- 每条消息使用北京时间 `YYYY-MM-DD HH:mm` 标记。
- Prompt 必须分开标记“今日互动”和“过往关系背景”。过往背景只能用于保持人物、关系和语境，不得描述成今天发生的事件。
- 当天没有完整互动时，明确告诉模型不得编造“今天用户说过或做过什么”。
- 来源在任务创建时冻结，后台执行不得因后续聊天而改变正文来源或卡片锚点。

### 2.3 日记每日协调

- 普通空间在应用初始化和回到前台时补偿到期任务，并为启用日记的每个角色选择最近活跃线程安排下一次 Android 唤醒。
- 自动日记不再要求用户先进入具体聊天页。
- 隐私空间仅在成功解锁后协调；锁定期间不得打开 Personal 数据库或调用远程模型。
- Android alarm、前台补偿和持久任务共同保证可恢复性。
- 应用被 Android 强制停止时不能承诺后台准点运行；下次手动启动时进行补偿。
- 每个角色、北京时间日期只完成一次自动日记。手动版本不阻止当天夜间自动版本。

### 2.4 梦境来源与频率

- 自动梦境维持每天最多两次成功梦境。
- 自动梦境成功后至少间隔 50 个完整问答轮。
- 失败不消耗每日成功配额，也不占用 50 轮成功冷却。
- 手动梦境不占自动配额。
- 梦境使用当前线程、当前分支最近最多 20 个完整问答轮。
- 当前触发轮和梦境场景证据单独标记；较早轮次标记为人物与关系背景。
- 每条消息带北京时间。较早背景不得被描述为当前正在发生的事实。
- 模型预算不足时优先删除最旧背景，保留触发场景。

## 3. 架构

### 3.1 `companionConversationSnapshotService`

新增共享来源快照服务，负责：

- 从当前分支读取并配对完整问答轮；
- 按日记日区分当天轮次与更早背景；
- 按调用方配置选择 30 轮日记来源或 20 轮梦境来源；
- 生成北京时间标签；
- 返回稳定的消息 ID、消息版本哈希、快照哈希和 `anchorMessageId`；
- 在任务创建阶段冻结快照。

日记和梦境共享“轮次、分支、时间戳、锚点”的基础语义，但各自保留独立 Prompt 和预算策略。

### 3.2 `companionArtifactTimelineService`

新增纯时间线组装器，输入为可见消息与陪伴产物视图模型，输出稳定的聊天列表项：

1. 建立可见消息 ID 到索引的映射。
2. 将产物归组到 `anchorMessageId`。
3. 顺序输出消息，并在消息之后输出锚定产物。
4. 未加载锚点的产物不进入当前列表。
5. 旧数据只使用受控回退规则。

该服务不得读数据库或依赖 React 状态，以便直接覆盖排序、分页和分支测试。

### 3.3 `diaryRuntimeCoordinator`

新增应用级日记运行时协调器，负责：

- 应用初始化与前台恢复补偿；
- 普通空间所有启用角色的下一次 wake job；
- 每个角色选择最近活跃、仍有效的来源线程及当前分支；
- 复用已有幂等 job、Android alarm 与任务恢复能力；
- Personal 解锁/锁定生命周期；
- 防止页面级 timer 与应用级 coordinator 重复生成。

`AiChatScreen` 只负责展示日记状态、手动触发和读取完成产物，不再拥有每日自动运行的唯一责任。

### 3.4 梦境任务状态与重试

梦境 worker 继续使用持久 job、lease、来源版本校验和自动重试，但对 UI 暴露明确状态结果：

- `provider_failed`：模型服务调用失败，可重试原任务。
- `invalid_classification`：分类输出无法验证，可重试原任务。
- `invalid_generation`：生成输出无法验证，可重试原任务。
- `model_unavailable`：等待有效模型配置，不显示成无期限普通“生成中”。
- `source_changed`：旧快照已失效，不重复执行必败任务。

普通临时失败点击重试时原任务立即变为 `pending`，聊天页同步刷新为制作中。`source_changed` 的操作文案改为“按当前对话重新生成”，基于当前分支创建新的用户主动恢复任务，不伪装成旧快照重试。

运行时事件的 `generating`、`completed`、`failed`、`cancelled` 都必须触发当前线程的梦境与 job 重载。

### 3.5 梦境结构化输出兼容

模型返回仍必须通过字段、长度、安全内容和来源 ID 验证，但解析器可以提取：

- 纯 JSON 对象；
- Markdown JSON 代码围栏中的对象；
- 对象前后存在少量模型说明时的首个完整 JSON 对象。

不得因为兼容外围格式而放宽未知字段、正文上限或安全检查。

## 4. Android 12+ 启动图

启动屏继续使用系统纯色背景 `#4a7bf7`。前景资源采用透明背景，以中央聊天气泡为主体并保留少量原画外围装饰：

- 移除原图方形蓝底，以及不适合 Android 12 安全区的大型外围装饰；
- 保留环绕气泡的轨道线、少量粉色星形/白色闪点，并可保留一个缩小的爱心气泡作为次要装饰；
- 不保留容易被系统掩膜切成残片的图片、视频和摄像机大图标；
- 所有外围装饰必须完整位于 Android 12 安全区内，不能贴近前景画布边缘；
- 主体位于 Android 12 图标安全区中央；
- 四周保留足够透明边距；
- 不使用生成式重画改变品牌图标形状；
- 维护一份标准前景源资产；
- 通过可复现脚本生成 mdpi、hdpi、xhdpi、xxhdpi、xxxhdpi 对应资源；
- 禁止把同一像素尺寸的 PNG 复制到全部 density 目录。

预览资产在用户验收后才能接入 `app.json` 和 Android 原生资源。

## 5. 数据流

### 5.1 日记

触发判定 → 快照服务冻结 30 轮来源与锚点 → 持久 diary job → 后台生成 → 保存版本及来源 ID → 时间线服务在锚点消息后展示卡片。

### 5.2 梦境

当前问答完成 → 本地候选与场景幂等 → 快照服务冻结 20 轮来源与锚点 → 分类 → 配额检查 → 生成 → 来源复核 → 保存梦境 → 原锚点 job 卡替换为梦境卡。

## 6. 边界与非目标

- 不把日记或梦境写入普通消息表。
- 不跨线程、跨分支或跨物理空间补来源。
- 不把历史兜底伪装为当天事件。
- 不因失败而改变已确认的梦境每日两次成功配额和 50 轮成功冷却。
- 不保证 Android 强制停止后的准点后台执行。
- 本次不重做日记或梦境阅读页视觉设计。

## 7. 验证

### 7.1 单元与集成测试

- 轮次配对、当前分支过滤、30/20 轮上限、北京时间格式。
- 日记当天优先、历史补足、无当天消息和预算裁剪。
- 梦境触发证据优先、背景补足、输出格式兼容和严格验证。
- 卡片锚点、分页未加载、旧数据回退、同锚点稳定排序。
- 应用初始化/前台恢复、每角色 wake job、Personal 解锁与锁定。
- 梦境各错误码、临时重试、`source_changed` 重新生成和运行时状态刷新。
- 每天最多两次成功、50 轮成功冷却、失败不占配额与冷却。

- `pnpm typecheck`
- `pnpm test`
- `git diff --check`
- Android 资源尺寸、透明角和主体安全区测试
- Android 构建资源检查
