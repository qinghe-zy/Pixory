# 聊天卡片版本、内心独白批量删除与空聊天历史修复设计

## 状态

- 日期：2026-08-11
- 状态：设计已批准，待用户复核书面规格
- 平台优先级：Android / Expo React Native

## 背景

聊天页会把角色日记和梦境作为外显卡片插入来源消息附近，但卡片目前没有与聊天气泡一致的长按菜单，也没有完整的版本切换能力。日记已经存在版本表，梦境仍是一条生成结果对应一条独立记录。内心独白只展示日记当前版本，删除交互也在日记、独白、梦境之间不一致。

历史列表还存在一项回归：为了消除 Android 上 expo-sqlite 的逐线程异步查询崩溃，历史查询改成单条 SQL 后使用了 `LEFT JOIN`，导致没有任何有效消息的普通线程也进入侧栏、首页和历史列表。会话设置、记忆管理或发送流程中断都可能在首条消息写入前创建这类线程。

本设计把两项工作作为独立改动实现和验证：

1. 日记、梦境聊天卡片的长按、重新生成、版本切换及聊天侧隐藏；内心独白三个标签的当前标签多选永久删除。
2. 恢复“空聊天不进入记录和历史”的产品规则，同时保留现有单 SQL 路由投影，避免重新引入 SQLite 崩溃。

## 目标

- 梦境和日记卡片长按效果与聊天气泡完全一致。
- 重新生成追加版本，不覆盖旧版本；卡片下方显示并可切换 `1/2`。
- 从聊天移除卡片只改变聊天展示，不影响内心独白或任何版本内容。
- 从聊天移除后重新构建时间线，不能产生错位、幽灵占位、错误日期分隔或消息结构损坏。
- 内心独白中的日记、独白、梦境都支持长按进入当前标签多选，并统一永久删除。
- 永久删除只删除选中版本；删除最后版本时才删除版本组。
- 零有效消息的线程不进入侧栏、首页、最近聊天、搜索或完整历史。

## 非目标

- 不为聊天卡片增加恢复入口或回收站。
- 不允许内心独白跨标签多选。
- 不在本次变更中物理清理数据库里已经存在的空线程。
- 不把后来新增的聊天内容混入旧日记或旧梦境的重新生成。
- 不统一重写日记、梦境和独白的全部生成架构。

## 交互设计

### 聊天页长按菜单

已完成的日记和梦境卡片使用与消息气泡相同的长按协议：

- `delayLongPress` 为 500ms。
- 从长按事件读取 `pageX`、`pageY`。
- 菜单以触点为锚点，根据可用空间自动向上或向下展开。
- 复用相同的淡入透明层、圆角、阴影、分隔线、图标行、按压态和底部时间栏。
- 菜单操作为“重新生成”和“从聊天中移除”。
- 同一版本组正在重新生成时，“重新生成”禁用，避免重复任务。

“从聊天中移除”必须使用这个表述，不能使用含糊的“删除”，因为该操作不会删除内心独白内容。

### 卡片版本切换

- 只有版本总数大于 1 时显示版本切换器。
- 切换器复用聊天消息现有的左右箭头、禁用态、触摸范围和 `当前序号/总数` 文字样式。
- 新版本生成成功后默认选择最新版本。
- 选择版本只影响卡片预览和点击卡片后打开的阅读版本，不改变模型上下文。
- UI 序号按仍存在的版本重新计算；数据库内部版本编号和版本 ID 保持不变。

### 从聊天中移除后的结构稳定性

聊天隐藏必须发生在时间线构建之前，而不是在 FlatList 渲染函数中返回 `null`：

1. 仓储层加载版本组及其聊天展示状态。
2. 在生成 `CompanionArtifactEntry` 之前过滤隐藏组。
3. 使用过滤后的完整集合重新运行 `buildCompanionArtifactTimeline`。
4. 重新计算来源消息锚点、日期分隔和列表项顺序。
5. 保留消息和卡片的稳定 key；版本切换不能改变版本组卡片的 key。

隐藏操作先关闭锚点菜单，数据库写入成功后统一重新加载卡片集合和时间线。禁止直接按数组下标 splice 当前 FlatList 数据，禁止删除或修改任何聊天消息，禁止遗留零高度卡片或旧日期分隔项。这样可以避免移除卡片后出现列表跳项、结构错乱或后续消息绑定到错误卡片。

### 内心独白多选

日记、独白、梦境三个标签采用同一套多选规则：

- 长按条目进入多选并自动选中该条目。
- 多选状态下，普通点击用于切换选择，不打开阅读页。
- 顶栏切换为“取消 / 已选 N 项 / 删除”。
- 删除按钮使用危险色；点击后统一确认“永久删除所选 N 项？删除后无法恢复。”
- 多选仅限当前标签；切换标签、返回或点击取消都会退出多选并清空选择。
- 删除失败时保留当前选择并显示错误，以便用户重试。
- 新的多选删除直接永久执行，不进入回收站。

现有已经处于 `soft_deleted` 状态的独白仍保留恢复能力，避免升级后让历史数据失去原有恢复入口；新的内心独白删除路径不再先执行软删除。

## 组件结构

### 通用锚点菜单

从 `AiMessageContextMenu` 提取通用展示层，例如 `AiAnchoredContextMenu`：

- 通用层负责定位、动画、遮罩、滚动、操作行和底部时间。
- 消息气泡保留消息专用操作组装和无障碍文案。
- 日记和梦境聊天卡片只提供各自的操作数组和标签；内心独白长按直接进入多选，不打开锚点菜单。
- 定位算法继续使用现有 `resolveAiMessageContextMenuPosition`，可在重命名后保留兼容导出，避免无关调用方 churn。

不得复制第二套相似菜单，也不得改用系统 ActionSheet。

### 通用版本切换器

从消息气泡页脚提取小型版本切换器，例如 `AiVersionStepper`：

- 输入当前显示序号、总数和前后切换回调。
- 消息气泡和卡片共同复用。
- 版本组 ID 决定列表 key，当前版本 ID 只决定显示内容。

### 内心独白选择状态

`CompanionInnerLifeScreen` 使用一个当前标签选择集合：

- `selectionKind` 表示当前多选标签。
- `selectedIds` 保存版本 ID 或独白 ID。
- 条目组件只接收 `selected`、`selectionMode`、`onPress`、`onLongPress`。
- 仓储层提供按类型批量永久删除方法，屏幕不拼装多条独立删除事务。

## 数据模型

### 日记版本

继续使用：

- `companion_diaries` 作为同一天、同一角色的版本组。
- `companion_diary_versions` 作为不可覆盖的版本记录。
- `currentVersionId` 指向当前版本。

新增查询能力：

- 按日记 ID 列出全部仍存在的版本。
- 按版本 ID 加载阅读内容。
- 为内心独白返回每个版本，而不是只返回 `currentVersionId`。
- 批量永久删除版本，并在同一事务内重选 `currentVersionId` 和修正 `current/superseded` 状态。

删除最后一个版本时删除 `companion_diaries` 版本组；删除生成内容不会删除来源聊天消息。

### 梦境版本

在 `companion_dreams` 增加：

- `versionGroupId TEXT NOT NULL`
- `versionNumber INTEGER NOT NULL`
- `isCurrent INTEGER NOT NULL DEFAULT 1`

迁移规则：

- 每条现有梦境的 `versionGroupId` 回填为自身 ID。
- 每条现有梦境的 `versionNumber` 回填为 1。
- 每条现有梦境的 `isCurrent` 回填为 1。
- 为 `(versionGroupId, versionNumber)` 建立唯一索引。
- 为每个仍有有效版本的组保证最多一条当前版本。

重新生成会写入同一 `versionGroupId` 的新梦境记录，并将旧当前版本降为非当前。聊天时间线按版本组聚合，内心独白按版本记录展示。

### 聊天展示状态

新增独立的 `companion_artifact_chat_states`，避免把“聊天是否显示”混入内容生命周期：

- `artifactKind`: `diary` 或 `dream`
- `artifactGroupId`: 日记 ID 或梦境版本组 ID
- `threadId`: 来源聊天线程
- `hiddenAt`
- `createdAt`
- `updatedAt`
- 主键：`(artifactKind, artifactGroupId, threadId)`

从聊天移除只 upsert 该状态。内心独白查询不读取这张表。删除版本组最后一个版本时清理对应展示状态。

### 永久删除语义

- 日记：删除选中的 `companion_diary_versions` 内容记录。
- 梦境：删除选中的 `companion_dreams` 内容记录。
- 独白：调用现有永久删除路径，但增加批量事务入口。
- 删除不会删除来源线程或来源消息。
- 生成任务、用量和不包含生成正文的审计元数据可以保留，以维持频率限制和运行一致性；用户生成正文不能通过正常仓储查询恢复。

## 重新生成数据流

### 日记

1. 读取目标日记版本及对应的冻结来源快照。
2. 使用原始 `sourceMessagesJson`、分支、角色快照、摘要和系统提示快照创建唯一的新手动生成任务。
3. 后台运行现有日记生成器。
4. 成功后由现有 `saveDiaryVersion` 追加版本并更新当前版本。
5. 重新加载卡片组，默认选择最新版本。

### 梦境

1. 读取目标梦境、seed、job 及保存的来源消息 ID、版本哈希和角色快照。
2. 克隆为新的用户主动生成 seed/job，设置同一 `versionGroupId`。
3. 用户主动重生成不占自动梦境每日次数。
4. worker 在调用模型前再次验证来源消息和版本哈希。
5. 来源已变化或缺失时返回明确错误，不退化为使用当前聊天。
6. 成功后追加版本并原子切换 `isCurrent`。

任何失败都不能创建半成品版本或覆盖当前版本。

## 当前版本与上下文

- 日记继续只把 `currentVersionId` 对应版本纳入上下文。
- 梦境上下文查询增加 `isCurrent = 1` 限制。
- 卡片中手动切换显示版本不会改变上下文版本。
- 删除当前版本后，按创建顺序选择最新剩余版本作为当前版本。
- 删除最后版本后，该组不再进入上下文。

## 空聊天历史修复

`listHistoryItems` 保留当前单条递归 SQL 的分支路由投影，但最终线程集合必须只包含能连接到 `projected_history` 的线程：

- 使用内连接，或等价的 `projected_history.threadId IS NOT NULL` 条件。
- 有效消息必须是当前采用路由上、非 system、`completed` 且未回滚的连续性消息。
- 不恢复逐线程异步查询。
- 不按 `ai_threads.updatedAt` 为无消息线程生成历史排序回退项。
- 侧栏、首页、最近、搜索和完整历史继续统一调用 `listHistoryItems`，避免页面间规则漂移。

角色卡自带第一条助手问候的线程已经拥有有效消息，不属于零消息线程。数据库中的旧空线程保留，但不会再出现在记录界面。

## 错误处理

- 重新生成中禁用同组重复操作。
- 原始来源已变化时提示“原始聊天内容已变化，无法按原版本重新生成”。
- 模型或网络失败时保留旧版本、当前版本指针和卡片选择。
- 聊天隐藏写入失败时保留卡片，不进行本地假隐藏。
- 批量删除使用单事务；失败时整体回滚、保留选择并显示错误。
- 删除后 UI 重新按仓储结果加载，不能仅凭本地计数推断剩余版本。

## 测试与验收

### 数据与服务测试

- 现有梦境迁移后均为独立的第 1 版且当前版本唯一。
- 日记和梦境重生成追加版本，不覆盖旧正文。
- 重生成使用冻结来源；来源变化时拒绝生成。
- 聊天隐藏状态不影响内心独白或上下文记录。
- 删除旧版本、当前版本、最后版本时，当前指针和组清理正确。
- 日记、独白、梦境批量永久删除均为全成或全不成。
- 删除中间版本后展示序号连续，内部版本 ID 不变。

### 历史回归测试

- 零消息普通线程不出现在 `listHistoryItems`。
- 有用户消息或助手消息的有效线程仍出现。
- 当前采用分支上的最后消息决定预览和排序。
- 较新的未采用兄弟分支不会污染预览和排序。
- 查询实现不存在逐线程 async 循环，避免 Android `NativeStatement.finalizeAsync` 崩溃。

### UI 与 Android 验收

- 消息、日记卡片、梦境卡片的菜单使用同一展示组件和 500ms 长按时机。
- 在屏幕顶部和底部真实卡片上验证菜单方向及安全区避让。
- 日记和梦境卡片显示、切换并打开正确版本。
- 从聊天移除卡片后，来源消息、后续消息、日期分隔、滚动和其他卡片顺序保持正确。
- 重新进入聊天后隐藏状态仍生效。
- 内心独白三个标签均能长按进入多选；切换标签后选择清空。
- 批量删除确认次数为一次，失败时选择不丢失。
- 使用真实多版本数据截图验证，不只验证空状态。

## 文档与兼容性

- 更新 `docs/feature-matrix.md` 中角色日记、梦境、内心独白、聊天卡片和历史列表相关条目。
- SQLite 迁移必须兼容现有 2.7.7 数据库和 OTA 更新流程。
- 保留现有日记、梦境、聊天消息和软删除独白数据。
- 不清理现有空线程，不修改来源聊天内容。

## 已批准的产品决策

- 梦境和日记都支持卡片长按、重新生成、聊天移除和版本切换。
- 聊天移除不影响内心独白。
- 内心独白展示所有版本。
- 永久删除只删除当前选中版本；最后版本删除后才移除整组。
- 日记、独白、梦境都支持长按多选永久删除。
- 多选仅限当前标签，切换标签时退出。
- 卡片长按必须与聊天气泡效果相同。
- 空聊天不进入记录和历史。
- 从聊天移除后必须通过完整时间线重建保证结构稳定。
