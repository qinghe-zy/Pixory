# Pixory Main UI 与素材导入稳定化设计

## 目标

在 `main` 保留现有聊天、素材和隐私逻辑的前提下：

- 同步已经确认的安全 UI 调整；
- 修复模型可用但测试误报失败；
- 为图片和视频分别增加“相册 / 文件”来源选择；
- 修复相册移动导入在系统删除确认前提前失败；
- 保持测试分支中的群聊、日常模式和沉浸模式逻辑完全隔离。

本设计不包含隐私空间聊天迁移外键修复，也不包含测试工作树的沉浸 reasoning 修复。这两项继续按独立的系统化调试计划推进。

## 硬边界

- 不 cherry-pick 测试工作树的聊天组件。
- 不修改 SQLite 聊天模型、消息 DTO、SSE、reasoning、tail、滚动定位或流式渲染。
- 不引入群聊、群成员提及、日常模式、沉浸模式切换或生成中插话。
- 不删除现有资料库、总资料库、Provider 或导入页面路由。
- 不覆盖 `main` 工作树中已有的用户修改。
- 各批次独立测试、独立审查、精确暂存。

## 一、UI 基础与 AI 页面

### 设计 token

- 聊天画布使用 `#EDEDED`。
- 输入框表面使用近白色。
- 输入框使用低对比边框和适合 Android 的轻量悬浮阴影。
- 新增颜色或阴影必须进入共享设计 token，页面不散落等价硬编码。

### AI 通用视觉

- AI 页面标题改为 18px、600 字重的系统字体。
- `AppDialog` 和 `PrimaryButton` 只增加可选的 AI 视觉变体，默认变体不变。
- 不新增 Provider 数据处理说明或其他解释文案。

### 聊天输入框

- 输入框使用已确认的 A 方案：近白表面、细边框、柔和阴影。
- 输入框外围不增加第二层装饰框。
- 承托区域保持透明，使 `#EDEDED` 页面背景从四周露出。
- Props、按钮顺序、回调、输入高度、附件、语音、发送和停止逻辑保持不变。
- main 原有正文流式、reasoning 和 tail 链路保持不变。

### AI 首页与聊天搜索

- AI 首页快捷区域保留“选择 IP 开聊”和“会话历史”。
- 首页不再重复显示“资料库”和“总资料库”快捷卡，但现有路由和其他入口保留。
- 聊天搜索只调整标题和空状态文字，不迁移群成员筛选、游标分页或任务调度。

## 二、关于、详细信息与“我的”

### 关于页统计说明

- 默认统计网格间距保持不变。
- 点击统计项后，在该项所在整行下方展开全宽说明。
- 说明按正常文档流显示，最多自然占用两行，不使用绝对定位。
- 只有展开期间向下推后续内容；收起后恢复原间距。
- 保留再次点击关闭和五秒自动收起。

### 详细信息

- 顶栏和 Markdown 正文统一使用产品文档阅读器的画布颜色。
- 去掉顶部装饰背景，仅保留轻量分隔线。
- Markdown 生成、预加载、加载状态、IP 跳转和聊天跳转保持不变。

### “我的”

- 移除整块页面标题栏。
- 保留系统状态栏安全距离。
- 头像和资料内容整体上移。
- 底部导航“我的”、普通/隐私空间切换、动画和错误提示保持不变。

## 三、图片与视频双来源选择

### 交互

- “选择图片”标题右侧增加紧凑的“相册 / 文件”分段按钮。
- “选择视频”标题右侧增加同样的独立分段按钮。
- 标题占左侧弹性空间，按钮贴齐卡片右侧内边距，不在按钮右侧留下大块空白。
- 复用测试版分段按钮的滑块交互，但使用主项目现有米白和绿色 token，不依赖 AI 模式组件。

### 状态

- 图片来源和视频来源分别持久化。
- 首次使用均默认为“相册”。
- 用户切换后，下次进入页面恢复各自的上次选择。
- 设置保存在当前空间对应的现有设置存储中，不写入聊天数据。

### 相册来源

- 图片继续使用系统相册图片选择器，支持批量选择。
- 视频继续使用系统相册视频选择器，支持批量选择。
- 相册素材可以使用复制或移动模式。

### 文件来源

- 使用现有 `expo-document-picker`。
- 图片限制为 `image/*`，视频限制为 `video/*`。
- 两者均启用批量选择和缓存复制，以便现有导入服务立即读取。
- 文件来源固定按复制模式处理，不能删除系统文件夹里的原文件。
- 即使页面当前开启移动模式，文件来源素材也只复制，不尝试删除。

### 混合批次

用户可以先从相册选择，再切换到文件继续选择。每个待导入素材必须保留自己的来源标记：

- 相册素材按当前复制/移动策略处理；
- 文件素材始终复制；
- 不允许用批次级来源覆盖单个素材的真实来源。

## 四、移动模式与系统删除

### Pixory 风险提示

- 用户打开移动模式时显示说明弹窗。
- 主按钮为“知道了”。
- 弹窗提供较小的“下次不再弹出”勾选项。
- 只有用户勾选后才持久关闭后续 Pixory 风险提示。
- 该设置不影响 Android 系统删除确认，系统确认不能被应用关闭。

### 相册移动流程

正确顺序：

```text
选择相册素材
→ 复制到 Pixory 私有存储
→ 验证文件与数据库记录
→ 请求 Android 系统删除确认
→ 用户确认后删除相册原文件
→ 返回移动成功
```

### 删除未完成

如果用户取消系统确认、系统拒绝或无法取得可删除媒体引用：

- 保留 Pixory 中已经验证成功的副本；
- 保留相册原文件；
- 返回“导入成功，原文件未删除”结果；
- 不回滚已完成导入；
- 不把整批笼统标记为导入失败。

### 当前根因

当前图片和视频服务在复制前硬性要求 `assetId`。系统相册没有返回 `assetId` 时，代码会在调用删除 API 前直接失败，因此没有系统确认框，原文件也不会变化。

实现前必须先用失败测试覆盖 `assetId = null`，并在真机确认选择器返回的媒体引用形式。最终实现可以使用可验证的 MediaStore 资产 ID 或受控的原始媒体 URI，但不能根据缓存文件 URI 猜测并删除原文件。

## 五、Provider 测试误报

### 根因

正式版验证链路调用 Expo 原生 Fetch 尚未实现的 `response.clone()`。正常聊天不走该分支，因此会出现聊天可用但测试失败。

### 修复边界

- 先写失败测试模拟 `clone()` 抛出 `Not implemented`。
- 响应正文只读取一次，并在验证和 `/v1` 回退判断中复用。
- 保留现有 Provider 保存、同步、默认模型和正常聊天请求。
- 成功或失败后重新加载持久化卡片状态，避免继续显示旧结果。
- 不新增解释文案。

## 六、组件边界

计划新增或扩展的 UI 单元：

- 通用紧凑双选分段组件：只负责显示两个选项和回调；
- `LightFormSection` 标题右侧插槽：默认不渲染，不影响其他表单；
- 移动风险提示：只管理勾选状态和“知道了”；
- 图片、视频来源设置：分别读写，默认相册；
- 文件选择适配器：把 DocumentPicker 结果转换为现有导入服务可消费的素材记录。

导入服务必须根据单个素材的来源决定是否允许删除，不能依赖页面当前按钮状态。

## 七、测试与验收

### 自动测试

- 图片来源和视频来源默认均为相册。
- 两个来源设置独立持久化。
- 文件图片和文件视频均支持多选。
- MIME 过滤和缓存复制参数正确。
- 相册与文件混合批次按单素材来源执行。
- 文件来源在移动模式下仍只复制。
- 移动风险提示的“不再弹出”正确持久化。
- `assetId = null` 不再导致复制前失败。
- 删除未完成时保留已导入副本并返回部分成功。
- Provider 验证不依赖 `response.clone()`。
- main 不新增群聊、日常模式或沉浸模式依赖。

### Android 真机

- 图片相册批量选择。
- 视频相册批量选择。
- 图片文件批量选择。
- 视频文件批量选择。
- 图片和视频来源分别记忆。
- 分段按钮在窄屏和大字体下仍贴右对齐且不挤压标题。
- 相册移动出现系统删除确认。
- 确认、取消和“不再提示”三条路径均符合设计。
- 文件来源不会删除系统文件。
- 输入框、关于、详细信息和“我的”页面截图验收。
