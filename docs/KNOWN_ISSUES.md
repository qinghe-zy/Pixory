# 已知问题

更新时间：2026-05-05

## 当前已知问题

1. Android 模拟器输入法会干扰自动化文本注入
说明：在编辑页与导入页，`adb input text` 容易被输入法改写，导致精确标签或备注注入不稳定。

2. Expo Go 会保留旧页面状态
说明：即使 fresh bundle 已启动，Expo Go 仍可能停留在上一次会话页面，需要强制重开或重新进入项目。

3. 回收站清空后的物理删除，仍建议补做外部独立核验
说明：当前代码和历史链路已支持物理删除，但本轮最终提测前未完成独立二次验证。

4. 自动分堆能力尚未贯穿后续整理入口
说明：自动分堆不应只在首次导入或导入批次整理中出现。普通图库、IP 图片、分组图片、标签结果、收藏、最近查看等批量整理入口也应提供自动分堆辅助，帮助用户按本地规则快速选择和整理图片。

5. 两套批量整理入口能力仍需继续统一
说明：`BatchManageImagesScreen` 已有“规则模式”和若干规则选择；`BatchImageOrganizePanel` 被全部图片、分组图片、标签结果、收藏、最近查看等页面复用，但自动分堆/规则选择辅助仍需继续统一。后续应抽取共享的批量选择辅助能力，避免导入批次整理和普通整理体验割裂。

6. 当前 release APK 是 universal APK，体积偏大
说明：`v1.0.5` APK 同时包含 `armeabi-v7a`、`arm64-v8a`、`x86`、`x86_64` 四套 native 库，便于覆盖真机和模拟器，但安装包约 68.5 MB。后续若只面向真机分发，可考虑单独产出 `arm64-v8a` APK 或改用 AAB。

## Expo Go / Android 模拟器限制

- Expo Go 不是正式 APK，页面恢复行为与正式安装包可能不同
- 模拟器输入法会影响自动化文本输入
- 媒体选择器会受系统相册索引影响
- 开发环境文件路径位于 Expo Go 沙盒中，外部观察不如独立包直观

## 物理删除外部独立核验是否完成

- 当前状态：未完成最终独立复核
- 已完成内容：代码链路存在，历史回归已走通，本轮已记录为后续必补项

- 当前状态：存在
- 受影响范围：仅 `__DEV__`
- 不应影响正式首页主路径
- 正式提测前可移除

## 后续建议

- 在更稳定输入环境下补一轮完整 Android 长链路人工复核
- 如继续依赖自动化回归，优先解决模拟器输入法干扰
- 规划自动分堆组件复用，让导入批次整理与普通批量整理共享同一套辅助选择能力
- 评估是否增加单架构 APK 或 AAB 发布流程，降低用户实际下载体积
