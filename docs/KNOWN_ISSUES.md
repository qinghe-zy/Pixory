# 已知问题

更新时间：2026-05-04

## 当前已知问题

1. Android 模拟器输入法会干扰自动化文本注入
说明：在编辑页与导入页，`adb input text` 容易被输入法改写，导致精确标签或备注注入不稳定。

2. Expo Go 会保留旧页面状态
说明：即使 fresh bundle 已启动，Expo Go 仍可能停留在上一次会话页面，需要强制重开或重新进入项目。

3. 回收站清空后的物理删除，仍建议补做外部独立核验
说明：当前代码和历史链路已支持物理删除，但本轮最终提测前未完成独立二次验证。

4. 分组图片页“移出分组”仍复用通用分组选择流程
说明：在分组图片页中，页面上下文已经确定当前分组。用户长按选择图片后点击“移出分组”，应直接作用于当前分组，或最多只做确认；不应再次要求选择分组。当前截图中左下角还出现了确认按钮文字不可见的布局问题，需要一并修正。

5. 自动分堆能力尚未贯穿后续整理入口
说明：自动分堆不应只在首次导入或导入批次整理中出现。普通图库、IP 图片、分组图片、标签结果、收藏、最近查看等批量整理入口也应提供自动分堆辅助，帮助用户按本地规则快速选择和整理图片。

6. 批量管理的规则选择缺少可见基准与取消机制
说明：`BatchManageImagesScreen` 中“当前筛选 / 未分组 / 无标签 / 更多选择”会直接覆盖当前选择集。`选择同尺寸` 目前以已选第一张图为基准；如果没有已选图，则默默使用列表第一张图。用户难以判断“同尺寸是基于谁的尺寸”，也无法再次点击同一规则来取消这次规则选择。后续应让规则选择变成可解释、可撤销的状态：规则激活后显示基准、结果数量，并出现“取消本次选择/取消该规则”按钮；再次点击同一规则也应取消该规则产生的选中范围。

7. 两套批量整理入口能力不一致
说明：`BatchManageImagesScreen` 有“更多选择”和若干规则选择；`BatchImageOrganizePanel` 被全部图片、分组图片、标签结果、收藏、最近查看等页面复用，但缺少同等的自动分堆/规则选择辅助。后续应抽取共享的批量选择辅助能力，避免导入批次整理和普通整理体验割裂。

8. IP 详情页整理状态区域卡片感过重
说明：`IpDetailScreen` 中“待整理”“当前 IP 整理度”“最近导入批次”“快捷操作”等模块连续堆叠，尤其是最近导入批次上方的整理状态部分应更一体化。后续优化应把整理进度、待整理数量、最近导入未整理等信息收束成一个连续的管理摘要，而不是多个独立卡片。

9. 标签页缺少显式新增标签入口
说明：`TagsOverviewScreen` 当前支持搜索、展示最近/热门/全部标签，并可长按重命名或删除；`tagRepository` 已有 `create` 能力，但页面没有清晰的“新增标签”入口。标签页不应只是搜索已有标签，也应允许用户主动创建标签。

10. 我的页面本地原图存储进度条语义不真实
说明：`MeScreen` 当前用 `imageRepository.sumFileSize({ includeDeleted: true })` 汇总 SQLite 中记录的原图 `fileSize`，显示为“本地原图存储”的容量数值；但进度条宽度不是基于设备容量、应用私有目录容量、用户阈值或真实比例计算，而是 `totalBytes > 0 ? '34%' : '8%'` 的固定视觉效果。因此它不会随存储逐步涨满，只会在有无原图之间切换，容易让用户误解为真实容量进度。后续应移除该进度条，只保留真实容量数字。

11. 我的页面统计信息卡片拆分过散
说明：`MeScreen` 当前把“本地空间”与 `IP数量 / 图片总数 / 收藏数 / 回收站` 做成两张独立卡片。后续应合成一张本地空间卡片：上方展示 `本地原图存储：大小`，下面一行展示 `IP数量 / 图片总数 / 收藏数 / 回收站`，形成一张综合本地资料库状态卡，减少卡片堆砌感。

## Expo Go / Android 模拟器限制

- Expo Go 不是正式 APK，页面恢复行为与正式安装包可能不同
- 模拟器输入法会影响自动化文本输入
- 媒体选择器会受系统相册索引影响
- 文件路径位于 Expo Go 沙盒中，外部观察不如独立包直观
