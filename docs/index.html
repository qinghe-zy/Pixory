Archive Ethics

原质完整进入，缩略只做预览。设备内成库，离线可用。数据主权永远属于你。

01 / 原质保留

原始图像按母版规格保存，缩略图独立生成。你存入的，就是未来可继续使用的素材源。

02 / 离线本地

所有结构化数据保存在本地 SQLite 数据库中。离线可用，设备内完成整理、检索与查看。

03 / 开放带走

Under The Hood

清楚可控的图片管理体验。

本地 SQLite 驱动

Pixory 内部运行标准关系型数据库，通过结构化索引为查询提供稳定、快速的元数据检索响应。

原质大批量导入

直接读取文件物理路径进行硬拷贝 (Copy-on-write)，原始像素与关键元数据随素材一起进入私有库。

分离式缩略图系统

原图与缩略图在存储层完全隔离。瀑布流加载极其丝滑的同时，点开详情页永远能看到未经妥协的原始像素。

多维度标签索引

IP 决定归属，Group 决定分类，Tag 决定细节。通过任意属性的交集，即便图库堆积如山，也能如同进行 SQL 查询般精确过滤。

软删除防呆设计

每一次“删除”都会先修改数据库状态标位，并进入隔离回收站。你可以在清空前恢复图片及其元数据。

全量打包离场机制

你可以随时一键生成完整的数据快照，将文件夹、清单与数据库本身直接转移到 PC 或其他设备上读取，这是真正的开源契约。

Technical FAQ

那些有关数据边界的尖锐问题。

Pixory 会把我的图片上传到云端分析吗？

Pixory 是一个纯粹的“Local-first”本地优先应用。图片流转、检索和整理都在你的 Android 设备上完成，素材库由你本地掌控。

如果应用被意外卸载，我的图片还在吗？

如果你在 Android 系统中清除了应用数据，Android 会删除应用专属目录下的文件。因此，定期使用“全量导出”功能将 Pixory/ 完整目录备份到外部存储空间，是保障资产绝对安全的基础。

原图很大，大量导入会撑爆手机内存吗？

Pixory 按原图体积保存素材，10GB 的原图导入后会占用约 10GB 以上空间（含额外缩略图缓存）。建议为严肃资产库预留充足的物理存储空间。
