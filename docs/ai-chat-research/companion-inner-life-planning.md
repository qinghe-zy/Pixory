# 角色内在生活：分阶段产品规划

**状态：** 设计讨论中，尚未进入代码实施。

**目标：** 分三轮建设角色内在生活、沉浸式回复表达与情感感知系统。第一轮把日记、离线思绪与梦境碎片作为同一个角色内在生活系统一起落地，而不是把三者拆成三次独立实施。

## 已确认的产品方向

- Pixory 保持 Android-first，聊天是产品中心。
- 角色可以以强沉浸、第一人称的方式表达日记、想法与梦境。
- 不把面向用户的好感度或亲密度数值作为核心体验；情绪、关系、节奏和时间感可以作为内部角色状态。
- 日记、思绪和梦是角色的内在产物，不自动改写用户事实记忆。
- 任何内在产物都必须按 `space + role` 隔离，并记录 `thread + branch` 来源；Personal 与 normal 物理隔离。
- 每次聊天最多主动带出一项相关内在产物，避免角色一次提起多件旧事。
- 日记在生成时一次性收集当天当前聊天页的有效内容：当前 `thread + selected branch route + message versions` 会被锁定为来源快照；日记正文不随之后的 thread 切换而动态改写。
- 日记的阅读时间线与 thread 完全分离：所有日记在一个统一的日记会话框中按日期连续展示，不按 thread 分组或拆页；切换到任意旧 thread 后，前一天及之后的日记仍然可在同一时间线中上滑查看。
- 每个日期的当前日记版本保留生成时的 `sourceThreadId`、branch route、message version IDs 和 source snapshot hash。来源聊天后来被编辑、重生成或删除时，日记保留在时间线中并标为“来源已变化”，由用户选择更新为新版本，而不是消失或静默覆盖。

## 已确认的日记细则

### 信纸、分页与阅读

- 日记使用独立阅读页；聊天页已生成卡片是唯一入口。阅读页不使用正文内部滚动，而是显示自然叠放的多张 `9:13` 信纸，整组信纸左右滑动。
- 可见纸堆只挂载当前页、下一页和第三页。当前页离场后先让下一页扶正，再进入第三张槽位；不可出现“从第一页回到第二张”的视觉错位。
- 页数由字体实际测量后的正文布局决定，不固定三页；一页、两页或五页均有效。全文和后续页面在进入阅读页时预计算并预加载，翻页不请求模型、不等待图片、不展示空白页。
- 不做“回拉上一段文字”或任何为了填满页面而搬运正文的策略。以完整段落优先分页；单段长于单页容量时才按已测量的行边界拆开，绝不重复文本。最后一页自然保留其真实内容，不以单个标点作为页面。
- 纸张整体位于阅读区视觉中心并略向下。底部只居中显示纯文本页码，例如 `3 / 3`，没有白色工具条、圆点或额外卡片底。
- 第 1 页顶部显示星期与生成时刻；左下显示“写给今天”。阅读历史日记时，该位置改为精确日期 `YYYY.MM.DD`。
- 第 2 页起顶部显示 `CONTINUED`；左下显示精确日期。最后一页左下也保持日期，不额外写“日记完成”一类文字。
- 正文区域优先利用纸面：首末页均以约 70% 可读高度为目标，但不以填满为目的。边缘花纹不进入正文安全区，黑色正文保持高对比。
- 正文字体内置两套可读的中文手写风格：`LXGW WenKai` 与 `ZCOOL XiaoWei`。创建日记时用 `diaryId` 稳定散列选择其一，并持久化 `bodyFontKey`；同一篇日记、所有续页和之后每次打开都使用同一字体，绝不在阅读时随机变化。

### 入口、卡片与可见状态

- “我的 → AI 设置”增加“启用角色日记”开关，默认开启。关闭后取消未来日记 job，不删除已生成日记。
- 会话设置增加“内心独白”入口。进入后顶部使用整理页同款胶囊筛选，第一轮提供 `日记`、`独白`、`梦境`；下方按时间倒序显示每天的 artifact 卡片。
- 当天卡片使用 `TODAY · HH:mm`；过了当天，聊天页和阅读时间线都使用精确日期，避免陈旧条目仍显示 Today。
- 同一角色同一天只维护一篇“当前日记”，不按线程累积。触发或手动生成时，只使用用户**当时所在**的 `thread + active branch` 的上下文；切换线程后重新生成会以新线程来源创建当天新版本，原版本进入可撤销历史。角色级时间线和该角色各 thread 的日记卡片始终只展示最新 current-version，来源 thread 只用于追溯与再次生成。
- 聊天页只在当前来源线程展示当天卡片；“内心独白”时间线只展示每天当前版本，不按 thread 分组。
- 日记生成完成而聊天仍有气泡流式输出时，artifact 可先落库为 `ready_pending_presentation`；待当前流结束再插入聊天卡片，避免打断回复节奏。

### 自动生成状态机

`lastInteractionAt` 取当前聊天页最后一条用户消息或助手**完成**输出的较晚时间；草稿、正在输入和未完成流不重置静默计时。所有判断使用持久化的本地时区 date key。

| 窗口 | 条件 | 动作 |
| --- | --- | --- |
| 22:00–22:29 | 当日有有效聊天，静默至少 30 分钟 | 自动生成当日日记。 |
| 22:30–23:49 | 当日有有效聊天，静默至少 10 分钟 | 自动生成当日日记。 |
| 23:50 | 当前会话仍活跃 | 聊天输入框上方展示一次轻提示；“点击生成今天的日记”以品牌色可点击，不弹窗。 |
| 23:50 后结束活跃会话 | 会话开始于 23:50 前，之后静默至少 10 分钟 | 自动生成，日期锁定为前一天。 |
| 23:50 后新开始会话 | 即使跨零点 | 不为前一天生成；改走新一天 22:00 后规则。 |
| 当天无聊天 | 距离上次真实聊天不超过 24 小时 | 生成符合人设的第一人称“安静独白”；超过 24 小时不补写、不追写。 |

- 手动点击“生成今天的日记”可立即创建后台生成请求；以点击时已经完成的消息建立 source snapshot，后续新消息只会让来源标为已变化，不会静默改写该版本。
- 当前日记逻辑唯一键为 `space + roleCardId + diaryDate`；每个物理 space 数据库的实际唯一索引为 `roleCardId + diaryDate`。每个版本仍保存 `sourceThreadId + branchRoute + sourceSnapshotHash`。job、锁和结果持久化到 SQLite，应用恢复、重启或消息状态变化时都可幂等重算；跨线程重新生成只替换该日期的 current-version 指针，不产生并列日记。
- 产品要求“用户一直未打开，进入时卡片已经存在”需要 Android 后台调度与落库任务，而不应等到页面打开后才开始生成。设备端以时间闹钟触发持久化 worker，并在冷启动时只做校验与补偿；若设备被强制停止、离线或模型服务不可用，则任务保留为待执行并在条件恢复后生成，不显示伪造的已完成卡片。

### 日记生成上下文与提示词

- 日记请求复用当前会话的 provider/model 配置，但使用独立的 `DiaryPromptInput`、独立 request ID 与独立 token 预算；不得把日记请求的 history 直接混入正常聊天 prompt，也不得反向污染聊天上下文。
- 固定部分：角色卡快照、稳定人设/世界设定、正常聊天已用的受控摘要、允许进入日记的角色状态。
- 当日部分：只取当前 `thread + active branch + selected message versions` 中本地日期相同、带时间戳的有效消息。若当日消息数少于用户“上下文注入轮数”，全部注入；若更多，最多注入 `min(用户注入轮数 × 3, 日记 token 预算可承受量)`。超过上限时优先截断最早消息，保留较新的当日消息与当天事件摘要。
- 普通聊天的上下文轮数和日记的当日窗口分别计算：用户设置为 20、当天 50 轮时，日记可取最多 60 轮内的当日内容；用户设置为 50、当天 20 轮时，20 轮全部保留。
- 长度不做死板分档。提示词要求“通常不超过 300 个汉字；只有当当天有效互动明显丰富时才自然延长”，由模型按素材密度决定。
- 输出采用第一人称私密日记：具体、克制、有角色口吻，但不复述系统机制。禁止出现模型、AI、提示词、记忆、上下文、数据、生成等出戏词；用户说过的话只能依据 source snapshot，角色世界细节只能来自角色卡允许设定。
- 无聊天日独白应是角色自洽的心理状态、日常感受或轻微抱怨，不伪造与用户发生过的互动。

### 上下文与记忆选择

- 日记默认仅展示：不进入上下文，不进入记忆。聊天页卡片下仅以极轻小字询问“是否将该日记纳入上下文？ 是 / 否”。
- 未点击或选择“否”时，日记不参与任何 prompt 或记忆提炼。
- 选择“是”后，先作为显式标注的 `role_diary` 上下文进入后续 prompt：它是角色回顾性私密记录，不是用户新消息、即时指令或用户事实。之后是否产生长期记忆仍遵循既有记忆提炼、确认与撤销规则。

## 共同底座

三项能力共享一个后续需要实现的 Companion Ledger，但首期只定义最小公共契约：

| 概念 | 最小职责 |
| --- | --- |
| `CompanionEvent` | 记录对角色有意义的对话或时间事件，并引用原始 message/version。 |
| `CompanionArtifact` | 保存日记、思绪或梦的正文、来源事件、状态与可见方式。 |
| `CompanionState` | 保存可重算的角色情绪、关系、时间和表达节奏投影。 |
| `CompanionJob` | 持久化延后生成、补写、投递与失效任务，适应 Android 进程退出。 |

所有 artifact 都需要 `createdAt`、`updatedAt`、`sourceEventIds`、`roleCardId`、`threadId`、`branchRoute`、`space`、`status`。删除、分支切换和消息版本变更时，系统可以定位受影响的产物并提供重新生成，而不是静默修改文本。

## 三轮实施顺序与决策门

### 第一轮：角色内在生活（日记、离线思绪、梦境）

**目标：** 让角色拥有持续写入的日记、未说出口的离线思绪和梦境碎片，并让三者共享事件来源、角色状态和“角色内心”入口。

本轮作为一个实现包，共用 Companion Ledger、artifact 状态和后台 job。产品讨论可以先定日记，再定思绪和梦，但三项会在同一份设计、同一套 schema 迁移和同一轮实现计划中交付。

本轮需要定下：

1. 日记的一次性生成范围、生成时机、可见方式、内容边界与无模型降级。已确认：日记在生成时只使用当天当前 thread 的有效聊天页内容，统一显示在一个日记会话框中；不按 thread 分组；切换 thread 不会隐藏任何历史日记；来源变化只产生可选的新版本。
2. 离线思绪的数量、触发事件、保留期、投递策略与无模型降级。
3. 梦境碎片的生成窗口、意象来源、主动触发、收藏与转化为共同回忆的动作。
4. 三类 artifact 的优先级：同一轮聊天最多主动带出一个，日记、思绪和梦之间通过统一仲裁选择。

本轮完成定义后，产出一份角色内在生活设计说明和一份可执行实施计划。

### 第二轮：多气泡、思考展示与回复时间

**目标：** 解决沉浸式聊天中的思考区、流式输出、多气泡、首句延迟、长回复失控和模型输出聊天风格不稳定的问题。

本轮将确定 Provider reasoning 与角色心绪的展示边界、`ResponsePresentationPlan`、单流句段气泡化、连续 wave、输出契约、长度校验、停止/继续和 Android 中断恢复。

### 第三轮：情感与感知系统

**目标：** 借鉴 Ackem 的事件驱动情绪、关系、psyche、时间感、主动话题仲裁和节奏机制，为角色内在生活与回复表达提供统一状态来源。

本轮将确定 CompanionEvent 分类、连续情绪维度、关系事件投影、时间锚点、开放回路、topic arbitration、节奏引擎和角色状态重算策略；不把好感度数值作为前台产品机制。

## 明确后置的能力

以下能力与三轮规划相关，但当前第一轮不纳入代码范围：

- Android 按住说话与自带离线 ASR；
- 主动通知、后台召回和语音回复。

语音和主动能力会在三轮核心认知/表达能力稳定后另立计划，以免扩大 `aiChatService.ts` 的改动面。

## 共通验收标准

- 每条内在产物能追溯到角色、空间、线程、分支和来源事件。
- 角色内在产物不会被当成用户陈述自动写入稳定记忆。
- 切换 branch 后不会读取 sibling branch 的 artifact。
- Android 强杀、重启或后台限制后，待处理生成任务可恢复、过期或明确失败，不会无声丢失。
- 同一轮聊天不会同时主动带出日记、思绪和梦。
- 删除 source message、thread 或 Personal 数据时，关联 artifact 有确定的删除、归档或重生成行为。
