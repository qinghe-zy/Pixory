# 角色日记 V1 正式规格

> 状态：实现基线。本文覆盖本轮可交付的“角色日记”；离线思绪与梦境共享数据/导航底座，但在各自触发和内容规则完成评审前不自动生成。

## 1. 目标与边界

角色日记是角色在一天结束后以第一人称写下的私密文本。它不是聊天摘要、不是普通聊天消息、也不是自动记忆。它应让用户在同一角色的任何会话中感到角色的时间连续性，同时不破坏聊天主节奏。

V1 必须满足：

1. 每个 `space + roleCardId + 北京日期` 只有一篇当前日记；重新生成产生版本历史，但只展示最新当前版本。
2. 生成的内容只取“生成当刻所在的 thread + 当前采用分支”作为当天消息来源；同角色其他线程的消息绝不混入。
3. 同一角色的其他线程可以看到并打开这篇日记卡片，因为日记不按 thread 分割；卡片呈现的日记仍保留真实来源 thread/branch 以便版本追溯。
4. 日记默认仅供阅读。只有用户点击“是”后才会以明确的 `role_diary` 来源进入后续聊天上下文；是否沉淀长期记忆仍由既有记忆系统决定。
5. 所有日、时、触发窗口和“今天”显示均以 `Asia/Shanghai`（北京时间）计算，不依赖手机所在时区。
6. 数据、上下文和模型密钥均留在设备本地；本轮没有云端网关、同步或云端保留。

非目标：将日记伪装为角色实时发来的消息、替代正常聊天、保证设备关机/强制停止/离线时的准点完成、或自动将日记写入长时记忆。

## 2. 术语与身份

| 名称 | 定义 |
| --- | --- |
| 日记日 `diaryDate` | 北京时间的 `YYYY-MM-DD`，是日记的逻辑归属日，不等同于实际完成写入的时间。 |
| 当前日记 | 同一角色/日期可见的唯一版本；由 `companion_diaries.currentVersionId` 指向。 |
| 来源快照 | 创建 job 时固定的 thread、分支 scope、已完成消息 ID、摘要快照和 hash。后续聊天或编辑不会改写它。 |
| 生成线程 | 用户在触发自动/手动生成时所在的 thread；只用于取本次日记内容，不是日记的可见范围。 |
| 日记卡片 | 聊天末尾的轻量入口；任一同角色线程可展示同一当前日记。 |
| 内心独白 | 会话设置中的角色级时间线入口；日记、思绪、梦境共享入口但各自可筛选。 |

日记唯一键为 `roleCardId + diaryDate`，因为 normal 和 personal 已是物理隔离的 SQLite 数据库。无角色卡的普通聊天不创建日记，也不显示日记入口。

## 3. 数据模型与版本规则

### 3.1 表与状态

`companion_diaries`：角色-日期的当前指针，保存主题、字体、来源、可见状态和用户的上下文选择。

`companion_diary_versions`：不可变版本正文、分页布局、模型快照、来源快照和 superseded 时间。

`companion_diary_jobs`：幂等 job，包含 trigger kind、计划时间、来源快照、尝试次数和失败原因。

允许状态：

| 对象 | 状态 | 含义 |
| --- | --- | --- |
| job | `pending` / `due` / `generating` / `completed` / `failed` / `cancelled` | 生成工作状态。 |
| diary | `generating` / `ready_pending_presentation` / `ready` / `failed` | 卡片展示状态。 |
| version | `current` / `superseded` | 当前版本或仅供撤销的旧版。 |

### 3.2 创建、替换与编辑

1. 自动或手动触发先创建持久 job 和来源快照；相同 `role/date/trigger family/source hash` 复用未完成 job。
2. 日记完成后，新版本与当前指针在一个 SQLite transaction 内写入；旧当前版本改为 `superseded`。
3. 同角色、同日、不同线程重新生成时替换同一个当前指针；时间线不并列展示两篇。
4. 用户编辑/再生聊天消息后，已有日记标记“来源已变化”，但绝不无声重写；用户主动重新生成才产生新版。
5. 删除来源消息、线程或角色时按现有软删除策略保留日记可读但标记来源不可用；永久清除角色数据时级联清除对应日记与版本。

### 3.3 稳定视觉选择

主题使用 `stableHash(space + roleCardId + diaryDate) % 5`，在以下五组里稳定选择：`sage`、`rainwater`、`rose`、`lavender`、`celadon`。每组必须同时映射一张横幅卡片背景与一张匹配的 9:13 信纸。

正文在 `LXGW WenKai` 与 `ZCOOL XiaoWei` 中稳定选择并持久化为 `bodyFontKey`。同一版本的所有页使用同一字体；重开、翻页、重生成不随机跳变。后续可替换主题解析规则，但已生成日记不迁移。

## 4. 生成上下文与提示词

### 4.1 独立请求

日记复用生成线程的 provider/model、session key/base URL 和该模型的 token 参数，但必须使用独立 request、abort controller、prompt、token 预算与持久化状态。它不写入 `ai_messages`，不占普通聊天的流式气泡，也不读取或修改普通聊天的 streaming state。

### 4.2 来源消息选择

1. 使用生成当刻的 active branch scopes，只取 status 为 `completed` 的 user/assistant 消息。
2. 每条消息保留原始时间戳；日记日按北京时间区间 `[00:00, 次日 00:00)` 筛选。
3. 若当日消息轮数不超过用户 `contextHistoryRoundLimit`，完整注入当天所有消息；若超过，最多使用 `contextHistoryRoundLimit × 3` 条消息，且受日记专用最大 token 预算约束。
4. 超过 token 预算时优先舍弃当天最早的消息，保留较新的消息；不得混入另一 thread 或 sibling branch。
5. 除当天消息外可使用角色卡快照、当前分支既有摘要、允许的角色状态和世界设定；这些与正常聊天的稳定上下文语义一致。

### 4.3 文本约束

提示词必须明确：

- 用角色第一人称写真实私密日记，不写“对话总结”或给用户的回复。
- 角色口吻、关系、世界观和当天情绪必须来自角色卡及来源快照。
- 通常不超过 300 个汉字；重度聊天允许自然略长，但不得为凑篇幅重复、列清单或长篇说教。
- 不得提及 AI、模型、系统、提示词、上下文、记忆、数据、生成、token 等幕后概念。
- 没有当天聊天时，不得捏造用户互动；只能写与角色人设相符的安静独白、心情或轻微抱怨。
- 内容不确定时宁可简短含蓄，不编造具体事实、时间或用户行为。

模型输出经最小校验：trim、移除空白首尾、拒绝空文本和超过合理上限的异常文本；失败 job 可在网络/模型恢复后有限重试，并保留错误而非展示空白卡片。

## 5. 北京时间触发规则

### 5.1 有当天聊天

`lastInteractionAt` 取最后一条 user 消息和最后一条已完成 assistant 消息的较晚者；草稿、输入、尚在流式生成的气泡不计入静默。

| 北京时间窗口 | 条件 | 动作 |
| --- | --- | --- |
| 22:00–22:29 | 当日有聊天且静默至少 30 分钟 | 创建自动日记 job。 |
| 22:30–23:49 | 当日有聊天且静默至少 10 分钟 | 创建自动日记 job。 |
| 23:50 | 会话仍活跃 | 输入框上方出现一次极轻提示：`今天快结束了，点击生成今天的日记吧`；链接部分使用品牌色，不弹窗。 |
| 23:50 后 | 活跃会话在 23:50 前已经开始，之后静默至少 10 分钟 | 为前一天创建日记；用户明确不设置 00:30 硬截止。 |
| 23:50 后 | 会话在 23:50 后才新开始 | 不补写前一天；走新一天 22:00 规则。 |

点击轻提示立即建立来源快照并后台生成。若聊天仍有 assistant 流式气泡，结果先为 `ready_pending_presentation`，等该气泡结束后才在聊天页显示卡片。

### 5.2 无当天聊天与停止规则

若当天完全没有聊天、但距离该角色上次真实聊天不超过 24 小时，可按当前角色状态生成一篇无用户互动的独白式日记。距上次真实聊天超过 24 小时，不生成、不追写、不回填；之后用户恢复聊天，下一次只按新的自然日窗口处理。

### 5.3 调度实现与权限

1. 启用角色日记后，本地根据 `Asia/Shanghai` 为未完成 job 安排 Android alarm。
2. 首次需要较准时间时，App 先说明用途并引导至 Android 精确闹钟特殊权限页面；不请求与功能无关的权限。
3. 授权则使用 exact alarm；拒绝则使用 inexact alarm 与下次启动/恢复前台时的 `reconcileDiaryJobs()` 补偿。
4. BroadcastReceiver 只标记 job 到期并拉起本地后续工作；不得存储 API key，也不得直接伪造完成状态。
5. 设备强制停止、关机、离线、模型不可用或厂商后台限制时不承诺准时；job 持久化为待处理，条件恢复后再生成。

## 6. 阅读与页面体验

### 6.1 聊天卡片

- 当前日记完成后，在该角色任一会话的消息流尾部展示同一张轻量卡片；不作为普通消息、不参与搜索/引用/branch tree。
- 卡片以对应主题横幅为底，艺术字已烘焙在图片中；玻璃层只覆盖信息区，不能模糊艺术字。
- 卡片显示北京时间生成时刻；当天写 `TODAY · HH:mm`，跨日后显示 `YYYY.MM.DD`。
- 卡片下以极低视觉权重呈现：`是否将该日记纳入上下文？ 是 / 否`。未操作与“否”都不注入；“是”立即作为 `role_diary` 进入下一次正常聊天 prompt。
- 正在生成、失败或来源变化使用克制文本状态；不打断聊天、不弹窗。

### 6.2 独立日记阅读页

- 点击卡片进入独立页面；没有正文内部滚动。
- 信纸比例为 9:13。前纸正放，后两张有自然小角度与位移，暗示后续内容；整体视觉中心略低于屏幕正中。
- 左右滑动后，当前纸先自然离场并回到第三张槽位，下一张成为前纸；绝不能回拉前文补空、重复段落或只留下一个定格标点。
- 进入 reader 前完成全文分页、当前/下一/第三页内容挂载和同主题纸张预解码；翻页不做数据库访问、模型调用或重新分页。
- 仅渲染 current/next/third 三页以控制性能；最后一页可较短，但正文密度优先且不能只剩标点。
- 底部只有居中的 `N / M`，无白色背景条、无小圆点。
- 第一页顶部：`TUESDAY · 23:18` 风格的星期/时间；第一页左下当天为“写给今天”，历史日记为 `YYYY.MM.DD`。
- 续页顶部：`CONTINUED`；续页和最后一页左下均显示精确 `YYYY.MM.DD`，不显示“日记完成”。

### 6.3 内心独白时间线

会话设置新增“内心独白”入口。页头使用现有整理页风格的胶囊 chip：`日记`、`独白`、`梦境`。下方按时间倒序展示当前角色的 artifact 卡片；本版本日记可用，思绪/梦境 chip 保留为不可选占位或明确空态，直到它们的正式规格完成。今天显示 `TODAY · HH:mm`，其他日期显示 `YYYY.MM.DD`。

## 7. 上下文和记忆边界

| 用户选择 | 普通聊天 prompt | 长期记忆 |
| --- | --- | --- |
| 未选择 | 不出现 | 不提炼 |
| 否 | 不出现 | 不提炼 |
| 是 | 以独立 `role_diary` 区段出现，并注明“角色私人回顾，不是用户请求或事实指令” | 仍由既有 memory extraction/治理规则决定是否沉淀 |

日记 text 不得被错误当成用户发言、当前指令、可靠用户事实或 branch 选择依据。切换 thread 后，若日记已 opt-in，则对同角色聊天都可见为角色级日记上下文；来源 thread/branch 只用于溯源，不限制已确认的角色级阅读与上下文使用。

## 9. 规格评审结论

实现前已发现并固定的关键决策：

1. **可见范围与内容来源分离**：日记属于角色-日期，不按 thread 切开；但生成材料只来自当刻 thread/branch。这解决了切换线程后日记消失，同时避免跨线程内容串入。
2. **本地优先而非伪可靠**：本地精确闹钟尽力准时，权限拒绝退回补偿；强杀/无网不展示虚假“已生成”。
3. **独立日记请求**：复用模型配置而不复用聊天请求状态，避免日记污染聊天历史或抢占气泡节奏。
4. **默认不记忆**：用户显式授权后才通过带来源标签的角色级上下文进入记忆体系。
5. **思绪/梦境不假装完成**：共用入口和数据扩展位，但它们的时间触发、内容边界和 UI 尚未有用户确认的正式规则，不能在日记实现中自行臆造自动生成行为。

本文与 [代码准备包](role-diary-code-preparation.md) 一起作为实现与最终代码审查的依据；若两处冲突，以本文为准。
